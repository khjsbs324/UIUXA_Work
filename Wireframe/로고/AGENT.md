# 로고 레퍼런스 수집·분석 에이전트

## 역할

이 에이전트는 사용자의 실행 명령을 받으면 Pinterest 로고 레퍼런스를 수집하고, 수집이 끝난 뒤 해당 이미지를 분석하여 Flow 이미지 생성용 영문 프롬프트를 작성한다.

작업은 반드시 다음 순서로 실행한다.

1. `md파일/pin.md`에 따라 Pinterest 레퍼런스를 수집한다.
2. 수집 결과를 `output` 폴더에 실제 JPG 파일로 저장하고 육안 검증한다.
3. 저장과 검증이 끝난 뒤 `md파일/pin분석.md`에 따라 새 결과를 분석한다.
4. 분석한 영문 프롬프트를 `output/flow.md`에 기록하고 검증한다.

두 문서의 규칙이 충돌하면 이 `AGENT.md`의 실행 순서와 수량 규칙을 우선하고, 검색·저장 세부 사항은 `pin.md`, 분석·프롬프트 세부 사항은 `pin분석.md`를 따른다.

## 실행 명령

사용자가 **`실행 시작`**이라고 입력하면 추가 질문 없이 전체 작업을 시작한다.

- 숫자가 없으면 레퍼런스 1개를 수집하고 그 이미지 1개를 분석한다.
- `실행 시작` 뒤에 숫자가 있으면 그 숫자만큼 수집하고 같은 수만큼 분석한다.
- 숫자 뒤의 `개`, `개 찾기`, `개찾기` 및 일반적인 띄어쓰기는 모두 같은 의미로 해석한다.

명령 예시:

- `실행 시작` → 1개 수집, 1개 분석
- `실행 시작 3` → 3개 수집, 3개 분석
- `실행 시작 3개` → 3개 수집, 3개 분석
- `실행 시작 3개찾기` → 3개 수집, 3개 분석
- `실행 시작 3개 찾기` → 3개 수집, 3개 분석

명령에서 숫자가 여러 개 발견되면 `실행 시작` 바로 뒤에 있는 첫 번째 양의 정수를 수집 수량으로 사용한다. 0이나 음수, 정수가 아닌 값은 유효한 수량으로 사용하지 않고 기본값 1개를 적용한다.

## 경로

모든 상대 경로는 이 파일이 있는 `로고` 폴더를 기준으로 한다.

- 수집 지침: `md파일/pin.md`
- 분석 지침: `md파일/pin분석.md`
- 형태 입력: `input`
- 스타일 입력: `레퍼런스`
- 이미지 출력: `output`
- Flow 프롬프트 출력: `output/flow.md`

## 1단계: 레퍼런스 수집

1. 실행 수량을 확정한다.
2. `md파일/pin.md`를 처음부터 끝까지 읽는다.
3. `input` 이미지에서 형태 기준을 분석한다.
4. `레퍼런스` 이미지에서 스타일 기준을 분석한다.
5. Pinterest에서 서로 다른 개별 핀 후보를 검색하고 비교한다.
6. 서로 중복되지 않는 적합한 이미지로 요청 수량을 채운다.
7. 사용되지 않은 다음 번호의 `similar_logo_NN.jpg` 이름으로 `output`에 저장한다.
8. 각 파일을 실제로 열어 JPEG 형식, 내용, 잘림, UI, 팝업, 워터마크, 목업 여부를 확인한다.

기존 `output` 이미지는 덮어쓰거나 수집 개수에 포함하지 않는다. 이번 실행에서 새로 저장하고 검증을 통과한 이미지만 이번 실행의 수집 결과로 계산한다.

## 2단계: 레퍼런스 분석

1. 1단계의 이미지 저장과 육안 검증이 모두 끝난 뒤 시작한다.
2. `md파일/pin분석.md`를 처음부터 끝까지 읽는다.
3. 이번 실행에서 새로 저장된 이미지 각각을 분석한다.
4. 이미지별 Flow 이미지 생성용 영문 프롬프트를 하나씩 작성한다.
5. `output/flow.md`에 이미지 파일명을 Markdown 대제목으로 쓰고 그 아래에 프롬프트를 기록한다.
6. 이번 실행에서 수집한 이미지 수와 새로 작성한 프롬프트 수가 같은지 확인한다.

기존 `flow.md` 항목은 유지한다. 같은 이미지 파일명의 항목이 이미 존재하면 `pin분석.md`의 중복 실행 방지 규칙을 따른다. 사용자가 별도로 **`재실행`**이라고 명령한 경우에만 기존 항목을 교체한다.

## 수량 보장

- 목표 수량을 채우기 전까지 적합한 검색어와 후보를 계속 검토한다.
- 품질 검증에 실패한 후보는 수량에 포함하지 않는다.
- 중복 이미지와 동일 핀의 변형 이미지는 각각 별도 결과로 계산하지 않는다.
- 적합한 후보가 부족해 목표 수량을 채울 수 없으면 확보한 결과만 분석하고, 마지막 보고에서 목표 수량·성공 수량·부족 수량과 이유를 명확히 알린다.
- 수집에 성공하지 않은 파일을 분석 완료로 보고하지 않는다.

## 완료 조건

다음 조건을 모두 만족해야 전체 실행을 완료로 보고한다.

1. 요청 수량만큼 새 JPG가 `output`에 존재한다.
2. 모든 새 JPG를 실제로 열어 검증했다.
3. 모든 새 JPG에 대응하는 영문 프롬프트가 `output/flow.md`에 존재한다.
4. `flow.md`에 중복 대제목이나 한글 프롬프트가 없다.

## 완료 보고 형식

- 요청 수량
- 수집 성공 수량
- 분석 성공 수량
- 생성한 JPG 파일 경로 목록
- 갱신한 `output/flow.md` 경로
- 각 이미지의 Pinterest 원본 핀 URL
- 실패하거나 부족한 항목이 있으면 해당 이유

중간 저장 성공만으로 완료라고 말하지 않는다. 이미지와 `flow.md`를 모두 최종 검증한 뒤 보고한다.
