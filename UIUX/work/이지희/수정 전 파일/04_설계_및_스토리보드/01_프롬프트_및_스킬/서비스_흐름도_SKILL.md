## 📐 4. 각 세트당 포함할 세 가지 파일 규격

1. **`서비스_흐름도...md`**:
   - 서비스 흐름 개요 및 클라이언트 분석서(`REQ-01~05`) 반영 요약
   - 사용자 유형과 시작 조건
   - 카드 3대 요소(사용자 행동 ➔ 화면 접점 ➔ 서비스 반응) 기반 명세
   - **`클라이언트 요구사항 (REQ ID)` 컬럼을 포함한 단계별 Flow Matrix Table**
   - **`<div align="center">`로 감싸진 화면 중앙 정렬 Mermaid `flowchart` 다이어그램**

2. **`서비스_흐름도...mmd`**:
   - `서비스_흐름도...md`에 사용한 pure Mermaid 코드만 포함

3. **`서비스_흐름도...svg`**:
   - `.mmd` 작성이 끝난 후 `npx -y @mermaid-js/mermaid-cli -i <file.mmd> -o <file.svg> -b transparent` 명령을 실행하여 공식 브라우저 렌더링 정밀 SVG를 생성한다.

## 📑 5. 작성 규칙

- 시작점과 종료점을 명확히 표시해줘.
- 주요 흐름은 기존 양식의 안정감을 기반으로 목적별 특색과 구도가 보이게 구성해줘.
- 카드별로 **[사용자 행동 ➔ 화면 접점 ➔ 서비스 반응]** 3대 요소를 필수 기재해줘.
- 클라이언트 분석서의 REQ 요구사항을 1:1로 매핑해줘.
- 모든 화면 이름은 사이트맵의 페이지 이름과 일치시켜줘 (1:1 라벨 동기화).
- 연결이 끊긴 단계나 도달할 수 없는 화면이 없는지 검토해줘.
- 작업 완료 후 생성한 파일의 상대 경로와 각 파일의 용도를 짧게 출력해줘.
