## 🏛️ 2. 화면설계서 아키텍처: 3대 공통 필수 템플릿 vs 선택적 고유 기능 결합 원칙

모든 클라이언트의 화면설계서는 동일한 UI 패턴을 무분별하게 획일화하지 않으며, **공통 필수 3대 페이지 템플릿(메인/상품/브랜드)을 기본 골격으로 탑재하되 페이지명, GNB 네비게이션, 메인 섹션 배치 위계, LNB 카테고리명, 상품 카드 레이아웃을 각 클라이언트 페르소나에 100% 맞춤 설계**하여 결합한다.

### 🛒 2-1. 전 클라이언트 공통 필수 3대 페이지 템플릿 (Mandatory Common Baseline)
**모든 클라이언트 와이어프레임(`와이어프레임_*.html`)과 화면 설계서는 다음 3대 공통 페이지를 필수로 기본 탑재하며, 페르소나별 가변 구조를 따른다**:

1. **① 메인 페이지 (`WXX-HOME`) - 페르소나별 맞춤 GNB 및 4대 섹션 가변 배치**:
   - **GNB 메뉴명**: 범용 텍스트(`메인 홈`, `20종 상품 도감` 등) 사용을 전면 금지하고, `사이트맵_통합.md`에 명시된 클라이언트 고유 GNB 메뉴명(4~5개)을 1:1 적용 (예: 박지후 `오피스 탕비실 허브`, 윤기준 `정밀 계측 콘솔`, 한명석 `20pt 큰글씨 안식 다실`).
   - **메인 4대 섹션 가변 위계**:
     - **B2B 조달형 (07 박지후, 04 임태경)**: [1] 대용량 계산기 (메인 60% 비중) ➔ [2] 시간대별 사내 복지 웰니스 큐레이션 ➔ [3] 4단 아크릴 디스펜서 0원 렌탈 ➔ [4] B2B ROI 비용 절감표
     - **숏폼 인터랙션형 (08 이지민, 05 송아린)**: [1] 실시간 pH 수색 변환 캔버스 ➔ [2] 9:16 세로형 릴스 피드 ➔ [3] 파스텔 오로라 수색별 큐레이션 ➔ [4] SNS 챌린지 랭킹 투표
     - **데이터 대시보드형 (09 윤기준)**: [1] TDS 수온/시간 용출 곡선 실시간 차트 콘솔 ➔ [2] HPLC 성분 분석표 ➔ [3] 터미널 코드 각인기 ➔ [4] Terminal Order Bar ($ git commit)
     - **시니어 큰글씨형 (11 한명석, 10 서지안)**: [1] 20pt+ 큰글씨 헤더 & ☎️ 1588 전화 배너 ➔ [2] 식약처 0g 무설탕 성분표 ➔ [3] 백자 다기 오동나무 선물함 ➔ [4] 10분 가야금 음향
   - **하단 푸터 (Footer)**: 사업자 정보, 고객센터, KTR 3無(무설탕/무카페인/무색소) 공인 성적서, 이용약관.

2. **② 상품 페이지 (`WXX-CATALOG`) - 고유 6대 LNB 및 맞춤 카드 레이아웃 의무화**:
   - **고유 6대 LNB 카테고리 연동**: `카테고리 1~5` 등의 임시 텍스트 사용을 엄격히 금지하고, `화면_설계서.md` [섹션 3]의 클라이언트 고유 6대 LNB 명칭을 100% 바인딩.
   - **20개 이상 상품 도감 (20 Curated Products)**: SEC-01 ~ SEC-20 전수 20개 상품 카드 렌더링.
   - **카드 형태 차별화**: B2B는 '벌크 패키지 스펙표', 엔지니어는 'HPLC 데이터시트 테이블', 시니어는 '2열 대형 활자 카드', 숏폼은 '9:16 비디오 썸네일 카드'.

3. **③ 브랜드 페이지 (`WXX-ABOUT`) - 고유 헤리티지 스토리 & 특화 룸 결합**:
   - **브랜드 스토리 & 철학**: 브랜드 세계관('비밀정원 다과회') + 조향/추출 철학 + KTR 3無 공인 인증서 + 클라이언트 특화 룸(성수 쇼룸 시향 예약, 사내 복지 리포트, 크로마토그래피 성분표, 지리산 다원 이야기).

> ⚠️ **와이어프레임 생성 제1원칙**:  
> **각 클라이언트 와이어프레임(`와이어프레임_*.html`)마다 이 3대 공통 페이지(메인페이지, 상품페이지, 브랜드페이지)를 기본 탑재한 뒤, 클라이언트별 고유 킬러 기능(B2B 계산기, 숏폼 플레이어, TDS 데이터, 시니어 1588 콘솔 등)을 결합하여 생성해야 한다.**

## 🏛️ 3. 화면설계서 핵심 품질 규칙

### 원칙 1. 상위 통합 문서 연계 및 3단계 상태 구분 표기 원칙
- 화면 설계서 및 와이어프레임 생성 시 **'100% 일치', '100% 동기화', '완전 차별화', '오차 0%' 등의 단정적·과장된 검증 표현을 엄격히 금지**한다.
- 실제 구현 검증 상태는 다음 **3단계 상태(Status) 시스템**으로 구분하여 정직하고 투명하게 명시한다:
  1. **`📐 설계 기준 (Design Baseline)`**: IA, 와이어프레임 그리드, 여백/폰트 규격 등 기획 및 설계 명세서 상의 기준
  2. **`🎯 반영 목표 (Target Goal)`**: 화면 및 인터랙션이 궁극적으로 달성하고자 하는 비즈니스/기능적 목표
  3. **`🔍 확인 필요 (Pending QA)`**: 실제 코드(HTML/CSS/JS)에서 비교 검사, DOM 바인딩 및 이벤트 핸들러 동작 확인이 필요한 항목
- `화면_설계서.md` 상단 메타데이터 영역 및 요구사항/화면 매핑표에 `상태(Status)` 컬럼을 필수로 포함한다.

### 원칙 2. 킬러 기능 ID 및 화면 ID 1:1 DOM 바인딩 의무화
- `화면_설계서.md`에 명시된 킬러 기능 ID(`PANTRY-CALC-01`, `AURORA-FINDER-01`, `PRECISION-DASH-01`, `PHONE-ORDER-01` 등)와 화면 ID(`WXX-HOME`, `WXX-CALCULATOR`, `WXX-REELS` 등)는 **와이어프레임 HTML에서 단순 텍스트가 아닌 실제 `<section id="...">`, `<div data-feature-id="...">` 등의 DOM 식별자로 1:1 매핑**되어야 한다.
- 슬라이더, 인풋 필드, 다운로드 버튼 등 조작 요소는 `oninput`, `onclick`, `onchange` 이벤트 핸들러를 탑재하여 실제 인터랙티브 상태(수색 변화, 견적 자동 계산, JSON 다운로드 등)가 동작하도록 구현한다.

### 원칙 3. 체크아웃(Checkout) 및 카탈로그(Catalog) UI의 페르소나 차별화
- **체크아웃 방식**:
  - 일반 D2C: `Slide-out Cart Drawer`
  - B2B 기업: `B2B 견적서 & 세금계산서 청구 드로어/모달`
  - 시니어: `1588 전화 주문 모달 / 원클릭 전화 배너`
  - 엔지니어: `Terminal Commit Bar & Order Console`
- **카탈로그 형태**:
  - B2B: `120/180/300포 벌크 패키지 그리드`
  - 엔지니어링: `HPLC 성분 분석 데이터시트 테이블`
  - 시니어: `2열 특대 활자 카드`
  - 숏폼: `9:16 비디오 썸네일 피드`

### 원칙 4. 100% 무채색(Monochrome) 저충실도 와이어프레임 원칙
