## 🎯 1. 실행 트리거 명령어 (Trigger Commands)

### 1.1 특정 클라이언트 단일 생성 명령어
- **특정 클라이언트 사이트맵 생성**: `"[이름] 사이트맵 만들어"`, `"[이름] 사이트맵 생성해"`, `"[이름] 사이트맵 진행"` (예: `"차은채 사이트맵 만들어"`, `"신유진 사이트맵 생성해"`)
- **특정 클라이언트 서비스 흐름도 생성**: `"[이름] 서비스 흐름도 생성해"`, `"[이름] 서비스 흐름도 진행"` (예: `"신유진 서비스 흐름도 생성해"`, `"송아린 서비스 흐름도 진행"`)
- **특정 클라이언트 화면 설계서 진행**: `"[이름] 화면 설계서 진행"`, `"[이름] 화면설계서 진행"` (예: `"박지후 화면 설계서 진행"`, `"이지민 화면설계서 진행"`)
- **특정 클라이언트 전체 설계 진행**: `"[이름] 설계 진행"` (예: `"서지안 설계 진행"`, `"차은채 설계 진행"`)
- **통합 스토리보드 진행**: `"[이름] 스토리보드 진행"` 또는 `"[이름] 스토리보드 실행"`

### 1.2 기존 클라이언트 결과부터 다시 실행 & 전사 자동 순차 파이프라인 명령어
- **기존 클라이언트 결과부터 다시 실행**: `"기존 클라이언트 결과부터 다시 실행"`, `"기존 클라이언트부터 다시 실행"`, `"설계 전체 다시 실행"`, `"화면 설계서 전체 다시 실행"`, `"스토리보드 전체 다시 실행"`
  ➔ **01번 클라이언트(차은채)부터 11번 클라이언트(한명석)까지 순차적으로 공통 필수 커머스 코어와 선택적 고유 기능 분리 원칙을 적용하여 산출물 전수 갱신**

### 1.3 클라이언트 공식 모수 및 진행 상태 기준 (Client Scope & Status)
1. **정식 확정 범위 (Official Baseline Scope)**:
   - **현재 확정 인원**: 총 **11명** (`01 차은채` ~ `11 한명석`)
   - 사이트맵, 서비스 흐름도, 화면 설계서, 스토리보드의 **기본 완료 및 전수 동기화 기준은 11명**으로 통일한다.
2. **20명 확장 로드맵 및 상태 표기 원칙 (Status Registry)**:
   - 향후 20명까지 확장을 대비하되, 현황표 및 보고서 작성 시 상태를 다음과 같이 엄격히 구분 표기한다:
     - **01번 ~ 11번**: `[정식 확정 / 파이프라인 완결 및 진행 대상]`
     - **12번 ~ 20번**: `[미생성 / 백로그(Backlog) 대기]`
   - 일괄 자동화 파이프라인 실행 시 **11번(한명석) 완결을 1차 전체 완료 기준**으로 삼으며, 12~20번은 사용자의 명시적 신규 생성 지시 전까지 미생성 대기 상태를 유지한다.

## 🎯 2. 3대 공통 필수 템플릿 vs 선택적 고유 기능 분리 원칙 (Architecture Separation)

### 2.1 전 클라이언트 공통 필수 3대 페이지 템플릿 (Mandatory Common Baseline)
**모든 클라이언트 와이어프레임(`와이어프레임_*.html`)과 화면 설계서는 다음 3대 공통 페이지를 필수로 기본 탑재하며, 페르소나별 가변 구조를 따른다**:
- **① 메인 페이지 (`WXX-HOME`)**: 
  - **GNB 명칭**: 범용 텍스트(`메인 홈` 등) 사용 금지, 클라이언트 고유 GNB 메뉴 4~5개 적용 (예: 박지후 `오피스 탕비실 허브`, 윤기준 `정밀 계측 콘솔`, 한명석 `20pt 큰글씨 안식 다실`)
  - **메인 섹션 위계**: 페르소나별 최적화된 4대 섹션 순서 가변 배치 (B2B 계산기 60% 상단 배치, 숏폼 릴스 피드 상단 배치, 데이터 차트 콘솔 상단 배치, 시니어 20pt 큰글씨 배너 상단 배치)
  - **하단 푸터**: 사업자 정보, 고객센터, KTR 3無 공인 인증
- **② 상품 페이지 (`WXX-CATALOG`)**:
  - **고유 6대 LNB 연동**: `화면_설계서.md` [섹션 3]의 클라이언트 맞춤 6대 LNB 카테고리명 100% 매핑
  - **20개 이상 상품 전수 도감**: SEC-01 ~ SEC-20 전수 20개 상품 카드 렌더링 (B2B 벌크 규격, 데이터시트 테이블, 시니어 2열 대형 카드, 숏폼 9:16 비디오 카드)
- **③ 브랜드 페이지 (`WXX-ABOUT`)**: 브랜드 세계관, 조향/추출 철학, 원료 원산지 및 헤리티지 스토리텔링 (클라이언트별 특화 룸 결합)

> ⚠️ **와이어프레임 및 화면 설계 제1원칙**:  
> **각 클라이언트 와이어프레임(`와이어프레임_*.html`)마다 이 3대 공통 페이지(메인페이지, 상품페이지, 브랜드페이지)를 기본 탑재한 뒤, 클라이언트별 고유 킬러 기능(B2B 계산기, 숏폼 플레이어, TDS 데이터, 시니어 1588 콘솔 등)을 결합하여 생성한다.**

---

### 2.2 클라이언트 유형별 선택적 고유 기능 (Optional Unique Features)
- **B2B 조달형 (07 박지후, 04 임태경)**: 팀원수 견적 계산기, 0원 샘플 신청, 디스펜서 렌탈, 세금계산서 청구
- **숏폼 인터랙션형 (08 이지민, 05 송아린)**: 실시간 수색 변환 슬라이더, 9:16 릴스 플레이어, 포토카드 에디터, 챌린지 랭킹
- **데이터 대시보드형 (09 윤기준)**: TDS 용출 곡선 차트, 수질 매칭 알고리즘, 터미널 Syntax 각인, JSON 로그 다운로더
- **시니어/패밀리형 (11 한명석, 10 서지안)**: 20pt 큰글씨 뷰, ☎️ 1588 전화 주문 콘솔, 혈당/혈압 무당 성분표, 10분 다도 묵상 오디오
- **D2C 감성/선물형 (01 차은채, 02 신유진, 03 윤서연, 06 이도은)**: 3D 회전 선물 패키징, 이니셜 각인 스튜디오, TPO 무드 진단
> *(※ 01~11번 정식 확정 인원 기준 매핑이며, 12~20번 클라이언트는 향후 신규 기획 시 해당 유형으로 추가 편입 예정 - 현재 [미생성/백로그 대기])*

## 🔗 4. 핵심 연계 및 품질 검증 규칙

1. **킬러 기능 ID 및 화면 ID의 DOM 1:1 바인딩**:
   - 설계 문서의 킬러 기능 ID 및 화면 ID는 HTML 와이어프레임/스토리보드의 DOM 태그(`id` 또는 `data-feature-id`)와 1:1로 매핑되고, 실제 이벤트 핸들러(`oninput`, `onclick` 등)를 통해 인터랙션 상태가 작동해야 합니다.
2. **라벨 1:1 동기화 규칙**:
   - 서비스 흐름도, 사이트맵, 화면 설계서, 스토리보드의 모든 화면/단계 이름 및 접점 ID는 100% 동일하게 일치시킵니다.
3. **SVG 파일 자동 컴파일 규칙**:
   - Mermaid CLI(`@mermaid-js/mermaid-cli`)를 통해 정밀 벡터 SVG 파일을 항상 동시 출력하여 최신 상태를 유지합니다.
