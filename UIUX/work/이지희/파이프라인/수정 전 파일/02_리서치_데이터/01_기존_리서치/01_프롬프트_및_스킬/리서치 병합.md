# WICKETA Reference Fix Final Merge Process

> 공통 규칙(브랜드 컨셉, 경로 통제 등)은 `CLAUDE.md`를 따른다. 아래는 이 단계 고유의 절차다.
>
> ⚠️ 원본 파일명은 `리서치.md`였으나, 리서치 보고서 작성 스킬(`리서치 수집.md`)과 역할이 달라(이 스킬은 "레퍼런스 목록 병합·중복 제거"가 목적이지 리서치 보고서 작성이 아님) `리서치 병합.md`로 이름을 정리했다.

   - 내용: 기존 200개 사이트 분석 후 최종 유지된 사이트 목록, 사이트 선정 이유, 활용 가능 영역

2. **`[신규리서치]_위케티_레퍼런스_119.txt`**
   - 위치: `C:\UIUX이지희\Antigravity\자동화\02_리서치_데이터\02_신규_리서치\`
   - 내용: 부족한 사이트 수 보충을 위해 신규 리서치한 사이트, 검색 키워드, 검색 목적, 선정 이유, 디자인/UX 특징, 중복 검증 결과

3. **Reference Format File**
   - 역할: 최종 출력 구조 및 데이터 작성 양식 기준 (반드시 해당 구조와 동일한 형태 출력)

## 🚀 MAIN TASK

### STEP 1. 데이터 통합
`[리서치_데이터] 위케티_200개_사이트_레퍼런스.txt` (200개)와 `[신규리서치]_위케티_레퍼런스_119.txt` (119개)를 통합합니다.
- **통합 기준**: 동일 사이트 제거, 동일 도메인 제거, 중복 브랜드 제거 (기존 선정 사이트 우선 유지)

### STEP 2. 사이트 데이터 재검증
각 사이트별 확인 사항:
- WICKETA 브랜드 적합성
- 디자인 참고 가치
- UX 참고 가치
- 활용 가능 영역 (필요시 사이트 분류 수정 가능)

### STEP 3. FINAL OUTPUT FORMAT 적용
최종 결과물은 반드시 `wicketa_reference_step3_final(200).txt`와 동일한 형식으로 작성합니다.
> ⚠️ **주의**: 새로운 출력 양식을 만들지 않으며, 표 구조, 항목 순서, 사이트 정보 작성 방식, 구분 방식 모두 기존 파일을 따릅니다.
