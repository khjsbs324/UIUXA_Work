# 위케티 리서치 수행

이 Skill은 WICKETA (위케티) 브랜드 웹사이트 UI/UX 기획 및 레이아웃 벤치마킹을 위한 리서치 보고서만 작성한다. 트렌드 분석, 제안서, PPT를 함께 만들지 않는다. 결과를 스스로 승인하지 않는다.

> 공통 규칙(경로 통제, 브랜드 컨셉, 3단계 실행 순서, 보고 체계, 팩트 검증 공통 원칙)은 `CLAUDE.md`를 따른다. 아래는 이 단계 고유의 절차다.

## 입력

사용자 요청: `$ARGUMENTS`

1. `[리서치_데이터] 위케티_200개_사이트_레퍼런스.txt`(위치: `사이트 리서치/`)를 기본 입력으로 사용한다.
2. 인수가 비어 있으면 해당 200개 레퍼런스 데이터베이스를 기본 데이터베이스로 사용한다.
3. 인수에 파일 경로가 있으면 프로젝트 내부의 실제 파일인지 확인하고 읽는다.
4. 리서치 대상 브랜드, 비주얼 무드, 프론트엔드 기능, WICKETA 적용 포인트를 추출한다.
5. 핵심 범위가 없지만 합리적인 기본값을 쓸 수 있으면 `가정`으로 표시한다. 결과가 크게 달라질 선택만 사용자에게 확인한다.

## 조사 계획 및 수집 목표

1. **50개 수집 목표**: 1회 리서치 진행 시 검증된 신규 레퍼런스 사이트 **50개 단위**로 수집을 완료한다.
2. **중복 0건 검증**: 기존 레퍼런스 데이터베이스(`01_기존_리서치`, `03_사이트_리스트`) 및 기존 수집 사이트와 도메인/URL/브랜드 중복을 전수 체크하여 중복 0건을 준수한다.
3. 핵심 질문을 3~7개로 정리한다 (예: 내면 무드 진단 퀴즈 폼, 차 우림 타이머, 롱스크롤 에세이 스토리보드, 비대칭 12컬럼 여백).
4. 질문별 검색어와 벤치마킹 기준(디자인+사용성 / 사용성 / 디자인 적합)을 설정한다.
5. WICKETA 브랜드 핵심 컨셉("Drink Me, Escape Reality") 및 4대 UI/UX 설계 전략과 상응하는 레퍼런스를 선별한다.

## 조사와 검증

1. **실제 연결 상태 검증 (Active Link)**: 수집하는 50개 웹사이트의 실제 접속 가능 여부(HTTP 200 OK)를 직접 확인하고, 작동 불능 URL은 수집 대상에서 즉시 제외한다.
2. 공식 브랜드 웹사이트, 브랜드 소개 원문 텍스트, 프론트엔드 실재 기능 1차 자료를 우선한다.
3. 브랜드명, URL, 비주얼 톤앤매너, 주요 기능 수치에 대해 독립된 근거를 검증한다.
4. 검색 결과의 요약문만 인용하지 말고 원문 화면 및 기능을 확인한다.
5. 수집 일시, 중복 여부(Duplicate Check 0건), 카테고리 매핑을 검증한다.
6. 출처나 기능 정보가 충돌하면 차이를 숨기지 말고 기준과 한계를 설명한다.
7. 확인할 수 없는 수치, 지어낸 기능, 작동 불능 URL은 사용하지 않는다.
8. 주관적 장단점이나 단순 의견은 외부 팩트처럼 표현하지 않는다.
9. 50개 검증 완료 시 분류(`리서치 분류.md`), 분석(`리서치 분석.md`), 통합 결과 보고 파이프라인을 연속하여 자동 실행한다.

본문의 핵심 근거에는 `[S01]` 형식의 출처 번호를 붙이고, 같은 번호를 출처 표에 연결한다.

## 작성

1. 팩트 기반 리서치 보고서의 필수 구조(1차 적합성, 2차 도메인, 3차 인터랙션 매핑)를 사용한다.
2. 객관적 사실(Fact)과 WICKETA 벤치마킹 해석을 별도 문단이나 표 열로 명확히 구분한다.
3. 각 레퍼런스 발견점마다 WICKETA 브랜드 적용 확신 수준과 다음 분석 질문을 표기한다.
4. 검증되지 않았거나 부족한 정보는 `추가 확인 필요 자료`에 기록한다.
5. 결론을 부풀리지 않고 200개 레퍼런스 데이터베이스 범위 안에서만 요약한다.
