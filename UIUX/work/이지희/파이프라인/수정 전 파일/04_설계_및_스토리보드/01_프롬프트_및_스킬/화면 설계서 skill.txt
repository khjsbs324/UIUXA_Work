[ 화면 설계서 제작]

사용자가 "서지안 화면 설계서 진행", "서지안 화면설계서 진행", 또는 "화면 설계서 진행" 지시문을 명령할 때 본 스킬을 실행해줘.

입력 및 출력 경로 규격:
- 사이트맵 입력 파일: C:\UIUX이지희\Antigravity\자동화\04_설계_및_스토리보드\사이트맵\사이트맵$(클라이언트번호)_$(이름)_*.md
- 서비스 흐름도 입력 파일: C:\UIUX이지희\Antigravity\자동화\04_설계_및_스토리보드\서비스 흐름도\서비스_흐름도$(클라이언트번호)_$(이름)_*.md
- 추가 참고 파일: C:\UIUX이지희\Antigravity\자동화\03_클라이언트\03_사이트_분석\[사이트 분석] 가상클라이언트$(클라이언트번호)_$(이름)_위케티_분석결과.md
- 결과물 저장 폴더: C:\UIUX이지희\Antigravity\자동화\04_설계_및_스토리보드\화면 설계서\

다음 파일 세트를 UTF-8 인코딩으로 생성해줘.

1. `화면_설계서$(클라이언트번호)_$(이름).md`
   - 프로젝트 및 설계 범위
   - 화면 ID 규칙과 전체 화면 목록
   - 화면별 목적, 진입 조건, 종료 조건
   - 화면 구성 영역과 UI 요소
   - 표시 데이터, 사용자 행동, 인터랙션, 이동 대상
   - 기본·로딩·빈 상태·오류·완료 상태
   - 유효성 검사와 오류 메시지
   - PC·태블릿·모바일 반응형 기준 및 접근성 요구사항
2. `와이어프레임$(클라이언트번호)_$(이름).html`
   - 외부 라이브러리 없이 브라우저에서 단독 실행 가능한 HTML/CSS/JavaScript 파일
   - 화면별 저충실도 와이어프레임과 화면 ID·이름 표시
   - 상단 목차 또는 사이드바에서 각 화면으로 이동 가능
   - 버튼과 링크를 누르면 서비스 흐름에 맞는 화면으로 이동
   - 모바일, 태블릿, 데스크톱 레이아웃을 확인할 수 있는 반응형 구성
3. `화면_목록$(클라이언트번호)_$(이름).json`
   - 각 화면의 `id`, `name`, `purpose`, `entryConditions`, `sections`, `actions`, `states`, `nextScreens`를 포함한 유효한 JSON

작성 규칙:
- 사이트맵과 서비스 흐름도에 정의된 화면 이름과 이동 관계를 그대로 사용해줘.
- 화면마다 고유한 화면 ID를 부여하고 세 결과물에서 동일하게 유지해줘.
- 공통 헤더, 푸터, 내비게이션과 반복 컴포넌트는 일관되게 적용해줘.
- 이미지 영역은 대체 텍스트가 있는 플레이스홀더로 표현해줘.
- 입력 파일에 없는 상세 정책은 `가정`으로 표시하고 설계서에 따로 모아줘.
- HTML의 모든 내부 이동, 주요 버튼, 반응형 레이아웃과 JSON 문법을 검사해줘.
- 작업 완료 후 생성한 파일의 경로와 실행 방법을 짧게 출력해줘.
