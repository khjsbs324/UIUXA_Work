# 이지희 WICKETA 최종 수정 파일

이지희 학생의 WICKETA 프로젝트를 기준으로 설계 문서와 와이어프레임을 전면 재구성한 결과물입니다. 다른 학생의 브랜드 구조나 화면 흐름을 복제하지 않고, WICKETA의 감정 기반 티 믹솔로지 경험에 맞춰 작성했습니다.

## 이지희 전용 설계 기준

- 브랜드: WICKETA
- 핵심 경험: 감정 진단 → 믹솔로지 조합 → 180초 리추얼 → 번들 설계 → 저장·커뮤니티
- 메인 화면: WICKETA 경험 모듈 12개와 상품 카드 20개로 구성
- 개인화: 20명에게 서로 다른 콘셉트·킬러 기능·`WNN-*` 화면 ID 적용
- 레이아웃: editorial, lab, dashboard, spatial, social 5개 유형으로 분화
- 상품 전략: 단순 상품 나열보다 감정·향·시간대·음용 상황을 연결한 큐레이션 중심
- 제외 기준: SOAPHE형 선형 상품 소개 및 사전 신청 흐름 미사용

## 폴더 구성

- `client-manifest.json`: 20명 클라이언트의 콘셉트, 기능, 레이아웃 기준
- `설계 자동화 파이프라인.md`: WICKETA 전용 생성·검증 규칙
- `사이트맵/NN_이름`: 사이트맵 4종
- `서비스 흐름도/NN_이름`: 서비스 흐름도 4종
- `화면 설계서/NN_이름`: 화면 설계서와 와이어프레임 6종
- `workflow-status.md`: 전체 생성 상태
- `검증.ps1`: 결과물 자동 검증
- `검증_보고서.md`: 최종 검증 결과

## 확인 순서

1. `client-manifest.json`에서 대상 클라이언트의 콘셉트와 킬러 기능 확인
2. 사이트맵 → 서비스 흐름도 → 화면 설계서 순서로 설계 근거 확인
3. 대상 폴더의 `와이어프레임.html`에서 동작과 콘텐츠 확인
4. `검증.ps1` 실행 후 `검증_보고서.md`에서 누락 여부 확인
