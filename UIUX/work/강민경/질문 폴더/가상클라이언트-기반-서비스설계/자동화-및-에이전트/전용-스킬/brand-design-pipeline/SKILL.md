# Brand Design Pipeline

## 시작

1. `../../00-작업관리/통합-작업관리.md`를 읽는다.
2. 현재 단계, 최신 `Vn`, 활성 결과와 남은 검증을 확인한다.
3. 새 폴더를 만들기 전에 해당 단계 폴더가 있는지 확인한다.
4. 실질적인 추가·수정이 있을 때만 같은 단계 폴더에 다음 `Vn`을 만든다.

## 실행

`SOURCE → FINDING → CLIENT → REQ → PRODUCT → PAGE → FLOW → SCREEN → STORYBOARD` 순서를 지킨다. 각 단계는 자신의 출력 범위를 넘지 않는다.

- 단계별 필드·수량·페이지 역할·검증 기준은 통합 작업관리 문서를 따른다.
- 실제 도출 값은 반드시 `../../<번호>-<단계명>-출력물/`에 저장한다.
- 단계 폴더명에는 `클라이언트생성`, `사이트구조맵`, `서비스흐름도`처럼 실제 단계명을 명시한다.
- 작업관리 MD, Skill, 체크리스트, 감사 기록과 이전 이력을 단계별 출력 폴더에 저장하지 않는다.
- 중요 오류가 있으면 다음 단계로 넘어가지 않고 `REVISION_REQUIRED`로 기록한다.
- 각 대상을 `대량 생성 → 구분·분류 → 탐색 → 검증 → 추가 생성·수정 → 재검증 → 판정` 순서로 반복한다.
- 자동화 문서나 표지만으로 실제 후보를 대신하지 않는다. 결과 MD 안에서 각 후보의 이름, 내용, 판정과 추적 연결을 직접 확인할 수 있어야 한다.
- 신규·재검수·수정·검증마다 폴더나 MD를 만들지 않는다. 한 버전 문서 안에 Section으로 기록하고, 실질적인 변경 후에만 `V2`, `V3`로 올린다.
- 후보 하나마다 파일을 만들지 않는다. 단계별 기준 MD 하나를 우선하고 시각 검증이 필요할 때만 같은 버전의 HTML을 추가한다.
- 시작하지 않은 단계의 폴더와 빈 파일을 만들지 않는다.
- `도출결과-Vn`, 사용자 승인 후의 `병합결과-Vn`, 제출 확정 후의 `최종제출-Vn`을 파일명에서 구분한다.

## 반복

새 Client는 기존 집합에 없는 문제·행동·판단 기준·충돌·예외를 추가해야 한다. 후보 수와 품질을 함께 기록하며, 중복 후보도 생성 사실과 제외 이유를 같은 버전 문서에 보존한다. 결과는 `KEEP`, `MERGE`, `REVISE`, `HOLD`, `EXCLUDE`로 분류한다. Client 단계에서는 사용자 요구에 따라 Client 1명당 개별 상세 MD 1개를 실제 출력물로 만들고, 인덱스는 링크·집계만 관리한다. Client 내용을 하나의 병합 문서로 대체하지 않는다.

## 최종 병합 차단

모든 단계의 후보 생성·검증이 끝나지 않았거나 사용자 승인이 없으면 최종 병합을 실행하지 않는다. 조건을 충족하면 사용자에게 `이제 병합 진행을 추천합니다`라고 먼저 보고한 뒤 최종 전환 승인을 요청한다.
