# 단계별 자동 실행 계약

## 공통 실행 단위

각 단계는 다음 7개 블록을 반드시 출력한다.

1. 입력 및 승인·근거 수준
2. 생성 결과
3. 상위·하위 ID Mapping
4. 정상·예외·HOLD
5. 직관·창의 독립 검토
6. 근거 감사와 오류 등급
7. 내부 판정과 다음 배치

## 사이트맵 실행기

입력: Client·REQ·기존 Page·대표 Page 후보.  
출력: Page 후보, 목적, Parent, Depth, 상태, 콘텐츠·기능, Cross link, 생성·통합·제외 이유.  
차단: 근거 없는 Page, 고립 Page, 같은 목적 중복, HOLD 기능의 Page 승격.

## 서비스 흐름 실행기

입력: 승인·후보 Page와 Client 과업.  
출력: Actor, 시작, Trigger, 행동, 상태, 분기, 오류, 취소, 복귀, 종료, 관련 ID.  
차단: Happy path만 존재, 실패 후 입력 소실, 종료·복귀 없음, Page ID 불일치.

## 화면설계서 실행기

입력: Page·Flow·콘텐츠·기능·정책.  
출력: Screen, Section, Content, UI, 행동, 상태, Validation, 반응형, 접근성, 다음 화면, 근거.  
차단: Flow에 없는 행동, Label 없는 입력, 오류·빈 상태 누락, 실제 기능 오인.

## 스토리보드 실행기

입력: Screen 계약·브랜드 원칙·카피·샘플 데이터.  
출력: 순서, 목적, 카피, 콘텐츠, UI·배치, 행동, 상태·예외, 반응형·접근성, 근거.  
차단: 화면설계와 다른 기능, 장식만 있는 Section, 근거 없는 상품·정책·효과.

## 병합 실행기

동일 ID와 목적을 먼저 비교한다. `KEEP / MERGE / REVISE / HOLD / EXCLUDE` 판정과 이유를 남기고, 원본 배치 결과는 삭제하지 않는다. 병합본은 사용자 승인 전 `MERGE_CANDIDATE`만 사용한다.

## 검증 실행기

수량·ID·상태·링크를 기계적으로 검사하고, 목적·서사·브랜드 적합성은 독립 관점 패스로 검사한다. 자동 검증하지 않은 항목을 PASS로 기록하지 않는다.
