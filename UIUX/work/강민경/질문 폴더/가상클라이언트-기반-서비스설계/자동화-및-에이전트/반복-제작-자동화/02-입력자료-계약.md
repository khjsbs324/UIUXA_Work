# 반복 제작 입력자료 계약

## 공통 필수 입력

| 입력 | 최소 조건 | 사용 범위 |
|---|---|---|
| 원본 조사 자료 | 경로·출처·변조 없음 | 사실 검증 |
| 종합 분석 | 발견·한계·근거 ID | Client 후보 |
| 기존 Client | 상태·문제·목표·요구 | 중복·공백 판정 |
| 요구사항 등록부 | 우선순위·상태·Client 연결 | 구조·기능 판단 |
| 사이트 경험 분석 | 패턴·예외·적용 조건 | 설계 대안 |
| 브랜드 기획 | 브랜드 목적·말씨·시각 원칙 | 콘텐츠·표현 |
| 콘텐츠·기능 정책 | Page·Section·Function·상태 | 화면 설계 |
| 디자인 토큰 | 확정·가설 구분 | 와이어프레임·Figma |

## 단계 전달 계약

모든 산출물에는 `ID`, `상태`, `근거`, `결정 이유`, `미정 사항`, `다음 단계 전달 필드`를 포함한다.

```text
SOURCE → FINDING → CLIENT → REQ → PAGE → FLOW → SCREEN → STORYBOARD
```

하나라도 연결되지 않으면 `UNMAPPED`로 기록한다. 추적되지 않은 항목을 다음 단계의 확정 입력으로 사용하지 않는다.

## 사실 수준

- `FACT`: 원본에서 직접 확인
- `INFERENCE`: 복수 근거에서 합리적으로 도출
- `HYPOTHESIS`: 검증이 필요한 설계 가설
- `TBD`: 정책 또는 자료 미정
- `HOLD`: 현재 범위에서 사용 금지

가설을 사실처럼 쓰거나 TBD에 임의 수치를 넣지 않는다.
