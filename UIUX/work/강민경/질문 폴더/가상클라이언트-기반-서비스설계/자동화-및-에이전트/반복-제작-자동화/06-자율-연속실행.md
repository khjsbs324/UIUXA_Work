# 최종 병합 전 자율 연속 실행 규칙

## 1. 목적

최종 병합 직전까지 작업을 매번 사용자에게 확인하지 않고 연속 실행한다. 각 배치에서 생성·독립 검토·반려·수정·재검증을 반복해 결과를 점진적으로 개선한다.

이 문서의 `내부 통과`는 사용자의 최종 승인이나 프로젝트의 `USER_APPROVED`를 대신하지 않는다. 최종 병합 전환과 최종 제출 확정은 항상 사용자 승인 대상으로 남긴다.

## 2. 사용자 위임 범위

사용자가 위임한 범위:

- 최종 병합 전 단계의 다음 배치 선택
- 기존 근거 안에서 설계 대안 생성
- 중복 Client·REQ·Page·Flow·Screen 병합 후보 판정
- 품질 미달 결과 반려와 수정
- 정적 검증과 추적성 검사
- 중요하지 않은 미정 항목을 HOLD로 격리하고 나머지 작업 계속
- 배치 결과와 인수인계 갱신
- 작업 결과 Git 커밋과 기존 원격 저장소 백업

위임되지 않은 범위:

- 사용자 대신 최종 승인
- 최종 병합·최종 제출 확정
- 브랜드명·상표·실제 가격·법률·개인정보 정책 확정
- 조사에 없는 사실·제품 사양·사용자 행동 생성
- 원본 삭제·이동·덮어쓰기
- 실제 결제·로그인·저장·동기화 기능 제공 결정

## 3. 연속 실행 상태 머신

```text
READY
→ SELECT_NEXT_GAP
→ GENERATE_BATCH
→ INTUITION_PASS
→ CREATIVE_PASS
→ INTEGRATION_PASS
→ EVIDENCE_AUDIT
→ INTERNAL_GATE
   ├─ INTERNAL_PASS → REGISTER_RESULT → SELECT_NEXT_GAP
   ├─ INTERNAL_REVISE → REVISE_BATCH → EVIDENCE_AUDIT
   └─ INTERNAL_HOLD → ISOLATE_HOLD → REGISTER_RESULT → SELECT_NEXT_GAP

품질 조건 2개 연속 배치 충족
→ FINAL_GATE_PENDING
→ USER_APPROVAL_PENDING
```

## 4. 독립 검토 패스

실행 환경에 별도 에이전트가 없거나 사용하지 않는 경우 `EXECUTION_MODE=단일 CLI 팀별 독립 패스 실행`으로 기록한다. 각 패스는 앞 패스의 결론을 복사하지 않고 동일 원본 결과를 별도로 검토한다.

### 직관 패스

- 핵심 목적과 사용자 과업이 한 문장으로 설명되는가
- 정보 구조와 다음 행동이 단순한가
- 불필요한 Page·Section·기능이 있는가
- 대표 3페이지의 역할이 구분되는가
- 일정 안에 구현 가능한가

### 창의 패스

- 빠진 Client 상황·예외·브랜드 접점이 있는가
- 더 차별화되면서 실행 가능한 대안이 있는가
- 상품 15개가 단순 나열이 아닌 탐색 경험을 만드는가
- 브랜드 스토리와 상품·기능이 연결되는가
- 기존 결과의 관성 때문에 놓친 구조가 있는가

### 통합 패스

- 두 관점의 공통점·충돌을 분리한다.
- `KEEP / MERGE / REVISE / HOLD / EXCLUDE`를 판정한다.
- 채택 이유와 거부 이유를 모두 기록한다.
- 하위 산출물에 영향을 주는 변경을 `STALE_CANDIDATE`로 표시한다.

### 근거 감사

- 모든 중요 항목의 Source·Client·REQ·Page·Flow·Screen 연결을 검사한다.
- FACT·INFERENCE·HYPOTHESIS·TBD·HOLD 오표기를 찾는다.
- 근거 없는 수치·정책·효과·제품 정보를 반려한다.
- ID 중복·고립 Page·Dead end·상태 누락을 반려한다.

## 5. 내부 판정

`INTERNAL_PASS` 조건:

1. 해당 배치의 필수 출력이 모두 존재한다.
2. Critical 오류가 0건이다.
3. High 오류가 0건이거나 다음 배치에 영향 없이 HOLD로 격리됐다.
4. 모든 중요 결정에 근거 수준과 상위 ID가 있다.
5. 새 결과가 이전 결과보다 명확성·추적성·실행 가능성 중 하나 이상 개선됐다.

`INTERNAL_REVISE` 조건:

- Critical 또는 해결 가능한 High 오류가 존재
- Client·REQ·Page·Flow·Screen 추적 단절
- 대표 페이지 역할 중복
- 근거 없는 확정 또는 HOLD 항목의 기능 승격
- 새 배치가 개선 없이 문서량만 증가

`INTERNAL_HOLD` 조건:

- 실제 사용자 조사·공식 제품 자료·사용자 정책 결정이 필요한 항목
- 수정해도 현재 근거로 진전할 수 없는 항목
- 최종 대표 3페이지 작업을 차단하지 않는 미정 사항

## 6. 오류 등급

| 등급 | 의미 | 처리 |
|---|---|---|
| Critical | 근거 조작, ID 붕괴, 원본 훼손, 대표 흐름 불가능 | 즉시 반려·수정 전 다음 단계 금지 |
| High | 핵심 요구 누락, Page 역할 충돌, 접근성 핵심 실패 | 같은 배치에서 수정 |
| Medium | 카피·정렬·세부 상태·보조 흐름 문제 | 수정하거나 다음 배치 작업으로 등록 |
| Low | 표현·오탈자·문서 형식 | 배치 종료 전 정리 |

## 7. 반복 한도와 정체 방지

- 같은 원인으로 3회 연속 실패하면 해당 항목만 HOLD로 격리한다.
- 다른 작업이 가능하면 전체 파이프라인을 중단하지 않는다.
- 2개 연속 배치에서 새 가치가 없으면 Client·Page·기능 추가를 중단하고 압축 단계로 전환한다.
- 문서 수·Client 수·Page 수 자체를 품질 지표로 사용하지 않는다.
- 매 배치에서 `새로 추가된 가치`, `제거된 복잡성`, `남은 위험`을 기록한다.

## 8. 다음 작업 자동 선택 우선순위

1. Critical·High 오류 수정
2. 끊긴 추적성 복구
3. 대표 3페이지의 목적·콘텐츠·행동·상태 완성
4. 상품·패키지 15개의 정보 계약과 카테고리 연결
5. 서비스 흐름·화면설계서·스토리보드 계약 일치
6. 접근성·오류·빈 상태·복귀 상태
7. 브랜드 서사·카피·시각 원칙 일관성
8. Medium·Low 개선

## 9. 허용 중단 조건

다음 경우에만 사용자에게 돌아간다.

- 최종 병합 전환 조건 충족
- 브랜드명·상품 실정보·정책처럼 사용자 결정 없이는 핵심 흐름이 달라짐
- 원본 또는 필수 입력이 없어 안전한 대안도 없음
- 같은 핵심 차단 원인이 3회 반복되고 격리할 수 없음
- 작업 범위를 materially 확대할 새 권한이 필요함

단순히 작업량이 많거나 일부 자료가 미정이라는 이유로 중단하지 않는다.

## 11. 최종 전환

최종 품질 게이트가 2개 연속 배치에서 통과하면 자동 반복을 멈추고 `FINAL_GATE_PENDING`으로 기록한다. 이때 최종 병합은 실행하지 않고 사용자에게 다음만 보고한다.

- 통과한 배치와 검증 근거
- 최종 병합 후보 산출물
- 남은 HOLD·위험
- 병합 시 변경될 파일
- 사용자 승인 필요 사항
