# Brand Design Pipeline

## 시작

1. `../../00-작업상태.md`와 `../../01-통합-실행.md`를 읽는다.
2. `../../02-입력자료-계약.md`로 필수 입력과 승인 상태를 검사한다.
3. `../../WORKFLOW-STATE.md`와 `../../06-자율-연속실행.md`를 읽는다.
4. 실행할 배치와 목표 공백을 명시한다.
5. 기존 결과를 덮어쓰지 않고 회차 또는 작업 위치에 생성한다.

## 실행

`SOURCE → FINDING → CLIENT → REQ → PAGE → FLOW → SCREEN → STORYBOARD` 순서를 지킨다. 각 단계는 자신의 출력 범위를 넘지 않는다.

- Client 생성에는 기존 `virtual-client-builder`를 적용한다.
- 사이트 구조에는 기존 `site-structure-designer`를 적용한다.
- 나머지 단계는 `references/output-contracts.md`의 계약을 따른다.
- 각 단계 종료 후 `../../05-산출물-검증체크리스트.md`의 관련 절을 검사한다.
- 중요 오류가 있으면 다음 단계로 넘어가지 않고 `REVISION_REQUIRED`로 기록한다.
- 최종 병합 전에는 자율 연속 실행 상태 머신에 따라 다음 배치를 선택하고, 내부 반려 시 수정·재검증한다.

## 반복

새 Client는 기존 집합에 없는 문제·행동·판단 기준·충돌·예외를 추가해야 한다. 수량 자체를 성과로 간주하지 않는다. 배치 결과는 KEEP·MERGE·REVISE·HOLD·EXCLUDE로 분류하고 다음 배치의 공백을 정한다.

## 최종 병합 차단

최소 2개 연속 배치가 품질 게이트를 통과하지 않았거나 사용자 승인이 없으면 최종 병합을 실행하지 않는다. 조건을 충족하면 `../../04-최종-병합규칙.md`를 읽고 최종 전환 승인만 요청한다.
