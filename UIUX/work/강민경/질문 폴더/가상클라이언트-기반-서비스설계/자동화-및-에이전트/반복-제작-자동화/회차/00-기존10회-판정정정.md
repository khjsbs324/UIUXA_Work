# 기존 10회 판정 정정

정정 상태: `PREVIOUS_PASS_INVALIDATED`

## 정정 이유

기존 01~10회는 각 품질 축의 점검 항목을 빠르게 정리했으나 다음 증거가 부족했다.

- 원본 자료의 회차별 재검토 기록
- 실제 독립 대안 산출물
- 대안 간 Page·Flow·Screen 수준 비교
- 15명 Client별 과업 실행 결과
- 실패 사례와 수정 전후 차이
- 브라우저 렌더링·키보드·반응형 검증
- 실제 상품 콘텐츠·공식 자료 검증

따라서 기존 `10/10 INTERNAL_PASS`, `FINAL_GATE_STREAK=10`, `USER_APPROVAL_PENDING`은 품질 결론으로 사용할 수 없다.

## 유효하게 남는 것

- 검사해야 할 품질 축 목록
- 자동화 상태 구조
- Client·REQ·Page·상품 ID 초안
- HOLD와 위험 후보

## 무효화되는 것

- 최종 병합 준비 완료 판정
- Critical·High 오류 0이라는 품질 결론
- 심층 반복 10회 완료라는 표현

## 새 심층 회차 합격 조건

각 회차는 원본 입력, 가설, 실제 대안, Client 시나리오, 실패, 수정, 재검증, 남은 위험을 모두 포함해야 한다. 하나라도 없으면 `INTERNAL_PASS`를 사용할 수 없다.
