# 브랜드 설계 반복 제작 통합 실행

## 목적

승인된 근거에서 가상 클라이언트, 요구사항, 사이트 구조, 서비스 흐름, 화면설계서, 스토리보드를 배치 단위로 반복 생산한다. 반복 결과가 충분히 성숙하기 전에는 최종 병합·Figma·포트폴리오 확정 단계로 이동하지 않는다.

최종 병합 전 연속 실행·내부 반려·수정·재검증은 `06-자율-연속실행.md`를 따른다.
단계별 필수 출력과 차단 조건은 `08-단계별-자동실행-계약.md`를 따른다.

## 실행 순서

```text
입력 검증
→ 가상 클라이언트 확장
→ 요구사항 구조화
→ 사이트맵 후보
→ 서비스 흐름 후보
→ 화면설계서 후보
→ 스토리보드 후보
→ 배치 검증
→ 중간 병합
→ 품질 게이트
→ 반복 또는 최종 병합 후보 등록
```

## 단계 게이트

| 단계 | 시작 조건 | 종료 결과 | 차단 조건 |
|---|---|---|---|
| 입력 검증 | 원본·승인 결과 존재 | 입력 매트릭스 | 출처·승인·ID 누락 |
| 클라이언트 확장 | 검증된 사용자 문제 | 독립 후보군 | 근거 없는 설정·중복 |
| 요구 구조화 | Client 상태 분리 | 요구 등록부 | Client→REQ 추적 실패 |
| 사이트맵 | 승인·조건부 요구 | Page 계층 후보 | 고립 Page·근거 없는 메뉴 |
| 서비스 흐름 | Page와 과업 존재 | 정상·예외 흐름 | 시작·종료·상태 누락 |
| 화면설계서 | Page·Flow 연결 | 화면·상태 명세 | ID·콘텐츠·기능 불일치 |
| 스토리보드 | 화면·카피·정책 존재 | 페이지 후보 | 근거 없는 UI·카피 |
| 배치 검증 | 단계 결과 모두 존재 | 검증 보고 | 중요 오류·추적 단절 |
| 중간 병합 | 배치 검증 통과 | 통합 후보 | 충돌 은폐·HOLD 자동 채택 |
| 최종 전환 | 품질 게이트 반복 통과 | 최종 병합 승인 요청 | 한 번의 우연한 통과 |

## 실행 배치

- `BATCH-BASE`: 기존 핵심 가상 클라이언트 7명 재검증
- `BATCH-EXPAND-01`: 근거 공백을 채우는 신규 후보 5~8명
- `BATCH-EXPAND-02`: 구매·상품·카테고리·브랜드 경험 후보 5~8명
- `BATCH-EDGE`: 접근성·중단·오류·저연결성·다기기 예외 검증군
- 이후 배치는 앞선 결과의 미충족 축이 있을 때만 추가한다.

클라이언트 수를 목표로 삼지 않는다. 새 후보가 독립 문제·행동·판단 기준·충돌·예외를 추가하지 않으면 병합 또는 제외한다.

## 상태

```text
NOT_STARTED
INPUT_READY
RUNNING
VALIDATION_FAILED
REVISION_REQUIRED
BATCH_VALIDATED
MERGE_CANDIDATE
FINAL_GATE_PENDING
USER_APPROVAL_PENDING
```

## 재실행

실패한 단계부터 재개하되 상위 입력이 바뀌면 하위 결과를 `STALE_CANDIDATE`로 표시한다. 기존 결과는 삭제하지 않고 `보관/이전-결과` 또는 `회차`에 보존한다.

## 최종 전환 조건

아래 조건이 최소 2개 연속 배치에서 유지될 때만 사용자에게 최종 병합 전환을 제안한다.

1. 핵심 요구 추적률 100%
2. Page·Flow·Screen ID 불일치 0건
3. 근거 없는 확정 문장 0건
4. 중요 충돌 미처리 0건
5. 대표 3페이지의 목적·콘텐츠·행동·브랜드 서사가 명확함
6. 상품·패키지 최소 15개가 카테고리 전략과 연결됨
7. 접근성·오류·빈 상태·복귀 상태가 설계됨
8. 직전 배치 대비 새 중요 오류가 증가하지 않음
9. 결과가 단순히 많지 않고 최종 포트폴리오 서사로 압축 가능함
