# VC-50 아인 — 서비스 흐름도 v1

상태: `DRAFT_CONTINUOUS_RUN`

## 1. 클라이언트 맥락

- 상황: 같은 제품이 다시 시작, Analog, 선물 등 여러 위치에 나타나 중복 제품인지 다른 구성인지 헷갈린다.
- 목표: 카테고리 기준과 다중 소속 이유를 이해하고 같은 제품을 중복 후보로 세지 않는다.
- 핵심 과업: 카테고리 정의 → 제품 소속 → 다른 분류 경로 → 동일 Product 확인.
- 행동 흐름: 카테고리 목록 → 카드 → 다른 분류에서도 보기 → 동일 ID → 원래 위치.
- 요구: 분류 기준 설명, 동일 Product 유지, 주·보조 소속 구분, 중복 수량 제거.
- 성공 조건: 같은 제품과 다른 변형을 구분하고 현재 카테고리 포함 이유를 설명한다.
- 실패 조건: 이름·이미지만 바꿔 중복 제품을 새 후보로 계산한다.
- 연결 제품: `PROD-030`, `PROD-060`, `PROD-100`.

## 2. 독립 서비스 흐름

    flowchart TD
    A[카테고리 목록 진입] --> B[카테고리 기준 설명 확인]
    B --> C[제품 카드와 Product ID 확인]
    C --> D{다른 분류에서도 보기}
    D --> E[동일 Product ID의 다른 소속 표시]
    E --> F{동일 제품인가, 변형인가?}
    F -- 동일 --> G[중복 수량 제거·원래 카테고리 복귀]
    F -- 변형 --> H[구성·차이 근거 비교]
    H --> I[후보 유지 또는 보류]
    G --> J[현재 카테고리 포함 이유 확인]
    I --> J
    J --> K[선택·보류·다른 카테고리 탐색]

## 3. 단계별 상세

| 단계 | 사용자 행동 | 화면 역할 | 시스템 응답·분기 |
|---|---|---|---|
| 1 | 카테고리 목록 탐색 | 카테고리 페이지 | 주 소속과 카테고리 정의 표시 |
| 2 | 제품 카드 확인 | 제품 카드 | 제품명·Product ID·현재 소속 표시 |
| 3 | 분류 기준 이해 | 기준 설명 | 다중 소속 이유와 주·보조 소속 구분 |
| 4 | 다른 분류로 이동 | 교차 탐색 | 동일 Product ID를 유지해 중복 생성 방지 |
| 5 | 동일 제품·변형 판단 | 비교 영역 | 구성 차이와 확인되지 않은 정보 구분 |
| 6 | 복귀·선택·보류 | 원래 카테고리 | 현재 위치·필터·판단 맥락 보존 |

## 4. 예외·상태

- Product ID 누락: 이름이나 이미지만으로 동일 제품이라고 확정하지 않고 확인 필요 상태를 표시한다.
- 카테고리 기준 불명확: 기준 설명과 주·보조 소속을 먼저 보여주고 탐색을 계속한다.
- 결과 없음: 카테고리 초기화·전체 후보 보기·보류를 제공한다.
- 중단·복귀: 원래 카테고리와 카드 위치를 보존한다.
- 실패 방지: 이름·이미지만 바꿔 중복 제품을 새 후보로 계산하지 않는다.

## 5. 연결 검증

- V5 카테고리 경계 요구를 카테고리 기준, 교차 소속, 동일 ID 확인 단계에 반영했다.
- 연결 제품은 `PROD-030`, `PROD-060`, `PROD-100`이며 임의 제품을 추가하지 않는다.
- 이 문서는 VC-50 독립 문서이며 VC-51 이후 최종 검토 때 통합한다.
