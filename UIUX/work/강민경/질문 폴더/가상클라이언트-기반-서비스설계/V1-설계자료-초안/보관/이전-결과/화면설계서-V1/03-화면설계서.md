# 화면설계서

## 1. 문서 목적

사이트-구조맵과 서비스 흐름을 화면 단위 요구로 전환한다. 이 문서는 레이아웃의 기능적 구역과 정보 우선순위를 정의하며 색상·정확한 좌표·최종 컴포넌트·와이어프레임은 확정하지 않는다.

## 2. 공통 화면 구조

| 영역 | 설계 항목 | 원칙 |

## 4. 핵심 화면 상세

### SCR-001 / 홈

- 우선순위 1: “무엇을 제공하는 기록 브랜드인가”
- 우선순위 2: Digital/Analog가 서로 다른 독립 선택지임을 설명
- 우선순위 3: `기록 방식 비교`, `기록 스타일 찾기`, 각 트랙 직접 진입
- 금지: 감성 이미지로 핵심 이용 방식이 가려짐, 두 트랙 강제 연결

### SCR-003 / 기록 스타일 찾기

- 입력: 기록 목적·기록량·시간 관리 필요·물성 선호 등 승인 근거 기반 질문
- 출력: 추천 방식, 추천 이유, 맞지 않을 수 있는 조건
- 행동: Digital/Analog 중 선택하거나 비교로 돌아가기
- 금지: 진단 결과 강제, 근거 없는 성격 유형·직업·구매력 추정

### SCR-005 / 일정 관리

- 정보 위계: 오늘 시간대 → 이후 일정 → 중요 일정 → 상기 조건
- 기능: 시간 개요·세부 전환, 중요 일정 상기 제어 후보
- 상태: FUNCTION-006 `CONDITIONAL`; 외부 연동 `HOLD`
- 예외: 상기 시점·빈도·채널·끄기 조건이 없으면 확정 기능으로 표기하지 않음

### SCR-007 / 기록 구조 선택

- 비교 기준: 목적, 예상 기록량, 장문 여부, 구조 유연성
- 기능: 구조 유형 비교·선택
- 연결: 장문 조건은 SCR-008, 제품 적용은 SCR-009·011

### SCR-010 / 제품 상세

- 필수: 소재, 표면/촉감 설명, 내구성, 내부 구성, 기록 구조 호환성
- 보조: 감성 이미지·사용 예시
- 신뢰: 출처·검증 상태를 해당 정보 옆에 표시
- 금지: 공개 설명만으로 실제 촉감·필기감을 확정

### SCR-011 / 소재·구성 비교

- 비교 열: 제품/구성, 소재, 장문 적합, 내구성 정보, 내부 구조, 확인 필요
- 기능: 비교 대상 확인과 상세 왕복
- 성공: VC-001이 자기 조건에 맞는 이유/맞지 않는 이유를 판단

## 5. 공통 상태

- 기본: 정보 확인 가능
- Empty: 자료 부족 이유와 다음 확인 방법 제공
- Conditional: 조건부 기능의 해제 조건 표시
- Hold: 활성 UI에서 제공하지 않음
- Unverified: 사실·추정·검증 필요를 분리
- Error: 사용자를 비난하지 않고 복구 경로 제공

## 6. 반응형·접근성 전달

- 모바일에서도 동일한 정보구조와 Page ID 유지
- 1Depth 5개를 한 번에 과밀 노출하지 않도록 탐색 패턴은 후속 UI에서 검토
- 표 비교는 모바일에서 항목 단위 순차 비교가 가능해야 함
- 현재 위치, 상위 Page 복귀, 명확한 레이블을 유지
- 구체적 접근성 표준과 수치는 후속 검증 항목

## 7. HOLD

검색, 로그인·마이페이지, 커뮤니티, 기록 아카이브, 외부 일정 연동, 실물 커스텀 제작·배송과 독립 Shop 화면은 만들지 않는다.
