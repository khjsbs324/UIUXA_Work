# 제품콘텐츠 도출결과 V1

단계: `03-제품콘텐츠`  
버전: `V1`  
상태: `FIRST_CANDIDATE_SET_GENERATED / EXPANSION_IN_PROGRESS`  
목적: Client·REQ를 제품 후보·제품군·페이지 콘텐츠와 연결하기 위한 실제 결과 문서.

## 0. 입력 및 범위

- Client 입력: `01-클라이언트생성-출력물`의 Client V3 파일 51개.
- 요구사항 입력: `02-요구사항분석-출력물`의 REQ-001~REQ-051.
- 제품 후보 목표: 전체 최소 100개 이상. 제품군별 2~3개 이상을 기본으로 하며, 상세하게 구축 가능한 범위에서 약 100~200개 이상으로 확장한다. 200개는 확정 숫자가 아니라 충분한 후보를 확보하기 위한 참고 목표다.
- 메인 대표 제품 목표: 최소 15개.
- 적용 페이지: `PAGE-001` 메인 랜딩, `PAGE-020` 브랜드 소개, `PAGE-021` 카테고리 서브.
- 제품 성격: 실제 판매 제품이 아닌 포트폴리오용 가상 제품 후보.
- 현재 단계: 제품 데이터 생성 전 구조·필드·검수 기준 확정.

## 1. 제품 생성 원칙

- 제품마다 고유 `Product ID`를 부여한다.
- 실제 판매·가격·재고·배송·후기·인증·내구 연수는 근거 없이 확정하지 않는다.
- 제품명·브랜드명·사양이 미정이면 `가칭`, `가상 제품`, `검증 필요`를 표시한다.
- Client 1명당 제품 1개로 제한하지 않고 핵심·보조·대체·보류 제품을 복수 연결한다.
- 동일 제품의 변형·리필·번들·구성 차이는 중복 집계하지 않고 관계를 기록한다.
- 제품 후보 수량과 함께 내용의 구체성·근거·브랜드 적합성을 검증한다.

## 9. Client 제품 연결 후 버전 규칙

- 현재 Client V3는 원문 복구·상세 보강본으로 보존한다.
- 제품이 연결되면 Client 파일의 다음 버전으로 추가한다.
- 제품 연결 전 상황·목표·과업·판단 기준은 삭제하지 않는다.
- 제품 연결 후 추가할 항목: 연결 제품 목록, 제품별 사용 시나리오, 제품으로 해결되지 않는 요구, 제품이 만든 부담, Vn 대비 변경 이력.
- 제품 연결로 새로운 과업이 발견될 때만 추가 Client를 생성한다.
- 제품 연결 Client는 기존 파일을 덮어쓰지 않고 다음 `Vn`으로 저장한다.
