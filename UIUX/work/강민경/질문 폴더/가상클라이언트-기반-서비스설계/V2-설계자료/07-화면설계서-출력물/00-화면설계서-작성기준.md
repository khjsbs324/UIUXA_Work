# 07 화면설계서 출력물 작성 기준

## 목적

서비스 흐름도 VC-01~VC-51을 실제 화면 단위 설계로 전개한다. 클라이언트 1명당 화면설계서 1개를 만들고, 각 화면의 목적·콘텐츠·기능·상태·반응형·접근성을 기록한다.

## 입력

- `06-서비스 흐름도-출력물/VC-XX-*-서비스-흐름도.md`
- `05-final-design-output/VC-XX-*-사이트구조맵-final-design-v1.md`
- 해당 클라이언트의 V4/V5 요구사항·제품 연결

## 파일 규칙

`VC-XX-이름-화면설계서.md`

## 화면별 필수 항목

- Screen ID와 화면 목적
- 진입 조건·이전 화면·다음 화면
- 핵심 콘텐츠와 정보 우선순위
- 사용자 행동·CTA·입력·선택
- 정상·빈 결과·오류·HOLD·저장·중단 상태
- Desktop·Mobile 반응형 규칙
- 키보드·스크린리더·대체 조작·오류 안내
- 연결 REQ·PAGE·Product·서비스 흐름 단계

## 제작 원칙

- 흐름의 모든 주요 분기와 상태를 화면 단위로 변환한다.
- 클라이언트별 핵심 과업을 공통 화면 템플릿으로 대체하지 않는다.
- 화면설계서는 와이어프레임과 스토리보드의 직접 입력으로 사용할 수 있어야 한다.
- 51개 개별 문서 작성 후 전체 누락·중복·페이지 연결을 검토한다.
