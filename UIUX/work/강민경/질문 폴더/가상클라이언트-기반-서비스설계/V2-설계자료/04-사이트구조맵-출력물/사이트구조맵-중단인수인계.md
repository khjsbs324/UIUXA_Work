# 사이트구조맵-중단인수인계

## 1. 현재 단계

- 현재 단계: 사이트구조맵·사이트맵 생성·검증
- 작업 상태: Client V5 보강 완료 후 사이트구조맵 상세형 V2 확장 중
- 대표 제품 15개 선정: 미실행. 사용자 지시로 보류
- 제품 후보 기준: 제품군별 2~3개 이상, 총 100개 이상. 200개는 고정 확정 수가 아님
- Figma: 아직 진행하지 않음

## 2. 사이트구조맵 단계의 최종 목적

통합 분석 결과를 참고하되 개별 가상 Client를 최종 기준으로 삼아, Client 요구사항을 사이트의 메뉴·콘텐츠·기능으로 변환한다. 메인 랜딩페이지, 카테고리 서브페이지, 브랜드 소개페이지와 제품·브랜드 콘텐츠의 연결 관계를 여러 구조안으로 만들고 검증한다.

## 3. 입력 자료

1. Client 입력: `01-클라이언트생성-출력물/클라이언트-출력물-V5-사이트구조맵보강`
2. 요구사항 입력: `02-요구사항분석-출력물`
3. 제품 입력: `03-제품콘텐츠-출력물/제품콘텐츠-도출결과-V2.md`
4. 사이트구조맵 작성 기준: `04-사이트구조맵-출력물/사이트구조맵-작성기준/사이트구조맵-사이트맵-생성검증기준-V2.md`
5. 브랜드·공유자료: 기존 `V1-기존-설계자료` 및 인수인계 자료에서 근거를 확인

## 4. Client 보강 상태

- V2 Client 요구사항 파일: 51개
- V3 Client 복구 파일: 32개
- V4 제품 연결 파일: 51개
- V5 사이트구조맵 보강 파일: 51개
- V5 보강 항목: 페이지 우선순위, 요구→메뉴·콘텐츠·기능 변환, 상태·예외 행동, 제품 배치, 브랜드 접점, Client 고유 차별점
- V2·V3·V4 원본은 보존

## 5. 제품 연결 기준

- Client V4의 `제품 연결 결과 V4`를 기준으로 한다.
- 제품 ID는 임의로 변경하지 않는다.
- 제품 연결 원본: `03-제품콘텐츠-출력물/제품콘텐츠-도출결과-V2.md`
- 연결 추적 순서: Client V4 제품 목록 → Product ID → 제품 결과 V2의 동일 행 → 연결 REQ·PAGE 확인
- 제품은 판매 확정·가격·재고·최종 사양을 의미하지 않는다.
- 대표 15개는 이 단계에서 선정하지 않는다.
- 직접 연결이 확인되지 않은 Client VC-16·VC-19·VC-40·VC-42는 제품을 임의로 추가하지 않는다.

## 6. 현재 사이트구조맵 출력물

### 완료된 Client

- VC-01 은재: V1 시범본 및 상세형 V2 완료
- VC-02 지안: V1 시범본 및 상세형 V2 완료
- VC-03 하람: V1 시범본 및 상세형 V2 완료
- VC-04 소담: 상세형 V2 완료

### 각 Client 출력 구성

- A안·B안·C안
- 안별 `사이트맵.md`
- 안별 `사이트맵.mmd`
- 안별 `사이트맵.svg`
- Client 1명당 9개 파일

### 출력 폴더

`04-사이트구조맵-출력물/VC-번호-Client명-사이트구조맵-V2`

## 7. 상세형 사이트구조맵에 반드시 포함할 항목

1. Client 기본 정보
2. 상황·목표·과업·행동 흐름
3. 불편·문제·판단 기준
4. 성공·실패 조건
5. 요구사항·REQ 추적
6. 연결 제품 ID·제품군·배치 페이지
7. 요구→메뉴·콘텐츠·기능 매핑표
8. 전역 내비게이션
9. 1·2·3차 계층형 사이트맵
10. 페이지별 목적·콘텐츠·기능·사용자 행동·진입·이탈
11. 메인 랜딩페이지 구조
12. 카테고리 서브페이지 구조
13. 브랜드 소개페이지 구조
14. 공통 영역
15. 비회원·탐색·비교·보류·진행·저장·복귀 상태
16. 결과 없음·오류·취소·재시도·복귀 예외
17. 접근성·반응형·저연결성 고려
18. 정상·분기·예외 사용자 흐름
19. A·B·C 구조안 간 전략 차이
20. 누락·중복·끊긴 링크·가정 검증

## 8. A·B·C 구조안 구분 기준

- A안: Client 핵심 과업 직결형
- B안: 사용 상황·콘텐츠 선행형
- C안: 제품군·포트폴리오 허브형

단순히 메뉴 순서만 바꾸지 말고 진입점, 정보 우선순위, 제품 배치, 브랜드 콘텐츠 노출 방식이 달라야 한다.

## 9. 다음 재개 작업

1. VC-05 태오부터 상세형 V2 생성
2. V5 Client에서 기본 정보·REQ·제품 연결을 확인
3. A·B·C 구조안 작성
4. 각 안의 상세 MD·MMD·SVG 생성
5. Client당 9개 파일 수와 구조 일치 검증
6. VC-06부터 VC-51까지 같은 순서로 확장
7. 직접 제품 연결이 없는 VC-16·VC-19·VC-40·VC-42는 별도 검토 표시
8. 전체 Client 사이트구조맵 완료 후 구조안 검증·병합

## 10. 아직 하지 않은 작업

- 사이트구조맵 전체 Client 완료
- 사이트맵 후보 병합
- 최종 사이트맵 1안 확정
- 서비스 흐름도
- 화면설계서
- 스토리보드
- 대표 제품 15개 선정
- 최종 와이어프레임
- Figma

## 11. 파일 관리 규칙

- 기존 파일을 삭제하거나 덮어쓰지 않는다.
- 단계별 출력물은 해당 단계 폴더에 저장한다.
- 버전은 V1·V2·V3 방식으로 관리하며 날짜를 파일명에 넣지 않는다.
- Client를 합치지 않는다.
- 실제 결과물 없이 MD 기준 파일만 늘리지 않는다.
- 모든 결과물은 Client·REQ·Product ID를 추적할 수 있어야 한다.
