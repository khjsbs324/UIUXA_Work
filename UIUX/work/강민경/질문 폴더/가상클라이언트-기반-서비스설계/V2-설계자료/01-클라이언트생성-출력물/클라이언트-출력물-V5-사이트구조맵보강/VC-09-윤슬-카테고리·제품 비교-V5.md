# VC-09 윤슬 — 카테고리·제품 비교

단계: `01-클라이언트생성`  
버전: `V5`
파일 유형: `Client 개별 상세 결과`  
현재 판정: `KEEP / STRATEGIC_VALIDATION`
Client 역할: 카테고리·제품 비교

## 1. 가상 클라이언트 기본 정보

- 프로젝트 중심 주제: 통합 다이어리 브랜드 웹사이트의 브랜드·제품 탐색 경험.
- 제작 목적: 목적·분량·형태·휴대성으로 후보군을 좁히고 같은 속성으로 비교한다.
- 가상 Client 이름: 윤슬 (식별용 가상 이름이며 실제 조사 참여자 이름이 아님)
- 제공 자료·근거: 제품 15개 이상 탐색과 카테고리 공백 검증.
- 매체: 반응형 웹(Desktop·Mobile); 최종 산출물은 메인 랜딩·카테고리 서브·브랜드 소개로 연결.
- 우선순위: 높음; 후속 요구사항 분석에서 영향도 재평가
- 필요한 정보·기능: 명확한 카테고리, 핵심·상세 필터 분리, 비교 기준, Empty 복구, 판매 순위 비의존.

## 2. Client 요청사항

1. 요청: 명확한 카테고리, 핵심·상세 필터 분리, 비교 기준, Empty 복구, 판매 순위 비의존.
2. 중요도: 높음
3. 관련 자료·추적: `ER-001·004·005`, PAGE-001·007·008·014·021 후보.
4. 필요한 기능·과업: 카테고리 진입 → 핵심 필터 → 결과 → 최대 비교 후보 선택 → 근거 확인.
5. 성공 기준: 짧은 단계 안에 후보군을 좁히고 선택 또는 보류 이유를 확인한다.
6. 실패·금지 기준: 가격·판매량·베스트 배지로 적합성을 대신한다.
7. 누락·중복 점검: 동일 요구는 후속 요구사항 분석에서 비교하되, 이 파일의 Client 관점 자체는 병합하지 않음.

## 2-2. Client별 후속 후보 산출 요구

- 사이트 구조맵 후보: 이 Client의 요구를 반영한 복수 구조 방향을 후속 단계에서 생성합니다.

- 서비스 흐름도 후보: 정상·분기·오류·취소·복귀를 포함한 복수 흐름 방향을 후속 단계에서 생성합니다.

- 화면설계서 후보: 화면 목적·콘텐츠·기능·상태·반응형·접근성을 포함한 복수 방향을 후속 단계에서 생성합니다.

- 제품 후보: 이 Client에 연결되는 복수 제품을 제품 단계에서 생성하고 Product ID를 부여합니다.

- 현재 상태: Client 분석 단계에서는 후보 산출 기준을 확정하며, 실제 구조맵·흐름도·화면설계서·제품 파일은 해당 단계 출력물에서 생성합니다.


- 현재 판정: `KEEP / STRATEGIC_VALIDATION`
- 근거: 제품 15개 이상 탐색과 카테고리 공백 검증.
- 상황: 기록 목적은 알지만 많은 제품 중 감성 이미지가 아니라 자신의 조건에 맞는 차이를 빠르게 찾고 싶다.

- 핵심 과업: 카테고리 진입 → 핵심 필터 → 결과 → 최대 비교 후보 선택 → 근거 확인.
- 행동 흐름: 전체 탐색 → 조건 적용 → 결과 없음 복구 또는 후보 비교 → 상세 왕복 → 선택·보류.
- 불편·문제: 제품명·이미지·베스트 배지만 많고 선택 근거와 분류 기준이 보이지 않는다.
- 판단 기준: 카테고리 예측 가능성, 공통 비교 속성, 필터 해제, 결과 수, 상세 복귀 맥락.
- 요구: 명확한 카테고리, 핵심·상세 필터 분리, 비교 기준, Empty 복구, 판매 순위 비의존.
- 성공 조건: 짧은 단계 안에 후보군을 좁히고 선택 또는 보류 이유를 확인한다.
- 실패 조건: 가격·판매량·베스트 배지로 적합성을 대신한다.
- 제품 요구 방향: 목적별 기록 키트, 분량별 노트군, 휴대형 기록 세트, Analog·Digital 비교 패키지, 장기 보관 제품군.
- 브랜드 접점: 제품보다 선택 근거 우선, 카테고리의 정직성, Analog·Digital 균형.

- 회원 상태가 원자료에 없으면 구조맵에서 '가정'으로 표시합니다.

### 10-4. 제품 배치 입력

- 제품 연결 추적 원본: [제품콘텐츠-도출결과-V2.md](../../03-제품콘텐츠-출력물/제품콘텐츠-도출결과-V2.md)
- Client 연결 기준: 이 파일의 V4 제품 연결 목록 → 제품 결과 V2의 동일 Product ID 행 → 연결 REQ·PAGE 확인
- 사이트구조맵 전달 방식: Product ID를 임의로 재명명하지 않고, 제품군·사용 상황·Client 과업과 함께 페이지 배치 후보로 전달

- 연결 제품 ID: PROD-004·PROD-012·PROD-030·PROD-034·PROD-065
- 배치 후보: 메인 제품 레일, 카테고리 제품군, 브랜드 포트폴리오, 제품 상세·비교
- 제품이 해결하는 과업: V4의 Client 과업·불편·판단 기준과 연결하여 구조맵에서 확정합니다.
- 함께 제공할 콘텐츠: 사용 상황, 선택 근거, 브랜드 제작·기록 맥락
- 대표 15개 선정: **미실행 / 사용자 지시로 보류**

### 10-5. 브랜드 접점

- 브랜드 방향은 Client 요구를 설명하는 콘텐츠와 제품군의 배치 근거로 연결합니다.
- 제작 과정·재료·기록 철학은 Client가 신뢰를 판단하는 관련 페이지에 배치합니다.
- 제품은 판매 목록만이 아니라 브랜드 포트폴리오와 사용 맥락을 보여주는 결과물로 설명합니다.

### 10-6. Client 고유 차별점

- 공통 요구: 다른 Client와 겹치는 요구는 구조맵 검증표에서 중복으로 표시합니다.
- 고유 요구: 이 Client의 상황·불편·판단 기준을 핵심 페이지와 연결합니다.
- 유지해야 할 차별 요소: Client 이름과 V4에 기록된 핵심 과업·제품 연결을 임의로 병합하지 않습니다.
