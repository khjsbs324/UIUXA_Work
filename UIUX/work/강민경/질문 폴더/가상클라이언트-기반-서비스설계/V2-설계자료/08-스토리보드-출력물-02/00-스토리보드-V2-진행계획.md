# 스토리보드 재작업 진행계획

## 1. 이번 재작업의 원칙

- 기존 `08-스토리보드-출력물`은 수정하지 않고 보존한다.
- 이 폴더에서 스토리보드를 처음부터 다시 도출한다.
- SOAPHE 자료는 화면 명세의 표현 구조만 참고하고, 내용과 화면 구성은 현재 프로젝트 원자료에서 새로 도출한다.
- 51개 클라이언트를 한 번에 복제하지 않고 VC-01부터 VC-51까지 각각 원자료를 대조해 개별 작성한다.
- 공통 필드는 유지하되 화면 목적·콘텐츠·행동·분기·레이아웃·상태는 클라이언트별로 달라야 한다.
- SVG는 제작하지 않는다. MD 원본과 HTML 검토본을 제작한다.

## 2. 클라이언트별 입력 자료

각 VC를 작성할 때 다음 자료를 순서대로 대조한다.

1. `01-클라이언트생성-출력물`: 상황·목표·행동 특성
2. `02-요구사항분석-출력물`: 문제·요구·성공/실패 조건
3. `03-제품콘텐츠-출력물`: 연결 제품·콘텐츠·근거 상태
4. `04-사이트구조맵-출력물`: PAGE·섹션·진입/종료 구조
5. `06-서비스 흐름도-출력물`: 실제 행동 순서·분기·중단·복구
6. `07-화면설계서-출력물`: SCR별 목적·콘텐츠·UI·상태·검증
7. `04-기획/브랜드-기획/예시 참고자료/1차`: 명세 항목과 시각 구성 참고

## 3. 클라이언트별 산출물

### MD 원본

- 클라이언트 맥락과 핵심 여정
- 장면별 화면 목적
- 진입·종료 조건
- Visual Layout
- 실제 콘텐츠와 카피
- UI·인터랙션
- 데이터 정책
- 정상·로딩·빈 결과·오류·HOLD·완료 상태
- 반응형·접근성
- 사용자 행동·시스템 반응·분기·다음 화면
- REQ·PAGE·PRODUCT·SCR 추적
- 병합 시 보존해야 할 전용 규칙

### HTML 검토본

- 해당 클라이언트 전용 화면 보드
- 화면별 실제 콘텐츠·카피·컴포넌트 배치
- 장면 간 전환과 분기 표시
- 클라이언트 과업에 맞는 레이아웃
- 상태 전환 확인용 인터랙션
- MD·화면설계서·서비스 흐름도 연결

## 4. 진행 순서

1. 작성 기준과 검증 규칙 확정
2. VC-01 원자료 대조 및 개별 MD·HTML 작성
3. VC-01 내부 검증
4. VC-02부터 VC-51까지 동일한 검증 순서로 개별 작성
5. 각 클라이언트의 중복·누락·추적 오류 점검
6. 51개 전체 연결 검증
7. 메인·카테고리·브랜드 소개 페이지 스토리보드 복수안 도출
8. 병합 전 전체 검토본 작성

## 5. 중간 산출물 검증 기준

- 공통 템플릿 문구만 반복하지 않는다.
- 화면 수는 서비스 흐름과 화면설계서의 실제 단계에 맞춘다.
- 실제 제품·PAGE·REQ 근거가 없는 내용을 임의로 확정하지 않는다.
- 오류·빈 결과·HOLD·중단·재개가 최소 한 번 이상 검토된다.
- HTML에서 화면 목적과 다음 행동을 실제로 확인할 수 있다.
- 각 MD와 HTML은 같은 클라이언트의 원자료를 가리켜야 한다.
