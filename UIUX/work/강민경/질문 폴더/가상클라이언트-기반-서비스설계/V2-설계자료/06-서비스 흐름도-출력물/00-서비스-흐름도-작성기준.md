# 06 서비스 흐름도 출력물 작성 기준

## 목적

VC-08~VC-51의 클라이언트별 서비스 이용 흐름을 개별 문서로 제작한다.
기존 V1 서비스 흐름도의 공통 원칙과 표기법은 유지하되, 각 클라이언트의 목적·행동·제품·사이트 구조를 반영해 구체화한다.

## 제작 원칙

- 클라이언트 1명당 서비스 흐름도 1개를 독립적으로 작성한다.
- 여러 클라이언트의 흐름을 먼저 합쳐서 작성하지 않는다.
- 한 문서에 여러 클라이언트를 요약하거나 대표 흐름 하나로 대체하지 않는다.
- 각 문서는 해당 클라이언트의 상황, 과업, 판단, 페이지, 제품 연결, 예외 상태까지 구체적으로 포함해야 한다.
- VC-08~VC-51 개별 문서가 모두 작성·검토된 뒤에만 통합 흐름도와 추적표를 만든다.
- 통합본은 개별 문서의 대체물이 아니라 후속 집계·비교·누락 검증용이다.
- 이번 실행에서는 VC-08부터 VC-51까지 중간 검토 없이 연속 제작하고, VC-51 완료 후 최종 일괄 검토를 수행한다.

## 작업 대상

- 전체 클라이언트: VC-01~VC-51
- 기존 작성 완료: VC-01~VC-07
- 이번 작업 대상: VC-08~VC-51 (44명)

## 클라이언트 1명당 입력 자료

1. `01-클라이언트생성-출력물/클라이언트-출력물-V4-제품연결/VC-XX-*.md`
2. `01-클라이언트생성-출력물/클라이언트-출력물-V5-사이트구조맵보강/VC-XX-*.md`
3. `05-final-design-output/VC-XX-*-사이트구조맵-final-design-v1.md`
4. 필요 시 `02-요구사항분석-출력물`의 해당 VC 요구사항

## 파일 규칙

클라이언트마다 아래 형식으로 독립 파일을 만든다.

`VC-XX-이름-서비스-흐름도-v1.md`

## 문서 구성

### 1. 기본 정보

- Client ID / 이름
- 핵심 목적과 완료 정의
- 연결 제품 및 주요 페이지
- 근거 입력 파일

### 2. 핵심 과업

클라이언트가 서비스를 이용하는 대표 과업을 1~3개로 정의한다.
각 과업은 `시작 조건 → 행동 → 판단/분기 → 완료 상태`로 쓴다.

### 3. 서비스 흐름

Mermaid `flowchart TD`로 다음을 표시한다.

- 진입 페이지
- 질문·탐색·추천·선택·작성·저장 단계
- 페이지 이동과 되돌아가기
- 사용자가 선택을 수정하거나 중단하는 분기
- 완료·보류·재개 상태

흐름은 클라이언트의 대표 과업을 따라 충분한 단계 수로 작성한다. 공통 흐름을 복사한 뒤 이름만 바꾸지 말고, 클라이언트별 차이가 드러나는 분기와 판단 근거를 포함한다.

### 4. 단계별 상세 표

| 단계 | 사용자 목적/행동 | 화면·페이지 | 시스템 응답 | 다음 분기 | 연결 요구사항 |
|---|---|---|---|---|---|

### 5. 예외·상태 흐름

- 응답 부족 / 결과 없음
- 저장 중·저장 실패
- 오프라인·동기화 지연·충돌
- 중단 후 재개
- 취소·되돌리기·원본 보존

클라이언트에게 해당하지 않는 상태는 `해당 없음`으로 명시한다.

### 6. 제품·사이트 구조 연결 검증

- V4 제품 요구와 서비스 행동이 연결되는가
- V5/최종 사이트맵의 페이지 ID가 흐름에 등장하는가
- 핵심 요구사항 누락이 없는가
- 제품을 강제로 노출하지 않고 목적 중심으로 흐르는가

### 7. 완료 상태

문서 하단에 다음 메타데이터를 기록한다.

```text
STATUS=DRAFT
INPUT_V4=확인
INPUT_V5=확인
FINAL_SITE_MAP=확인
REQUIREMENT_TRACE=확인/보완 필요
REVIEW=NOT_STARTED
```

## 제작 순서

1. VC-08부터 번호순으로 입력 자료를 읽는다.
2. 핵심 목적·대표 과업·완료 상태를 먼저 추출한다.
3. V5/최종 사이트맵의 페이지와 행동을 매핑한다.
4. 해당 클라이언트의 독립 Mermaid 흐름을 작성한다.
5. 단계별 상세 표와 예외 상태를 작성한다.
6. 요구사항·제품·페이지 누락을 검사한다.
7. 개별 파일을 저장하고 다음 클라이언트로 이동한다.
8. VC-08~VC-51 전체 완료 후 최종 일괄 검토를 수행한다.
9. 최종 검토가 끝난 뒤에만 통합본을 별도로 만든다.

## 공통 원칙

추천은 강제가 아니라 근거가 보이는 수정 가능한 초안이어야 한다. 가장 작은 완료 단위를 허용하고, 중단은 실패가 아니라 보류·나누기·재개 가능한 상태로 처리한다.
