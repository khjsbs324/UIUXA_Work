# 산출물 검증 체크리스트

## 근거와 추적

- [ ] 모든 중요 결정이 Source 또는 승인된 상위 ID로 연결된다.
- [ ] FACT·INFERENCE·HYPOTHESIS·TBD·HOLD가 구분된다.
- [ ] 근거 없는 수치·정책·사용자 행동을 만들지 않았다.
- [ ] Client→REQ→PAGE→FLOW→SCREEN→STORYBOARD 연결이 끊기지 않는다.

## 가상 클라이언트

- [ ] 각 Client가 독립 문제·목표·행동·판단 기준 중 하나 이상을 추가한다.
- [ ] 80% 이상 유사한 후보는 병합 검토했다.
- [ ] 수를 늘리기 위한 장식 설정이 없다.
- [ ] 구매·탐색·브랜드 신뢰·재방문·접근성·예외 축을 검토했다.

## 구조·흐름·화면

- [ ] 고립 Page와 Dead end가 없다.
- [ ] 모든 Flow에 진입·행동·상태·종료·복귀가 있다.
- [ ] 오류·빈 상태·오프라인·취소·중단 후 복귀를 필요한 곳에 설계했다.
- [ ] Page·Flow·Screen ID와 명칭이 일치한다.
- [ ] 화면설계서가 콘텐츠·기능·상태·반응형·접근성을 포함한다.

## 브랜드와 콘텐츠

- [ ] 메인·카테고리·브랜드 소개의 역할이 겹치지 않는다.
- [ ] 브랜드 스토리가 기능 나열이 아니라 선택 이유를 설명한다.
- [ ] 상품·패키지 15개 이상이 카테고리와 사용자 요구에 연결된다.
- [ ] 카피의 말씨와 시각 원칙이 일관된다.

## 최종 전환

- [ ] 최소 2개 연속 배치에서 핵심 게이트를 통과했다.
- [ ] 중요 미처리 충돌이 0건이다.
- [ ] 최종 3페이지로 압축해도 핵심 서사가 유지된다.
- [ ] 사용자가 최종 병합 전환을 승인했다.
