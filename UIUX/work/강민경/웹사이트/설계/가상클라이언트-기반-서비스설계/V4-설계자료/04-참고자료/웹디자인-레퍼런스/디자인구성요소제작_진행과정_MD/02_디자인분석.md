## 0. 분석 원칙과 근거 수준

### 0.1 사용자 분류를 우선한다

`LOVE.md`의 세 그룹은 일반적인 품질 순위가 아니라 사용자가 직접 구분한 선호 맥락이다.

| 그룹 | 분석 의미 |
|---|---|
| 사용성·기능 측면 | 탐색, 정보 구조, 기능 연결, 이용 흐름에서 참고할 가치가 있음 |
| 디자인 측면 | 시각적 표현과 분위기에서 선호도가 높음 |
| 그럭저럭 괜찮은 정도·참고용 | 배제 대상이 아니라 비교 기준이며, 강한 선호와의 차이를 찾는 자료 |

따라서 기능 그룹의 시각 스타일을 자동으로 선호 디자인으로 간주하지 않고, 디자인 그룹의 구조를 자동으로 사용성 모범 사례로 간주하지 않는다.

### 0.2 근거 수준

| 구분 | 의미 |
|---|---|
| 확인 | 링크 원문 제목·설명·원본 캡처에 직접 나타나는 내용 |
| 시각 확인 | 제공된 화면 캡처에서 레이아웃·색·이미지·타입 구성 등을 확인 |
| 해석 | 사용자의 분류와 여러 사례의 반복을 바탕으로 도출한 선호 가설 |
| 확인 제한 | 정적 캡처나 프로젝트 소개만으로 실제 인터랙션·접근성·성능을 검증할 수 없음 |

### 0.3 자료 한계

- Behance 프로젝트는 실제 운영 사이트가 아닌 콘셉트·포트폴리오 사례가 포함된다.
- GDWEB 원본 자료는 긴 화면 캡처 중심이므로 Hover, Scroll Motion, Keyboard Interaction, Search 품질과 실제 반응형 동작은 확정할 수 없다.
- 프로젝트 작성자의 설명은 설계 의도를 확인하는 근거이지만 사용성 테스트 결과와 동일하지 않다.
- 링크가 특정 그룹에 포함됐다는 사실은 사용자의 선호 맥락을 보여주지만, 그 페이지의 모든 요소를 좋아한다는 뜻은 아니다.

## 2. 1차 분석 검증 결과

### 2.1 유지할 결론

다음 결론은 링크별 근거와 반복 패턴으로 지지된다.

1. 기능적으로는 정보량의 적음보다 **복잡성을 정리하는 방식**을 중요하게 본다.
2. Navigation, Category, Search, Filter, 비교, 저장, 상태 확인 같은 탐색·결정 기능에 관심이 있다.
3. 브랜드 이야기와 제품·서비스 기능이 하나의 흐름에서 연결되는 구성을 선호할 가능성이 높다.
4. 시각적으로는 Modern·Clean만으로 충분하지 않고 기억에 남는 Character가 필요하다.
5. Character의 수단은 Typography 하나가 아니라 Image, Graphic, Illustration, Editorial Layout, Color, Motion으로 다양하다.
6. 모든 정보를 같은 Card Grid에 넣기보다 Card와 Full-width·Editorial·Image Section을 혼합하는 경향이 강하다.
7. 특정 색 자체보다 Neutral Base와 선택적인 Accent, 또는 브랜드색의 집중 사용 방식이 반복된다.

### 2.2 정교화가 필요한 결론

1차 분석의 `디자인 선호군 = 강한 개성`, `참고용 = 일반적인 Modern Website` 구분은 방향상 유효하지만 모든 사례에 동일하게 적용되지는 않는다.

- 참고용의 헤리티디, 서울리빙디자인페어, 마켓형공연예술축제도 강한 색·그래픽·편집 구성을 사용한다.
- 따라서 강한 선호를 만드는 조건은 단순히 개성의 존재가 아니라 **개성의 종류, 강도, 정돈 수준, 브랜드 맥락과의 적합성**일 가능성이 높다.
- 참고용은 ‘개성이 없음’보다 ‘흥미로운 요소는 있으나 전체 조합이 최우선 취향은 아님’으로 해석하는 것이 안전하다.
- `Motion 선호` 역시 실제 동작을 모두 확인한 결과가 아니라 프로젝트 설명과 동적 매체 사용의 반복을 근거로 한 가설이다.

### 2.3 보완된 핵심 문장

> 사용자는 기능과 정보 구조가 명확한 웹사이트를 선호하며, 시각적으로는 정돈된 기반 위에서 사이트의 목적과 콘텐츠 맥락에 맞는 한두 가지 표현 요소가 분명하게 작동하는 디자인에 더 끌리는 경향이 있다. 개성은 많을수록 좋은 것이 아니라 정보 흐름을 방해하지 않고 일관된 Art Direction으로 통제될 때 선호도가 높아질 가능성이 크다.

### 3.1 기능 선호의 우선순위

1. 사용자가 현재 위치와 다음 행동을 이해할 수 있는 흐름
2. Category·Search·Filter를 통한 빠른 범위 축소
3. 비교와 선택 근거의 명시
4. 상태·저장·완료 여부의 지속적 피드백
5. 브랜드 설명과 기능을 분리하지 않는 문맥형 연결
6. 복잡한 정보를 Section·Module·Progressive Disclosure로 나누는 방식

### 3.2 기능 그룹에서 시각 스타일을 가져오는 규칙

- `기능 구조`는 적극 참고할 수 있다.
- `색상·서체·그래픽`은 디자인 선호 그룹의 반복 사례와 사용자의 분류가 함께 지지할 때만 수정 후보로 기록한다.
- 대형 기업·커머스의 기능 수를 복제하지 않고 현재 프로젝트의 실제 MVP에 필요한 흐름만 가져온다.

### 5.1 참고용 그룹의 정확한 의미

참고용 그룹에는 평범한 Modern Site뿐 아니라 강한 그래픽, Premium, Illustration, Editorial 사례도 포함된다. 그러므로 선호도를 가르는 요인은 다음 중 하나 또는 조합일 가능성이 높다.

- 표현 강도가 사용자에게 맞는가
- 정보 구조와 시각 표현이 자연스럽게 결합됐는가
- 브랜드 맥락에 표현 방식이 설득력 있게 맞는가
- 전체 페이지의 리듬이 일관되는가
- 특정 장면은 좋지만 전체 시스템으로는 과하거나 평범하지 않은가

이는 현재 링크만으로 확정할 수 없는 후속 비교 항목이다.

## 7. 사용자 취향의 재정의

### 7.1 신뢰도가 높은 판단

- 정보 구조는 명확하고 정돈되어야 한다.
- 복잡한 기능도 Category·Section·Module로 이해 가능하게 나눠야 한다.
- 사용자가 찾고, 비교하고, 선택하고, 상태를 확인하는 흐름이 중요하다.
- 시각 디자인은 안정적인 Template처럼 보이는 것만으로 부족하다.
- Typography, Image, Graphic, Layout, Motion 중 최소 하나가 기억점을 만들어야 한다.
- Card는 기능 단위에 사용하되 브랜드·콘텐츠 영역 전체를 지배하지 않아야 한다.
- 여백과 크기 대비로 콘텐츠 중요도를 표현하는 방식이 적합하다.

### 7.2 가능성이 높지만 초안 비교가 필요한 판단

- UI 본문용 Sans와 브랜드 Display용 Serif 또는 개성 있는 Display Type의 이중 체계
- Warm/Neutral Canvas에 절제된 Accent를 집중하는 Color 전략
- 기능 컴포넌트는 중간 Radius, Editorial·Image Section은 더 Sharp하거나 유기적인 Shape 사용
- Shadow보다 Border, 이미지, 면 색 차이, Layout으로 깊이를 만드는 방식
- Hero·전환 Section에 제한된 Scroll Motion 적용
- 한국적·자연적·서정적 표현을 직접적인 전통 장식보다 재료감·색·여백·사진으로 표현

### 7.3 아직 확정하면 안 되는 판단

- 특정 색 하나에 대한 절대 선호
- Serif 또는 Sans 하나만의 선호
- Rounded 또는 Sharp 중 하나의 전면 채택
- Photography·Illustration·Graphic 중 단일 최우선 매체
- Minimal 또는 Maximal 한쪽으로의 고정
- 강한 Motion의 전체 페이지 적용

## 8. 다음 단계 스타일 가이드 전체 수정에 전달할 기준

현재 분석은 스타일 가이드 수정안이 아니라 수정 작업의 입력 기준이다. 기존 Token·Semantic·Variant 구조는 유지하되 시각 언어를 다음 순서로 검토한다.

```text
사이트·서비스 목적과 사용자 흐름
        ↓
Foundation
├─ Color: Primitive → Semantic
├─ Typography
├─ Spacing & Sizing
└─ Radius & Effects
        ↓
Component
        ↓
State / Variant
        ↓
Web UI 초안
```

### 8.1 Color

- 특정 레퍼런스의 색을 복제하지 않는다.
- Neutral/Warm Base와 집중된 Brand Accent의 비율을 먼저 설계한다.
- Success·Warning·Danger 상태색은 브랜드색과 분리하고 의미를 유지한다.
- 이미지와 Graphic이 들어갈 경우 UI Color가 경쟁하지 않도록 면적을 조절한다.
- Light/Dark는 실제 Mode 값이 준비되지 않았다면 표지만으로 구현 완료를 주장하지 않는다.

### 8.2 Typography

- 기존 역할 기반 Scale은 유지할 가치가 있다.
- UI 가독성용 Sans와 브랜드·Hero용 Display Type을 분리하는 안을 비교한다.
- Display의 크기뿐 아니라 행 길이, 줄바꿈, Weight Contrast, 이미지와의 배치를 함께 설계한다.
- 작은 Label과 Caption은 장식보다 가독성을 우선한다.

### 8.3 Spacing & Layout

- 4/8px Token 체계는 유지하되 Section 여백은 더 큰 단위로 확장할 수 있다.
- 기능 영역은 밀도 있게, 브랜드·이미지·Editorial 영역은 호흡이 넓게 설계한다.
- 모든 Section을 동일한 Card Grid로 만들지 않는다.
- Full-width Image, Split Layout, Asymmetric Composition, Text-led Section을 목적에 따라 혼합한다.

### 8.4 Radius & Shape

- 하나의 Radius를 모든 요소에 반복하지 않는다.
- Button·Input·Quiz Option처럼 조작 요소는 일관성을 유지한다.
- Card·Image Frame·Editorial Section은 콘텐츠 성격에 따라 Radius 강도를 달리한다.
- Organic Shape는 브랜드 표현 영역에 제한하고 기능 상태의 인지를 방해하지 않게 한다.

### 8.5 Effects & Motion

- Shadow를 기본 강조 수단으로 사용하지 않는다.
- Border, Tint, Image, Scale, Overlap, Typography 대비로 Depth를 만든다.
- Motion은 등장, 상태 변화, 맥락 전환, 시선 유도처럼 목적이 있을 때만 사용한다.
- Reduced Motion과 Keyboard Focus에서 같은 정보와 행동을 제공한다.

### 8.6 Components

- Button·Badge·Progress·Question Number·Quiz Option·Timer의 상태 구조는 보존한다.
- 상태 이름과 실제 Token Binding이 미확인인 부분은 수정 전에 명세한다.
- Card 컴포넌트는 유지하되 웹페이지 전체를 Card만으로 구성하지 않는다.
- Brand 영역과 Functional UI 영역의 시각 자유도를 분리한다.
- 색만으로 Correct·Incorrect·Review를 전달하지 않도록 Icon·Label 보완안을 포함한다.

### 8.7 초안에서 비교해야 할 핵심 가설

1. Neutral/Warm Base + 절제된 Accent가 현재 Navy/Blue 중심보다 사용자의 시각 선호에 가까운가
2. Sans 단일 체계보다 Display/Editorial Type을 추가한 체계가 선호에 가까운가
3. 중간 Radius 기능 UI + 다양한 Editorial Shape 조합이 일관성을 유지하는가
4. Card 비중을 낮추고 큰 이미지·Typography Section을 넣었을 때 정보 이해가 유지되는가
5. Motion 없이도 구조가 이해되며 Motion이 추가될 때 경험이 실제로 개선되는가

## 9. 스타일 가이드 초안·최종안 비교 전략

과제 제출 조건상 초안과 최종안은 13장 모두 달라질 필요가 없고 최소 3장이 달라지면 된다. 다만 다음 단계의 ‘스타일 가이드 전체 수정’에서는 13장의 관계를 모두 검토하고, 초안 평가 후 최종안에서 차이를 가장 명확하게 보여줄 최소 3장을 선정한다.

우선 비교 후보:

1. `Foundations — Colors`: Neutral Base와 Accent 비율, 상태색 분리
2. `Foundations — Typography`: UI Type과 Display Type의 관계
3. `Components — Card`: Card 비중과 Editorial Surface 표현

대안 후보:

- `표지`: 전체 Art Direction 차이를 가장 빠르게 보여줌
- `Radius & Effects`: Shape와 Depth 전략 변화 제시
- `Button` 또는 `Quiz Option`: Foundation 변경이 상태 UI에 적용되는 방식 증명

최종 3장은 단순히 보기 좋은 페이지가 아니라 `Foundation 변경 → Component 반영 → Web UI 결과`가 설명되는 조합으로 선택한다.

## 10. 제출물과의 관계

과제 제출물은 다음 다섯 가지다.

1. 스타일 가이드 초안
2. 스타일 가이드 초안 기반 웹디자인 초안
3. 스타일 가이드 최종안
4. 웹디자인 최종
5. 디자인 기획 설명

본 `01.디자인분석.MD`는 아직 제출 파일 자체가 아니라 다음 제출물을 만드는 근거 문서다.

- 스타일 가이드 초안의 시각 방향 근거
- 초안 웹디자인 평가 기준
- 최종안의 수정 사유
- 디자인 기획 설명의 레퍼런스 분석 및 의사결정 과정
- 포트폴리오의 Research → Analysis → Draft → Evaluation → Final 과정

실제 제출물에 해당하는 파일을 제작하거나 확정할 시점에는 별도로 알리고, 사용자가 지정하는 `<제출파일>` 폴더에 요구된 이름으로 복사한다.

## 11. 최종 결론

1차 분석의 핵심인 `Modern + Clean + Visual Character`는 유지할 수 있다. 다만 이번 링크별 재검토를 통해 Visual Character는 단순히 강한 그래픽을 추가하는 것이 아니라 **기능·콘텐츠·브랜드 맥락에 맞춰 통제된 개성을 설계하는 것**으로 정교화된다.

다음 스타일 가이드 수정에서 지켜야 할 중심 원칙은 다음과 같다.

> 기능 영역은 빠르게 이해되고 예측 가능해야 한다. 브랜드 영역은 Typography·Image·Graphic·Layout 중 선택된 요소로 기억점을 만들어야 한다. 두 영역은 분리된 두 디자인이 아니라 공통 Color·Type·Spacing 규칙으로 연결되어야 한다.

따라서 기존 스타일 가이드의 안정적인 Token·Semantic·Variant 구조는 유지하고, Color 비율, Typography 역할, Section Layout, Shape 사용 범위, Card 비중, 이미지와 Motion의 역할을 전체 시스템 관점에서 다시 설계하는 것이 적절하다.
