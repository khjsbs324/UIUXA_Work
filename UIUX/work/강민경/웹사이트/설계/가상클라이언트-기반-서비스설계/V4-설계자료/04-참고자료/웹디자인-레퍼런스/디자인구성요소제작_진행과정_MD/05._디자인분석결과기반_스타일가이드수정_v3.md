## 1. 사용자 피드백 원문 해석

### 1.1 명시된 문제

1. Hero 제목 `기록은 남고, 방식은 달라져도 돼요.`의 마지막 `요.`가 별도 줄로 밀릴 수 있어 문장 리듬과 가독성이 불안정하다.
2. `하나만 남겨도 기록은 시작됩니다.` 등 다른 Section 제목도 줄바꿈이 다소 임의적이고 전체적으로 비슷한 문제가 있다.
3. 상단 Navigation이 일반적인 직선형 웹 Header보다 둥글고 떠 있는 앱 Bar처럼 보이길 원한다.
4. 현재 색상은 만족스럽지만 화면이 전반적으로 단조롭게 느껴진다.
5. `한 줄 시작하기`는 유지하되, 기존 작업물이 있는 사용자가 로그인하여 바로 작업으로 복귀할 수 있는 진입점이 필요하다.
6. Hero Visual의 메모장 표현은 방향은 좋지만 DAMORI의 중심 소재인 불렛저널과 쿠션 다이어리의 물성과 정체성을 충분히 보여주지 못한다.
7. 위 문제를 개별 수정으로 끝내지 않고 전체 화면에서 같은 유형의 문제를 찾아 개선하고 이후 검수까지 진행해야 한다.

### 1.2 피드백에서 도출되는 최종 방향

> 현재 Palette와 차분한 분위기는 유지하되, 제목의 언어 단위와 줄바꿈을 정밀하게 통제하고, Floating Navigation·쿠션 다이어리·불렛저널의 실제 구조·Section별 편집 리듬·복귀 사용자 진입을 추가하여 단조로움을 줄인다.

### 2.2 Notion에서 가져올 기능 원리

[Notion 한국어 홈페이지](https://www.notion.com/ko)는 상단에서 `로그인`과 신규 사용을 위한 CTA를 분리한다. DAMORI에는 다음 원리만 가져온다.

- 기존 사용자: `로그인` 또는 `내 기록으로 돌아가기`
- 신규·비로그인 사용자: `한 줄 시작하기` 또는 `내 방식 찾아보기`
- Navigation에서 두 행동을 경쟁시키지 않고 계층을 분리한다.
- 로그인 후에는 마케팅 Hero로 다시 보내기보다 최근 작업 또는 개인 작업 공간으로 복귀시키는 흐름을 설계한다.
- Notion의 제품 구조나 시각 디자인을 복제하지 않는다.

### 2.3 브랜드 기획 근거

브랜드 자료에는 다음 내용이 존재한다.

- 실물 다이어리와 노트
- 다이어리 커버
- 쿠션·패딩 구조
- 노트 앞면·옆면·제본부 확인
- 펼친 노트와 디지털 기기를 같은 생활 장면에 배치
- 노트·속지의 구조·줄·영역·분량 비교
- 기록·다이어리·생산성 도구에 관심이 있지만 고정 양식에는 피로한 사용자

따라서 Hero의 일반 종이 메모장을 `쿠션 커버 불렛저널`로 구체화하는 것은 새로 만든 장식이 아니라 브랜드 중심 소재를 회복하는 수정이다.

### 2.4 로그인 요구의 기존 기획과의 충돌

기존 CANONICAL 문서는 로그인·마이페이지·실제 클라우드 저장을 HOLD로 분류한다. 이번 사용자 요청은 기존 작업물로 복귀하는 로그인 진입을 새로 요구한다.

판정:

- 이번 피드백을 `NEW USER-APPROVED REQUIREMENT`로 기록한다.
- 최종 스토리보드에는 로그인 및 최근 작업 복귀 화면을 포함한다.
- 실제 백엔드 인증·동기화가 없는 HTML 단계에서는 `PROTOTYPE`으로 표시한다.
- 실제 로그인이 작동하는 것처럼 가짜 성공 상태를 만들지 않는다.
- 로컬 데모라면 로그인 Modal에서 `프로토타입 보기`까지만 제공하거나, 예시 최근 작업 화면으로 명확히 표시한다.
- 실제 제품 단계에서는 인증 방식, 개인정보, 세션, 로그아웃, 계정 복구, 저장 위치를 별도 설계해야 한다.

## 3. 문제 1 — 제목 줄바꿈과 가독성

### 3.1 원인

현재 Hero 제목은 HTML에 강제 줄바꿈이 있지만 다음 문제가 함께 존재한다.

- `font-size: clamp(3.5rem, 7vw, 7rem)`로 화면 폭에 따른 크기 변화가 크다.
- 제목 열의 실제 폭과 글자 크기의 조합에 따라 `달라져도 돼요.`가 의도와 다르게 끊길 수 있다.
- 모바일에서 글자 크기를 `3.45rem`으로 고정하지만 문구별 길이를 고려한 별도 규칙이 없다.
- 문장의 의미 단위가 아닌 시각적 공간에 따라 어미가 고립될 위험이 있다.
- 다른 Section 제목에도 공통 Heading Component 없이 개별 `<br>`이 들어가 있다.

### 3.2 최종 수정 원칙

1. 조사·어미·구두점이 단독 줄에 남지 않게 한다.
2. 줄바꿈은 문법 단위 또는 의미 단위로 고정한다.
3. Desktop, Tablet, Mobile용 문장 배열을 각각 정의한다.
4. `<br>`만으로 제어하지 않고 묶어야 할 어절에 `white-space: nowrap`을 제한적으로 사용한다.
5. CSS에서 Heading별 최대 폭과 글자 크기를 함께 조정한다.
6. 한 줄의 마지막이 `요.`, `돼요.`, `해요.`, `니다.`만 남으면 실패로 판정한다.
7. 실제 웹폰트 로딩 전후에도 같은 줄 구조가 유지되는지 확인한다.

### 3.3 권장 문장 배열

#### Hero

Desktop 권장:

```text
기록은 남고,
방식은 달라져도 돼요.
```

대안:

```text
기록은 남고,
방식은 달라도 돼요.
```

두 번째 문장은 길이가 짧고 의미가 더 직접적이므로 반응형 안정성이 높다. 다만 최종 카피 변경은 사용자 확인 후 확정한다.

Mobile 권장:

```text
기록은 남고,
방식은
달라져도 돼요.
```

`요.`만 별도 줄에 남는 구성은 모든 화면에서 금지한다.

#### Small Start

현재:

```text
하나만 남겨도
기록은 시작됩니다.
```

문법상 문제는 없지만 Hero와 같은 `2행 Serif + 설명` 공식이 반복되어 화면이 단조롭다.

개선안 A:

```text
오늘은 하나만,
그것으로 충분해요.
```

개선안 B:

```text
한 줄에서
오늘의 기록이 시작돼요.
```

이 Section에서는 큰 제목 옆에 `한 줄 / 사진 / 음성 / 기분`을 편집형 세로 Index로 배치해 구조적 변화를 만든다.

### 3.4 전 화면 Heading 검수 대상

| 영역 | 현재 제목 | 검수·수정 방향 |
|---|---|---|
| Hero | 기록은 남고, 방식은 달라져도 돼요. | 핵심 문장 2~3행, 어미 고립 금지 |
| 방식 찾기 | 지금의 나와 맞는 시작을 찾아볼까요? | 질문 의미 단위 유지, `찾아볼까요?` 단독 행 금지 |
| 작은 기록 | 하나만 남겨도 기록은 시작됩니다. | Hero와 다른 리듬, 편집형 Index 결합 |
| 방식 비교 | 종이와 화면을 같은 기준으로 비교해요. | `같은 기준으로`를 하나의 단위로 유지 |
| 원본 보호 | 표현을 바꿔도 원본은 그대로. | 2행 유지 가능, 마침표와 어절 고립 확인 |
| 복귀 | 멈춘 자리에서 다시 이어가도 괜찮아요. | 3행 이내, `괜찮아요.` 단독 행 가능 여부 시각 검토 |
| 제공 범위 | 지금 가능한 범위를 분명하게 알려드려요. | 크기를 낮추고 상태 Grid와 균형 조정 |

### 3.5 CSS 구현 기준

- Hero `max-inline-size`: 문구 실제 길이에 맞춘 9~11ch 후보
- Section H2 `max-inline-size`: 10~14ch 후보
- `font-size`: 글자 수가 긴 문구는 별도 Modifier 사용
- `text-wrap: balance`를 Progressive Enhancement로 사용
- 필수 어절은 `<span class="keep">달라져도 돼요.</span>`처럼 묶음
- 1280, 1024, 768, 430, 390, 360, 320px에서 캡처 비교
- 200% Zoom에서 잘림과 겹침이 없어야 함

## 4. 문제 2 — 상단바가 일반 웹 Header처럼 보임

### 4.1 목표

첨부 이미지 `image.png`를 최종 형태 기준으로 사용한다. 상단 전체를 둥근 Box로 감싸지 않고 Hero 이미지 위에 투명하게 얹힌 `Transparent Overlay Header`를 사용하며, 가운데 GNB 영역만 낮은 대비의 반투명 `Center Menu Capsule`로 묶는다.

이 구조의 핵심은 다음과 같다.

- Logo는 Capsule 밖의 왼쪽에 Hero 위로 직접 배치한다.
- Main Menu만 중앙의 길고 낮은 Rounded Surface 안에 넣는다.
- 언어·계정·Menu 같은 Utility는 Capsule 밖의 오른쪽에 둔다.
- Header 전체 배경과 Border를 만들지 않아 Hero 이미지가 끊기지 않게 한다.
- DAMORI에서는 오른쪽 Utility에 `로그인`을 포함하되 Primary CTA까지 무조건 넣어 복잡하게 만들지 않는다.

### 4.2 구조

```text
Hero Visual 위 Overlay Header
├─ Left: DAMORI Logo — 배경 없이 직접 배치
├─ Center: Rounded Menu Surface
│  ├─ 방식 찾기
│  ├─ Analog / Digital
│  ├─ 템플릿
│  └─ 기록 가이드
└─ Right: 로그인 / 언어 또는 Menu Utility — 배경 없이 직접 배치
```

```text
┌──────────────────────── Hero Image ─────────────────────────┐
│  DAMORI        ╭──────────────────────────╮        로그인  │
│                │ 방식 찾기  비교  템플릿  가이드 │        ○  │
│                ╰──────────────────────────╯                  │
│                                                            │
│                       Hero Content                         │
└────────────────────────────────────────────────────────────┘
```

### 4.3 시각 명세

- Header 폭: `min(calc(100% - 64~96px), 1440px)` 후보
- Header 자체 높이: 56~64px. 별도 Surface 없음
- Hero 상단 Offset: 12~20px 후보
- 중앙 Menu 폭: 콘텐츠 길이에 맞춘 440~620px 후보, 화면 전체 폭으로 늘리지 않음
- 중앙 Menu 높이: 40~48px
- 중앙 Menu Radius: 12~18px 후보. 과장된 999px Pill보다 낮고 긴 Rounded Rectangle 우선
- 중앙 Menu 배경: Olive/Ink 계열 18~32% 또는 Cream 12~22%의 반투명 Surface를 이미지 밝기에 따라 검수
- Backdrop Blur: 8~16px 후보, 미지원 브라우저에서는 충분한 불투명 배경 제공
- Border: 필수가 아니며 사용할 경우 흰색/Quiet Border 10~18% 한 단계
- Shadow: 기본적으로 없음 또는 매우 낮은 확산 Shadow
- Logo와 Utility는 투명 배경 위에서 읽히도록 밝은/어두운 전경 Token을 Hero 이미지별로 지정
- Logo 보호 영역 뒤에 별도 Capsule을 만들지 않음
- Hero 이미지의 구조물·얼굴·다이어리 핵심 Detail 위에 Menu가 겹치지 않도록 안전 영역 확보
- Scroll 전에는 Hero Overlay, Scroll 후에는 읽기 가능한 Solid/Blur Sticky 상태로 전환 가능

첨부 이미지와 DAMORI의 차이:

- 참고 이미지의 작은 흰색 Menu Text는 그대로 복제하지 않고 한글 가독성을 위해 13~15px, 500~600 Weight 후보로 높인다.
- DAMORI의 Cream·Olive Palette를 유지한다.
- 산업/건축 Hero 대신 쿠션 다이어리·손·노트북 장면의 비어 있는 상단 영역에 Header를 배치한다.
- Menu 항목 수를 줄여 중앙 Capsule이 길어지지 않게 한다.

### 4.4 기능 명세

- Logo: Home 이동
- Center Menu: `방식 찾기`, `비교`, `템플릿`, `기록 가이드`
- Right Utility: Text Link `로그인`, 선택적으로 언어 또는 Menu Icon
- `한 줄 시작하기`는 Header 안에 반드시 넣지 않고 Hero Primary CTA로 유지하여 상단 혼잡을 줄임
- Header CTA가 꼭 필요하면 로그인 옆 작은 Filled Button 하나만 허용하고 Desktop 시안 두 개를 비교 검수
- 현재 Section은 중앙 Capsule 내부의 Text/Underline/작은 Dot 중 하나로 표시
- 중앙 Menu Hover/Focus는 큰 Fill 변화보다 Text 대비와 얇은 배경 변화로 표현
- 모바일에서는 중앙 Capsule을 제거하고 Logo·로그인·Menu Button만 투명 Header에 유지
- 메뉴가 열리면 Header 아래 Rounded Sheet 또는 전체 화면 Menu로 연결
- ESC 닫기, Focus Trap, 닫은 뒤 Menu Button으로 Focus 복귀
- Hero 이미지 대비가 부족하면 Scroll을 기다리지 않고 Header 전용 Scrim 또는 Solid Mobile Header 적용

### 4.5 금지

- 과한 Glassmorphism
- 진한 Shadow로 실제 모바일 앱 창처럼 보이게 하는 것
- Header 전체를 하나의 큰 Rounded Card로 감싸는 것
- Logo와 오른쪽 Utility를 중앙 Capsule 안에 넣는 것
- 모든 버튼을 Capsule로 만들어 위계가 사라지는 것
- 로그인과 시작 CTA를 같은 강도로 표현하는 것
- Hero 이미지 밝기에 따라 Menu Text가 사라지는 것
- 중앙 Menu가 너무 길어 Logo 또는 Utility와 부딪히는 것
- 참고 이미지의 작은 Font와 낮은 대비를 그대로 복제하는 것

## 5. 문제 3 — 색은 좋지만 전체 화면이 단조로움

### 5.1 원인

- 대부분 Section이 `왼쪽 큰 Serif 제목 + 오른쪽 설명 + 아래 Grid` 구조를 반복한다.
- 배경색은 다르지만 콘텐츠의 크기 대비와 이미지 종류가 제한적이다.
- 기능 Card의 Border와 Radius가 유사하게 반복된다.
- 실제 브랜드 소재가 아니라 종이·화면을 추상 도형으로 표현해 Section 기억점이 약하다.
- 각 Section의 진입 장면과 종료 장면이 비슷하다.

### 5.2 색을 바꾸지 않고 변화시키는 방법

| 방법 | 적용 예 | 통제 기준 |
|---|---|---|
| Layout Variation | Split, Full Bleed, Editorial Rail, Overlap | 의미 순서와 Mobile Stack 유지 |
| Scale Contrast | 큰 쿠션 다이어리, 작은 상태 UI 병치 | 한 화면의 주인공 1개 |
| Product Detail | 커버 모서리, 패딩 두께, 제본, 밴드, 내지 | 미확정 소재·성능 단정 금지 |
| Typography Rhythm | Display, Vertical Index, Caption, Pull Quote | 본문 가독성 유지 |
| Texture | 패브릭·종이 Texture | Hero/About/Diary 영역에만 2~4% |
| Layering | 다이어리, 속지, 디지털 Card의 겹침 | 기능 UI 위에 장식 겹침 금지 |
| Section Divider | 재봉선, Grid Dot, Bookmark Line | 장식은 의미 상태와 혼동 금지 |
| Micro Motion | Nav 부상, Page Turn, Bookmark 이동 | Reduced Motion 대체 제공 |

### 5.3 Section별 다른 리듬

1. Hero: 큰 쿠션 다이어리 Product Composition + Floating Nav
2. 방식 찾기: 정돈된 기능 UI, 장식 최소
3. 작은 기록: Dark Editorial + 세로 Type Index
4. 방식 비교: 실제 다이어리 물성 Close-up과 Digital UI를 좌우 비대칭 비교
5. 원본/사본: 펼쳐지는 속지 Layer 또는 Before/After Rail
6. 복귀: Bookmark 또는 접힌 페이지를 Motif로 사용
7. 상태 범위: 작은 기능 Card Grid로 다시 밀도 회복

이 리듬은 모든 Section을 다르게 꾸미는 것이 아니라 `감성 → 기능 → 감성 → 기능`의 호흡을 만드는 방식이다.

## 6. 문제 4 — 메모장 이미지가 브랜드 중심 소재를 충분히 보여주지 못함

### 6.1 Hero 제품 이미지 방향

현재의 평평한 종이 메모장을 다음 조합으로 발전시킨다.

- 중심: 부드러운 쿠션/패딩 커버 다이어리
- 구조: 불렛저널 Dot Grid 또는 절제된 Grid 내지
- 디테일: 둥근 커버 모서리, 제본부, 두께, Bookmark, Elastic Band 후보
- 장면: 반쯤 열린 다이어리와 Digital 기록 Card가 같은 생활 장면에 놓임
- 소재: 저채도 Fabric, 종이, Sage/Olive 계열
- 조명: 자연광, 부드러운 그림자
- 배경: Cream Surface와 패브릭 또는 우드의 제한된 사용

### 6.2 불렛저널 표현 원칙

- 단순한 줄노트보다 Dot Grid를 사용한다.
- 월간·주간 양식을 빽빽하게 채우기보다 `Index, Key, Rapid Log`를 암시하는 작은 기록 조각을 사용한다.
- 과도하게 완성된 예쁜 다꾸 이미지는 시작 부담을 만들 수 있으므로 피한다.
- 빈 공간과 작성된 공간을 함께 보여준다.
- 실패 없이 수정 가능한 기록 태도를 나타내기 위해 작은 수정 흔적이나 이동 가능한 Tab을 사용할 수 있다.
- 불렛저널 명칭이나 공식 방법론을 상업적 기능처럼 단정하지 않고 `불렛저널 기반 기록 구조`로 표현한다.

### 6.3 쿠션 다이어리 표현 원칙

- 쿠션감은 단순 Drop Shadow가 아니라 커버 두께, 봉제선, 눌림과 모서리 형태로 표현한다.
- 너무 푹신한 파우치나 화장품 케이스처럼 보이지 않아야 한다.
- 펼침 구조와 필기 가능 영역이 보이게 한다.
- 실제 소재, 가격, 180도 펼침 성능은 검증 전 확정 문구로 쓰지 않는다.
- Hero 1장, Analog 비교 Detail 1~2장, 복귀 Section의 Bookmark Detail 정도로 이미지 반복을 제한한다.

### 6.4 필요한 이미지 자산 목록

1. `hero-cushion-diary`: 반쯤 펼친 쿠션 다이어리와 Digital 기록 Card
2. `diary-cover-detail`: 커버 모서리·봉제·두께 Close-up
3. `bullet-journal-spread`: Dot Grid, Index, 간결한 Rapid Log
4. `binding-paper-detail`: 제본부와 내지 Detail
5. `bookmark-return-detail`: 중단 후 복귀를 상징하는 Bookmark 장면

최종 사용 이미지에는 출처·라이선스 또는 생성 자산 여부를 기록한다.

## 7. 문제 5 — 로그인과 기존 작업 복귀 진입 부재

### 7.1 사용자 유형 분리

| 사용자 | 목표 | 첫 행동 |
|---|---|---|
| 처음 방문 | 기록 방식 이해와 작은 시작 | 내 방식 찾아보기 / 한 줄 시작하기 |
| 기존 작업 보유 | 최근 기록으로 즉시 복귀 | 로그인 / 내 기록으로 돌아가기 |
| 로그인 상태 | 최근 작업 확인 후 이어쓰기 | 최근 기록 열기 |

### 7.2 Navigation 행동 계층

- `로그인`: Text/Secondary Action
- `한 줄 시작하기`: Primary Action
- 로그인 후 `로그인`은 Avatar 또는 `내 기록`으로 변경
- 작은 시작은 로그인 전에도 가능해야 한다.
- 로그인 때문에 최초 기록이 막히면 안 된다.

### 7.3 Login Modal/Panel 명세

필수 요소:

- 제목: `내 기록으로 돌아가기`
- 설명: `기존 작업이 있다면 로그인해 이어서 기록할 수 있어요.`
- 이메일 입력
- 계속 버튼
- 소셜 로그인은 실제 연동 범위가 확인될 때만 추가
- 닫기
- 계정 없음/신규 시작: `로그인 없이 한 줄 시작하기`
- Prototype 상태 문구

접근성:

- Dialog 제목 연결
- 열릴 때 첫 입력 또는 제목으로 Focus 이동
- Focus Trap
- ESC와 닫기 버튼
- 닫은 후 로그인 버튼으로 Focus 복귀
- 오류는 입력과 연결된 Inline Message

### 7.4 로그인 후 복귀 화면

Notion의 원리는 “로그인 이후 기존 작업 공간으로 바로 돌아감”이다. DAMORI에서는 다음처럼 축소 적용한다.

```text
로그인
→ 최근 기록 1~3개
→ 마지막 수정 시점·매체·보존 상태 확인
→ 이어서 기록
```

최근 작업 Card 필드:

- 기록 제목 또는 첫 문장
- Analog/Digital/Template 구분
- 마지막 수정 시점
- LOCAL/PENDING/CONFLICT 등 상태
- `이어서 기록` CTA
- 다른 기록 보기

### 7.5 실제 구현 전 추가 결정

- 인증 제공자
- 이메일 인증·비밀번호·소셜 로그인 범위
- 기록 저장 위치
- 로그인 전 Local 기록을 계정으로 옮길지 여부
- 중복·충돌 처리
- 로그아웃과 계정 복구
- 개인정보와 삭제 정책

결정 전 HTML 최종안에서는 `로그인 및 작업 복귀 프로토타입`임을 표시한다.

## 12. 추가로 발견한 개선 방향

앞선 개선안이 `보이는 완성도`를 높이는 작업이라면, 아래 항목은 DAMORI가 실제로 이해되고 시작되며 다시 사용되는 경험을 완성하는 작업이다. 기능을 무조건 늘리는 것이 아니라, 초기 브랜드 기획의 핵심인 `부담 없는 기록`, `방식의 선택`, `Analog와 Digital의 공존`, `중단 후 복귀`가 화면 행동으로 이어지도록 보완한다.

### 12.1 첫 화면에서 5초 안에 브랜드를 이해시키기

현재 Hero는 정서와 분위기는 좋지만 방문자가 DAMORI를 다이어리 브랜드, 기록 방식 안내 서비스, 디지털 기록 도구 중 무엇으로 이해해야 하는지 잠시 고민할 수 있다.

Hero가 동시에 답해야 할 질문:

1. 무엇인가: 나에게 맞는 기록 방식을 찾고 가볍게 시작하는 공간
2. 누구를 위한 것인가: 기록하고 싶지만 정해진 방식과 꾸준함이 부담스러운 사람
3. 무엇을 할 수 있는가: 방식 찾기, 한 줄 시작, 기존 기록 이어가기
4. 무엇이 다른가: 종이 다이어리와 디지털 기록 중 하나를 강요하지 않음

개선 원칙:

- 감성 문구 아래에 기능을 설명하는 한 문장을 배치한다.
- Hero CTA는 `내 방식 찾기`, `한 줄 남기기`, `로그인`을 서로 다른 위계로 구분한다.
- 쿠션 다이어리와 디지털 기록 Card가 경쟁하지 않고 하나의 기록 생활 장면으로 연결되게 한다.
- 첫 화면에 기능 배지를 과도하게 나열하지 않는다.

검수 질문: 브랜드명을 가린 상태에서도 처음 보는 사용자가 5초 안에 서비스 목적을 설명할 수 있는가?

### 12.2 선택 피로를 줄이는 Progressive Disclosure

DAMORI는 방식의 자유를 말하지만 첫 화면에서 너무 많은 방식, 질문, 상태를 동시에 보여주면 오히려 선택 부담을 만든다. `모든 가능성 제시`보다 `지금 가능한 한 가지 행동`을 먼저 보여줘야 한다.

권장 흐름:

1. 지금 원하는 것 선택: `방식을 찾고 싶어요` / `바로 남기고 싶어요` / `이어서 하고 싶어요`
2. 선택한 목적에 필요한 정보만 표시
3. 결과 화면에서 다른 경로로 바꿀 수 있게 제공
4. 건너뛰기와 이전 선택 수정 허용

금지:

- 첫 진입부터 기록 종류·매체·빈도·목적을 한 화면에서 모두 질문
- 추천 결과를 정답처럼 단정
- 질문을 건너뛰면 불완전한 사용자처럼 표현

### 12.3 불렛저널을 `제품 이미지`가 아니라 `사용 구조`로 보여주기

Dot Grid를 배경 Texture로만 쓰면 불렛저널 정체성이 피상적으로 보인다. 실제 기록 원리를 짧은 데모로 보여줘야 한다.

최소 데모 구성:

| 요소 | 화면 표현 | 사용자 가치 |
|---|---|---|
| Rapid Log | 한 줄 기록 앞의 점·체크·이동 기호 | 짧게 시작 가능 |
| Index | 기록 주제와 페이지/날짜 연결 | 나중에 다시 찾기 |
| Migration | 오늘 못한 항목을 다음 날로 옮기기 | 실패가 아닌 이동 |
| Collection | 취향·문장·아이디어 묶음 | 자유로운 분류 |
| Blank Space | 채우지 않은 페이지 | 빈칸에 대한 부담 완화 |

브랜드 어조에서는 불렛저널을 숙련이 필요한 정답 양식으로 소개하지 않는다. `원한다면 사용할 수 있는 느슨한 뼈대`로 설명한다.

### 12.4 기록의 생애주기 설계

현재 화면은 시작과 복귀를 다루지만 기록 하나가 어떻게 남고 변하는지는 충분히 보이지 않는다. 최종 스토리보드에는 다음 생애주기를 한 번 이상 연결해 보여준다.

`빈 상태 → 첫 기록 → 임시/로컬 상태 → 수정 → 분류 또는 원본·사본 생성 → 중단 → 다시 찾기 → 이동/보관/삭제`

각 단계에서 필요한 정보:

- 지금 기록이 어디에 있는가
- 무엇이 저장되었고 무엇이 저장되지 않았는가
- 다음에 다시 찾는 방법은 무엇인가
- 수정하면 원본에 영향을 주는가
- 삭제 또는 이동을 되돌릴 수 있는가

실제 저장 기능이 없는 프로토타입에서는 이 흐름을 기능처럼 위장하지 않고 `예시 상태`로 표시한다.

### 12.5 로그인 전 기록과 로그인 후 작업의 연결 원칙

로그인 기능을 추가하면 `로그인 없이 바로 시작`이라는 장점이 약해질 위험이 있다. 따라서 로그인은 입장권이 아니라 기록을 이어가기 위한 선택지여야 한다.

권장 정책:

- 비회원도 한 줄 데모와 방식 찾기를 사용할 수 있다.
- 로그인 유도는 기록 시작 전보다 결과 확인 또는 이어가기 시점에 배치한다.
- 로그인 전 입력이 실제 저장되지 않는다면 입력 전에 명확히 알린다.
- 향후 Local 기록을 계정으로 옮길 경우 `가져오기`, `둘 다 유지`, `취소`를 제공한다.
- 중복 기록은 자동으로 덮어쓰지 않는다.
- 로그인 Dialog를 닫아도 작성 중이던 화면과 입력 맥락이 유지되어야 한다.

추가 상태:

| ID | 상태 | 필수 안내 |
|---|---|---|
| AUTH-003 | 로그인 취소 후 복귀 | 작성 화면과 입력 유지 여부 |
| AUTH-004 | Local 기록 발견 | 가져오기 선택과 영향 |
| AUTH-005 | 중복/충돌 | 두 버전의 차이와 안전한 선택 |
| AUTH-006 | 세션 만료 | 현재 입력의 보존 여부와 재로그인 |

### 12.6 `찾기` 경험은 검색창보다 먼저 설계하기

기존 기획은 검색 기능의 임의 추가를 금지하고 있다. 따라서 상단에 검색창부터 추가하지 말고, 적은 기록에서도 작동하는 다시 찾기 구조를 먼저 설계한다.

초기 탐색 방식:

- 최근 기록
- 날짜별 기록
- 내가 만든 Collection
- 종이/디지털 방식 구분
- Bookmark 또는 `다시 볼 기록`
- 중단한 기록

검색은 기록량과 사용자 필요가 검증된 이후 별도 기능으로 승격한다. 그 전에는 존재하지 않는 검색·필터가 작동하는 것처럼 표현하지 않는다.

### 12.7 쿠션 다이어리를 생활 장면과 세부 구조로 동시에 보여주기

제품 단독 Cut만 사용하면 커머스 페이지처럼 보이고, 감성 사진만 사용하면 구조를 이해하기 어렵다. 두 종류의 이미지를 역할에 맞게 분리한다.

| 이미지 유형 | 보여줄 내용 | 배치 |
|---|---|---|
| 생활 장면 | 침대 옆, 책상, 가방에서 꺼내는 순간, 디지털 기기와 공존 | Hero·브랜드 Section |
| 구조 Detail | 쿠션감 있는 커버, 모서리, 제본부, 펼친 내지, Bookmark | Analog·Diary Detail Section |
| 사용 흔적 | 짧은 기록, 빈칸, 이동 표시, 붙인 조각 | Bullet Journal Demo |

이미지는 지나치게 완벽하게 꾸민 다이어리보다 실제로 잠깐 쓰고 쉬었다가 다시 펼칠 수 있는 상태를 보여준다. 빈 페이지와 미완성 기록도 의도적으로 포함한다.

### 12.8 반복 방문을 위한 `오늘의 작은 입구`

첫 방문용 랜딩과 기존 사용자용 진입이 같은 정보 밀도를 가지면 반복 방문자는 매번 긴 설명을 통과해야 한다. 로그인 여부와 무관하게 재방문 맥락을 고려한 짧은 입구가 필요하다.

예시:

- 오늘 한 줄
- 어제 멈춘 곳 이어가기
- 최근 Bookmark 열기
- 방식 다시 고르기

단, 연속 기록일·미완료 수·목표 달성률을 전면에 표시해 압박을 만들지 않는다. DAMORI의 복귀 경험은 성취 추적보다 `다시 펼치기 쉬움`에 초점을 둔다.

### 12.9 감정 안전성을 포함한 Microcopy 기준

기록을 쉬거나 비워둔 사용자를 평가하지 않는다는 원칙을 버튼, 오류, Empty State까지 확장한다.

| 상황 | 피할 표현 | 권장 방향 |
|---|---|---|
| 빈 기록 | 아직 아무것도 작성하지 않았어요 | 오늘 남기고 싶은 것이 생기면 여기서 시작할 수 있어요 |
| 중단 후 복귀 | 밀린 기록을 완성하세요 | 멈춘 곳부터 이어가거나 새로 시작해도 괜찮아요 |
| 저장 불가 | 저장에 실패했습니다 | 이 화면에는 아직 남아 있어요. 다시 시도할 수 있어요 |
| 추천 결과 | 당신에게 가장 완벽한 방식 | 지금 답변과 가까운 방식 |
| 삭제 | 정말 삭제하시겠습니까? | 삭제되는 범위와 되돌릴 수 있는 시간 명시 |

문구 검수 기준:

- 사용자의 성실함·의지·꾸준함을 평가하지 않는가
- 완료를 강요하지 않는가
- 상태와 다음 행동을 함께 설명하는가
- 실제 기능 범위를 과장하지 않는가

### 12.10 모바일에서는 `작은 데스크톱`이 아닌 다른 편집 구조 사용

모바일에서 데스크톱 Card를 단순 세로 적층하면 길고 단조로운 화면이 된다.

모바일 전용 원칙:

- 모바일 Transparent Header는 로고·로그인·Menu Button만 남기고 중앙 Capsule은 펼침 Menu로 전환한다.
- Hero CTA는 엄지 영역에서 누르기 쉬운 순서로 배치한다.
- 다이어리 Detail은 작은 썸네일 나열보다 한 장씩 넘기는 구조를 사용한다.
- Analog/Digital 비교표는 좌우 열 축소 대신 기준별 전환 또는 순차 Card로 바꾼다.
- Modal은 작은 화면에서 Bottom Sheet 또는 전체 화면 Dialog를 검토한다.
- 키보드가 열려도 입력, 저장 범위 안내, 닫기 행동이 가려지지 않아야 한다.
- `100dvh`, Safe Area, 가로 320px, 글자 확대 200%를 함께 검수한다.

### 12.11 Motion은 장식보다 물성과 상태 전달에 사용

단조로움을 줄이기 위해 Motion을 늘리는 것이 아니라, 다이어리의 촉감과 기능의 변화를 이해시키는 데 제한적으로 사용한다.

적합한 Motion:

- Overlay Header가 Scroll 이후 읽기 쉬운 Solid/Blur Sticky 상태로 미세하게 전환됨
- Bookmark가 다음 Section 방향을 암시함
- 원본과 사본의 관계가 Layer 이동으로 설명됨
- 기록 상태가 바뀔 때 Label과 보조 문장이 함께 갱신됨
- 다이어리 페이지 전환은 짧고 절제된 움직임으로 표현

부적합한 Motion:

- 읽기 전에 사라지는 자동 Carousel
- 종이가 계속 흔들리거나 떠다니는 반복 Animation
- 저장되지 않았는데 완료 Check Animation을 보여주는 연출
- `prefers-reduced-motion`에서 정보가 사라지는 설계

### 12.12 콘텐츠 밀도와 여백의 리듬 설계

모든 Section을 큰 제목, 설명, 3개 Card로 구성하는 반복을 피한다. 색상은 유지하되 콘텐츠 밀도를 의도적으로 바꾼다.

권장 리듬:

1. Hero: 큰 이미지와 짧은 문장
2. 선택: 조작 중심의 조밀한 UI
3. Diary Story: 이미지 중심의 넓은 여백
4. Bullet Journal Demo: 실제 기록 Detail 중심
5. Analog/Digital: 비교 정보 중심
6. Small Start: 입력 행동 중심
7. Return: 낮은 밀도의 안심 문구와 한 가지 행동

각 Section마다 다음 네 요소 중 두 개 이상을 이전 Section과 다르게 한다: 정렬, 이미지 비율, 정보 밀도, 배경 Layer, 상호작용 방식.

### 12.13 접근성을 브랜드 품질로 통합

접근성은 검수 단계의 부가 항목이 아니라 `누구에게도 기록 시작을 어렵게 하지 않는다`는 브랜드 태도다.

추가 기준:

- Cream·Olive 조합의 일반 텍스트 대비를 실제 토큰별로 측정한다.
- 색뿐 아니라 Icon·Label·문장으로 상태를 구분한다.
- 모든 Dialog는 제목, 설명, 초기 Focus, Focus Trap, ESC, 닫은 후 Focus 복귀를 갖는다.
- Skip Link와 명확한 Heading 순서를 제공한다.
- 다이어리 이미지는 분위기 설명이 아닌 기능적 대체 텍스트를 갖는다.
- 장식 Dot Grid와 Texture는 보조 기술에서 제외한다.
- 터치 대상은 최소 44×44px, 인접 대상 간 간격을 확보한다.
- 오류 발생 시 입력값을 지우지 않고 오류 위치로 이동할 수 있게 한다.

### 12.14 신뢰를 만드는 Honest Product Language

DAMORI는 아직 실제 인증·동기화·파일 저장이 확정되지 않은 프로토타입이다. 기능처럼 보이는 시각 완성도가 높아질수록 오해 위험도 커진다.

화면별 표시 기준:

| 표기 | 의미 | 허용 표현 |
|---|---|---|
| DEMO | 조작만 확인하는 예시 | 입력해 볼 수 있어요 |
| SAMPLE | 예시 데이터 | 이런 모습으로 이어질 수 있어요 |
| LOCAL | 현재 기기/화면 범위 | 이 기기 또는 현재 화면에만 남아요 |
| PROTOTYPE | 아직 실제 서비스가 아님 | 흐름을 확인하는 화면이에요 |
| HOLD | 검증·결정 전 기능 | 아직 제공하지 않아요 |

`저장되었습니다`, `안전하게 보관됩니다`, `어디서나 이어집니다`는 실제 구현과 검증 없이는 사용하지 않는다.

### 12.15 디자인 전에 검증할 사용자 리서치

추가 개선은 내부 판단만으로 확정하지 않고 소규모 사용자 검증으로 우선순위를 결정한다.

#### 권장 인터뷰 대상

- 종이 다이어리를 샀지만 자주 중단한 사람
- 디지털 메모를 사용하지만 분류가 부담스러운 사람
- 종이와 디지털을 함께 사용하는 사람
- 다꾸·불렛저널 숙련자와 비숙련자
- 기록을 꾸준히 해야 한다는 압박을 느끼는 사람

#### 수행 과제

1. 첫 화면을 5초 보고 DAMORI가 무엇인지 설명하기

3. 나에게 맞는 기록 방식 찾기
4. 멈춘 기록으로 돌아가기

#### 기록 지표

- 상태 Label을 정확히 이해한 비율
- 제목·버튼·본문에서 멈추거나 다시 읽은 지점
- `부담 없다`, `나를 평가하지 않는다`, `다시 시작하기 쉽다`에 대한 정성 반응

전환율만으로 판단하지 않는다. 빠른 클릭이 오해로 인한 것인지, 사용자가 실제로 안심하고 선택한 것인지 인터뷰 발화와 함께 본다.

## 14. Analog/Digital 비교와 Main Hero 심화 개선안

### 14.1 이번 추가 피드백의 판정

현재 `종이와 화면을 같은 기준으로 비교해요.` Section은 Analog와 Digital을 우열 없이 나눈 점은 좋다. 그러나 텍스트 설명과 표가 중심이라 두 방식의 차이가 머리로는 이해돼도 화면에서 즉시 체감되지는 않는다. 또한 Digital이 `짧은 메모와 일정` 정도로 축약되어 노트 필기, 여행 기록, 학습, 취향 아카이빙처럼 실제로 확장 가능한 기록 생활을 충분히 보여주지 못한다.

따라서 이 Section의 목표를 다음처럼 수정한다.

> 하나의 표에서 장단점을 읽게 하는 비교가 아니라, 두 개의 서로 다른 기록 장면을 먼저 경험하고 동일한 기준으로 차이를 확인한 뒤, 필요하면 두 방식을 함께 선택하게 한다.

핵심 수정:

- Analog와 Digital을 각각 독립된 Visual Stage로 구성한다.
- Analog에는 쿠션 다이어리, 펼친 불렛저널, 펜, Bookmark, 실제 필기 흔적을 배치한다.
- Digital에는 노트북 또는 Tablet Frame, 기록 App Window, 모바일 Quick Capture를 배치한다.
- Digital 기록 범위를 메모 앱 하나로 축소하지 않는다.
- 두 방식의 시각 무게, 설명 분량과 CTA 위계를 동등하게 맞춘다.
- 비교의 끝을 `하나 선택`이 아니라 `지금 상황에 맞게 선택 또는 함께 사용`으로 마무리한다.

### 14.3 Main Hero 권장 콘셉트 — One Life, Two Surfaces

#### 핵심 장면

하나의 책상 또는 일상 공간 위에 다음 오브젝트가 자연스럽게 함께 놓인다.

- 반쯤 펼쳐진 Olive/Cream 쿠션 다이어리
- Dot Grid 위의 짧은 Rapid Log와 아직 비어 있는 영역
- 페이지 사이의 Bookmark와 작은 종이 조각
- 화면이 열린 얇은 노트북 또는 Tablet
- 노트북 안에 떠 있는 2~3개의 기록 App Window
- 바로 기록하는 모바일 Quick Capture Card
- 펜을 들거나 페이지를 넘기는 손의 일부

이 구성은 `종이 대 디지털`의 대결이 아니라 한 사람의 기록 생활 안에 두 표면이 공존한다는 의미를 만든다.

#### 화면 Composition

```text
┌──── Transparent Header / Center Menu Capsule ──────────────┐

  DAMORI                                      [얇은 앱 창]

  기록은 남고,                      ┌──────── Laptop ────────┐
  방식은 달라져도 돼요.             │ 여행 / 학습 / 취향 기록 │
                                     └────────────────────────┘
  설명 문장 + Primary CTA
  Secondary CTA                    ╱ Cushion Diary ╱
                                  펼친 Dot Grid + 손 + Bookmark

                 Scroll Cue · 두 방식 살펴보기
```

Desktop 기준:

- Text 42%, Visual 58%의 비대칭 Grid
- 다이어리는 화면 하단과 Grid 바깥으로 일부 Crop하여 물성을 크게 느끼게 함
- 노트북 화면은 다이어리 뒤쪽 상단에 배치해 깊이를 만듦
- App Window 1개만 Grid 밖으로 살짝 이탈시켜 Digital의 확장성을 암시
- Hero 높이는 최소 `min(900px, 100svh)` 후보로 검수
- 제목은 2~3행, 핵심 Visual과 시선이 충돌하지 않게 배치

Mobile 기준:

- 제목과 CTA 다음에 다이어리와 디지털 화면을 대각선으로 겹침
- 장식 App Window는 1개만 남기고 나머지는 다음 Section으로 이동
- 손·Bookmark·다이어리 모서리처럼 작은 화면에서도 알아볼 수 있는 Detail을 우선
- Hero에서 가로 Scroll이나 오브젝트 잘림으로 의미가 사라지지 않게 함

#### 권장 Hero Copy 구조

Eyebrow:

`PAPER, SCREEN, AND YOUR OWN WAY`

H1:

```text
기록은 남고,
방식은 달라져도 돼요.
```

Supporting Copy:

> 다이어리 한 페이지부터 노트북 속 여행 기록까지, 지금의 생활과 목적에 맞는 방식으로 남겨보세요.

CTA:

- Primary: `내 기록 방식 찾기`
- Secondary: `오늘 한 줄 남기기`
- Utility: `로그인해 이어가기`

### 14.4 Hero Motion Storyboard

Motion은 Hero의 의미를 보조하는 3단계만 사용한다.

| 단계 | 사용자 상태 | 표현 | 목적 |
|---:|---|---|---|
| 1 | 첫 진입 | 다이어리와 노트북은 이미 보이고, 제목과 CTA가 짧게 나타남 | 기능을 기다리지 않고 즉시 이해 |
| 2 | 첫 Scroll | Bookmark가 아래 방향으로 12~20px 이동하고 App Window가 제자리로 정돈됨 | 다음 비교 Section으로 연결 |
| 3 | 비교 Section 진입 | 하나의 Hero 장면이 Analog와 Digital 두 Stage로 분리됨 | 공존에서 비교로 자연스럽게 전환 |

제한:

- 초기 로딩 후 600ms 이내에 핵심 문장과 CTA가 읽혀야 한다.
- 다이어리와 Digital 화면을 늦게 로딩되는 숨은 콘텐츠로 만들지 않는다.
- Pointer Parallax는 4~8px 범위 후보이며 입력 장치가 없을 때 동일한 의미를 유지한다.
- Reduced Motion에서는 모든 오브젝트를 최종 위치에 정적으로 배치한다.

### 14.5 Analog Stage 시각 명세

Analog는 단순히 `느리고 감성적인 방식`으로 묘사하지 않는다. 손으로 쓰는 과정, 물성, 공간 기억, 자유로운 배치를 구체적으로 보여준다.

#### 오브젝트 구성

- 중심: 펼친 쿠션 다이어리 또는 불렛저널 1권
- 보조: 닫힌 다이어리 Cover Detail 1개
- 사용 흔적: Rapid Log, 여행 Ticket 조각, 학습 Diagram, 취향 Sticker 또는 작은 Photo
- 기능 표시: Bookmark, Index, Page Number, Migration Symbol
- 도구: 펜 1개와 필요할 때만 제한된 부착 요소

#### Visual Card 예시

```text
ANALOG · 손에 남는 기록

   [펼친 쿠션 다이어리 대형 이미지]
   왼쪽: 짧은 오늘 기록 + 빈칸
   오른쪽: 여행 Ticket + 작은 Sketch

   01 오래 생각하기
   02 손으로 자유롭게 배치하기
   03 물리적인 위치와 흔적으로 기억하기
```

#### Analog에서 보여줄 기록 유형

- 일상 다이어리와 감정 기록
- 불렛저널 Rapid Log
- 강의·독서 노트 필기
- 여행 Ticket·영수증·Sketch를 붙인 여행 기록
- 손으로 그린 학습 Diagram
- 취향 Scrap과 작은 Collection

### 14.6 Digital Stage 시각 명세

Digital은 검은 메모 Card 하나가 아니라 여러 기록이 구조화되고 다시 사용되는 작업 공간으로 보여준다. 단, 확정되지 않은 Cloud·자동 동기화 기능은 시각적으로 암시하지 않는다.

#### 기기와 UI Layer

- 중심: 노트북 또는 Tablet Frame 1개
- 내부: 기록 Library 또는 Workspace 화면
- 겹침: 모바일 Quick Capture 1개
- 보조 App Window: 최대 2개
- 상태 Label: SAMPLE 또는 PROTOTYPE

#### Digital Visual의 내부 구조

```text
DIGITAL · 이어서 확장하는 기록

┌ Laptop / Workspace ─────────────────┐
│ 최근 기록                           │
│ [여행] 서울 골목 기록               │
│ [학습] 디자인 시스템 강의 노트      │
│ [취향] 다시 보고 싶은 전시와 책     │
│ [노트] 오늘 떠오른 한 문장          │
└─────────────────────────────────────┘
               ┌ Mobile Quick Note ──┐
               │ 사진 + 짧은 문장    │
               └─────────────────────┘
```

#### Digital 기록 유형 확장

| 기록 유형 | 화면 예시 | 핵심 가치 | 주의 |
|---|---|---|---|
| 노트 필기 | 제목, 핵심 Bullet, 강조 문장, 연결 자료 | 수정과 재구성 | 특정 앱 UI 복제 금지 |
| 여행 기록 | 날짜, 장소 Label, 사진, 짧은 감상 | 순간과 맥락 함께 보관 | 실제 지도 연동처럼 표현 금지 |
| 학습 기록 | 강의별 Page, 개념 정리, 질문, 복습 표시 | 누적·분류·다시 보기 | 자동 학습 추천 암시 금지 |
| 취향 기록 | 책·음악·전시·공간 Collection | 좋아하는 것을 묶어 보기 | 외부 콘텐츠 권리 확인 |
| 일상 기록 | 한 줄, 기분, 사진 | 빠른 시작 | 실제 서버 저장 표기 금지 |
| 아이디어 | 떠오른 문장, Sketch Image, Link 자리 | 빠른 수집 후 정리 | 실제 Link Preview 보장 금지 |
| 프로젝트 기록 | 과정 Note, 결정, 다음 행동 | 변화 과정 보존 | 협업 기능으로 오해 금지 |

Digital을 업무 생산성 Dashboard처럼 만들지 않는다. 숫자 지표, 완료율, 연속 기록일보다 `기록의 제목`, `내용 일부`, `다시 펼치는 맥락`을 중심으로 보여준다.

### 14.7 같은 기준으로 비교할 콘텐츠 보완

기존 비교표의 `시작 속도·수정 방식·보관 확인`만으로는 사용자가 자기 상황을 판단하기 부족하다. 다음 9개 기준을 사용하되 한 화면에 모두 노출하지 않는다.

| 비교 기준 | Analog | Digital | 함께 사용할 때 |
|---|---|---|---|
| 시작 준비 | 다이어리와 펜이 필요함 | 기기가 켜져 있으면 바로 입력 가능 | 밖에서는 Digital, 책상에서는 Analog |
| 생각의 속도 | 손의 속도로 천천히 머무름 | 빠르게 입력하고 길게 확장 가능 | 초안은 Digital, 깊은 정리는 Analog 가능 |
| 표현 방식 | 필기·그림·부착·여백을 자유롭게 혼합 | Text·Image·구조화된 Block 조합 | 종이 흔적을 사진으로 참고 가능 |
| 수정 | 덧쓰기·지우기·이동 기호가 흔적으로 남음 | 재배열·복사·편집이 쉬움 | 원본 흔적과 편집본을 분리 가능 |
| 분류 | Index·Bookmark·물리적 구획 | Page·Collection·Label 구조 | 큰 주제는 Digital, 개인 흔적은 Analog |
| 다시 찾기 | 위치·표지·손의 기억으로 찾음 | 최근 기록·날짜·Collection으로 찾음 | 두 방식의 연결 표식을 둘 수 있음 |
| 휴대와 환경 | 빛·배터리 없이 사용, 물리적 부피 존재 | 기기 하나로 다양한 기록, 화면 환경 필요 | 상황에 따라 매체 전환 |
| 보관 | 직접 보관 장소와 손상 가능성을 관리 | 저장 범위와 상태를 확인해야 함 | 어느 쪽이 원본인지 정함 |
| 어울리는 기록 | 장문, 감정, Sketch, 부착물, 깊은 사유 | 노트, 여행, 학습, 취향, 사진, 빠른 수집 | 하나의 주제를 서로 다른 밀도로 기록 |

Desktop 표현:

- 처음에는 3개 핵심 기준만 노출한다.
- `더 비교하기`를 누르면 나머지 기준이 Disclosure된다.
- 행에 Mouse Hover가 아니라 Keyboard Focus와 Touch에도 대응하는 강조 상태를 제공한다.
- Analog/Digital 열에 동일한 면적과 Typography 위계를 사용한다.

Mobile 표현:

- 상단 Segmented Control을 `Analog / Digital` 전환 용도가 아니라 `기준별 보기`에 사용한다.
- 한 Card 안에 하나의 비교 기준과 두 방식의 설명을 순서대로 보여준다.
- 좌우 Swipe를 유일한 탐색 방식으로 사용하지 않고 이전·다음 Button과 위치 Label을 제공한다.

### 14.9 시각 차이를 만드는 세부 언어

색상은 기존 Palette를 공유하되 형태와 표면으로 차이를 만든다.

| 요소 | Analog | Digital | 공통성 유지 방법 |
|---|---|---|---|
| 형태 | 비정형 Crop, 종이 모서리, 제본 곡선 | 정돈된 Window, 얇은 Device Frame | 같은 Radius Scale 사용 |
| 표면 | 종이결·패브릭·연필 흔적 | 선명한 Surface·1px Border·Focus 상태 | Cream·Olive Palette 공유 |
| 깊이 | 겹친 종이의 낮은 Shadow | 떠 있는 Window의 명확한 Elevation | Shadow 색과 방향 통일 |
| Typography | Serif 제목과 손글씨는 이미지 안에서만 제한 | Sans UI Label과 명확한 정보 계층 | 본문 Font와 Size Token 공유 |
| Motion | 페이지·Bookmark의 느린 움직임 | Window 정렬·상태 전환 | Duration과 Easing Token 공유 |
| Icon | Index·Bookmark·Pen | Page·Image·Collection | 동일 Stroke Weight |

손글씨 Font로 본문을 만들거나 Digital을 검은 화면으로만 구분하지 않는다. 두 영역 모두 접근 가능한 대비와 동일한 정보 품질을 유지한다.

### 14.11 기록 유형 탐색 Component

비교 Section 아래에 `무엇을 남기고 싶나요?`라는 기록 유형 탐색을 추가할 수 있다. 이 Component는 Analog/Digital을 고르는 질문이 아니라 같은 기록 목적을 두 방식으로 미리 보는 장치다.

기록 유형:

- 노트 필기
- 여행 기록
- 학습 기록
- 취향 기록
- 일상과 감정
- 아이디어

선택 시 보여줄 내용:

```text
[여행 기록 선택]

Analog Preview
Ticket, 손글씨, 이동 경로 Sketch, 빈칸

Digital Preview
사진, 날짜, 장소 Label, 짧은 감상, Collection

둘 중 무엇이 더 편한가요?
[종이로 살펴보기] [화면으로 살펴보기] [둘 다 보기]
```

이 결과는 사용자의 방식을 자동 확정하지 않는다. `지금 이 기록에는 가까운 방식`으로만 제안한다.

| P0 | Analog/Digital Stage에 각각 명확한 대표 오브젝트 배치 | 텍스트를 읽기 전 차이를 인식 |
| P0 | 비교 기준을 3개에서 9개로 확장하고 Progressive Disclosure 적용 | 실제 선택에 필요한 정보 보완 |
| P0 | Digital 기록 유형에 노트·여행·학습·취향 추가 | Digital의 활용 범위 축소 문제 해결 |
| P1 | 기록 유형별 Analog/Digital Preview | 사용자가 자기 목적과 연결 |
| P1 | Hero에서 비교 Section으로 이어지는 제한된 Motion | Main Impact와 서사 연결 |
| P1 | 생활 장면과 구조 Detail 이미지 자산 분리 제작 | 감성과 기능 동시 전달 |
| P2 | Pointer 기반 미세 Depth | 큰 화면의 몰입감 보완 |

### 14.13 추가 검수 기준

#### Main Hero

- 5초 안에 다이어리와 Digital 기록이 모두 인식되는가
- 쿠션 다이어리가 일반 종이 또는 메모지처럼 보이지 않는가
- 노트북 화면이 업무 Dashboard 또는 특정 앱 복제품처럼 보이지 않는가
- Text와 Visual 중 한쪽이 지나치게 약하지 않은가
- Motion이 없어도 같은 메시지가 전달되는가
- 로그인보다 기록 방식 찾기와 한 줄 시작이 먼저 보이는가

#### Analog/Digital 비교

- 두 Stage가 색이 아니라 오브젝트·표면·구조만으로도 구분되는가
- Analog와 Digital의 이미지 면적과 설명 깊이가 동등한가
- Analog를 감성, Digital을 효율로만 단순화하지 않았는가
- 노트 필기·여행·학습·취향 기록이 실제 Preview로 보이는가
- Digital의 미구현 저장·검색·동기화를 기능처럼 암시하지 않는가
- 한 방식을 고르지 않고 `둘 다 보기`가 가능한가
- 모바일에서 비교를 위해 좌우로 반복 이동하지 않아도 되는가

#### 콘텐츠

- 기록 유형마다 Analog와 Digital 예시가 최소 하나씩 있는가
- 기록 내용이 지나치게 완벽하거나 성취 중심으로 보이지 않는가
- 빈칸과 미완성 기록도 자연스럽게 포함되는가
- 사용자가 자기 생활 장면을 떠올릴 수 있는가

### 14.14 이번 보완의 최종 결론

> Main Hero는 쿠션 다이어리만 크게 보여주는 제품 소개가 아니라, 다이어리와 노트북 화면이 한 사람의 기록 생활 안에서 공존하는 대표 장면이어야 한다. Analog/Digital 비교는 설명 표에 머물지 않고 서로 다른 물성과 사용 장면을 먼저 보여준 뒤 같은 기준으로 비교해야 한다. Digital은 빠른 메모뿐 아니라 노트 필기, 여행, 학습, 취향, 일상, 아이디어와 프로젝트 과정까지 담을 수 있는 확장된 기록 공간으로 표현하되, 실제 구현되지 않은 저장과 동기화는 약속하지 않는다.

## 15. 다이어리 템플릿 목록·간단 제작·실물 주문 제작 확장안

### 15.1 기능 추가 판정

사용자는 기존 템플릿을 선택해서 사용할 수 있을 뿐 아니라, 미리캔버스처럼 자신에게 필요한 다이어리 템플릿을 직접 만들고, 완성한 결과를 디지털로 사용하거나 실물 다이어리로 주문 제작할 수 있는 방향을 요청했다.

이 요청은 초기 브랜드 기획과 연결된다.

- Brand Layer: 템플릿·속지 추천
- Analog Track: 기본·맞춤형 속지, 도트 그리드와 템플릿 속지, 다이어리 커버
- Digital Track: 템플릿 선택과 미리보기
- Template/Expression Layer: 구조와 표현의 분리, 원본·미리보기·적용 결과 구분
- 장기 확장 방향: 디지털 템플릿 숍, 실물 다이어리 커스텀 제작

다만 기존 CANONICAL 범위에서는 실제 가격·결제·주문·생산·배송을 제공 기능으로 확정하지 않았다. 따라서 이번 피드백을 다음처럼 판정한다.

- `NEW USER-APPROVED PRODUCT DIRECTION`: 템플릿 직접 제작과 실물 주문 제작
- `CURRENT DESIGN SCOPE`: 템플릿 목록, 상세 미리보기, 간단 제작 UI, 완성 후 사용 방식 분기
- `PROTOTYPE`: 템플릿 편집·미리보기·사본 생성
- `PLANNED/INFORMATION_ONLY`: 실물 주문 제작 진입과 구성 확인
- `HOLD UNTIL VERIFIED`: 가격, 결제, 인쇄 사양, 생산 기간, 재고, 배송, 교환·환불

즉, 최종 웹디자인에는 앞으로 어떤 서비스가 될지 이해할 수 있는 내용과 화면을 넣되 현재 주문이 가능한 것처럼 오해시키지 않는다.

### 15.2 미리캔버스에서 참고할 구조와 DAMORI식 축소

[미리캔버스 템플릿 페이지](https://www.miricanvas.com/ko/templates?from=gnb)는 다양한 템플릿을 `타입`, 추천, 인기, 무료 등 목록 단위로 탐색하게 한다. DAMORI는 이 구조에서 `빠른 탐색`, `시각적 미리보기`, `기존 템플릿으로 바로 시작` 원리만 참고한다.

| 미리캔버스에서 참고 | DAMORI 적용 | 적용하지 않음 |
|---|---|---|
| 유형별 템플릿 탐색 | 기록 목적별 다이어리 템플릿 목록 | 수많은 범용 디자인 형식 |
| 썸네일 중심 빠른 비교 | 실제 다이어리 Spread와 Digital Preview | 광고·배너 중심 Gallery |
| 템플릿으로 빠르게 시작 | `이 템플릿으로 시작` | 처음부터 빈 Canvas 강요 |
| 빈 디자인 제작 | `내 템플릿 만들기` | 전문가용 복잡한 편집기 |
| 여러 페이지 결과 | 표지·월간·주간·기록 Page Set | Presentation 수준 Page 관리 |
| 제작 결과 활용 | Digital 사용 또는 실물 제작 계획 | 모든 출력물·상품으로 확장 |

DAMORI의 편집기는 `디자인 툴`이 아니라 `다이어리 구조를 고르는 조립 도구`여야 한다.

실물 주문 제작은 Template Maker의 결과 단계에서만 후속 선택으로 보여준다. Hero나 GNB의 Primary CTA로 올려 브랜드를 쇼핑몰처럼 보이게 하지 않는다.

### 15.4 Template Gallery 목록 구성

#### 상단 구조

```text

```

#### 목록 Group

사용자가 한 번에 너무 많은 템플릿을 보지 않도록 3개 Group만 우선 노출한다.

1. `부담 없이 시작하기`: 한 줄, 오늘의 기분, 5분 기록
2. `목적에 맞게 남기기`: 여행, 학습, 독서, 취향
3. `다시 이어가기`: 주간 회고, 미완료 이동, 다시 볼 기록

각 Group은 4~6개 카드 후보로 시작하고 `모두 보기`로 확장한다. 인기순·최신순·무료순 같은 상업적 정렬보다 기록 목적과 필요한 입력량을 먼저 보여준다.

| 이름 | 여행의 조각 | 용도 인식 |
| 목적 | 여행·사진·짧은 감상 | 적합 상황 확인 |

| 상태 | SAMPLE / PROTOTYPE | 실제 제공 범위 확인 |

### 15.6 복잡하지 않은 Template Maker 원칙

복잡성을 낮추기 위해 Desktop Publishing 방식의 자유 배치를 제공하지 않는다. 사용자는 모든 요소를 직접 그리는 대신 `Block 선택과 순서 조정`으로 템플릿을 만든다.

#### 4단계 제작 흐름

1. `무엇을 남길까요?`
   - 일상 / 불렛저널 / 노트 / 여행 / 학습 / 취향 / 회고
2. `어떤 틀에서 시작할까요?`
   - 추천 템플릿 3개 / 빈 Dot Grid / 간단 Blank
3. `필요한 항목만 골라요`
   - 날짜 / 제목 / 한 줄 / 긴 글 / Check / 사진 / 작은 그림 / Rating / Bookmark
4. `모습을 확인해요`
   - Digital Preview / 펼친 다이어리 Preview / 저장 범위 / 사용 방식 선택

단계는 4개를 넘기지 않는다. 표지·용지·제본·수량 같은 실물 옵션은 템플릿 제작 단계와 섞지 않고 주문 제작 단계에서 별도로 다룬다.

#### Editor 화면 구조

```text
┌─ Template Maker ───────────────────────────────────────────┐
│ ← 나가기             여행의 조각              [미리보기]  │
├──────────────┬─────────────────────────┬───────────────────┤
│ 필요한 항목  │                         │ 지금 바꿀 수 있어요│
│ □ 날짜       │     Page Preview        │ 구조 / 표현        │
│ □ 장소       │                         │                   │
│ □ 사진       │    [선택 Block 표시]    │ 크기: 간단 3단계   │
│ □ 한 문장    │                         │ 여백: 3단계        │
│ + 항목       │                         │ 색: Brand Set      │
├──────────────┴─────────────────────────┴───────────────────┤
│ 원본은 그대로예요. 현재 작업은 사본 미리보기입니다.       │
│                             [이전] [완성본 확인]           │
└────────────────────────────────────────────────────────────┘
```

#### 허용 편집

- 항목 추가·제거
- 항목 순서 이동
- Page 추가·복제·제거
- 2~3단계의 Block 크기
- 2~3단계의 여백
- 제한된 DAMORI Color Set
- Dot / Ruled / Blank 배경 선택
- 표지 제목과 짧은 문구
- 사진 또는 장식 자리 표시 여부

#### 초기 제외

- Pixel 단위 자유 배치
- 수백 개 Font와 Color
- 복잡한 Layer Panel
- Mask, Path, Vector 편집
- 자유로운 Animation
- 동시 협업
- Plugin과 외부 App 연동
- AI 자동 완성

고급 기능은 `더 많은 설정` 아래 숨기는 방식이 아니라, 사용자 검증 전에는 제공하지 않는다.

### 15.7 구조와 표현을 분리하는 편집 모델

초기 기획의 핵심인 Template과 Expression Asset 구분을 Editor에도 유지한다.

| 영역 | 바꾸는 것 | 예시 |
|---|---|---|
| 구조 | 무엇을 어떤 순서로 기록하는가 | 날짜·장소·사진·한 문장 |
| 표현 | 같은 내용을 어떤 모습으로 보는가 | Cream/Olive, Line, Sticker 자리, Cover |
| 실물 구성 | 어떤 물리적 형태로 제작하는가 | 크기·내지·표지·제본 후보 |

세 영역을 한 Panel에 섞지 않는다.

- `구조 편집`: Template Maker 핵심
- `표현 바꾸기`: 선택적 2차 행동
- `실물로 만들기`: 완성 후 별도 단계

이 구분은 사용자가 표현을 바꾸다가 기록 항목을 잃거나, 디자인 제작 중 주문 옵션까지 동시에 결정해야 하는 부담을 막는다.

### 15.8 원본·사본·완성본 상태

| 상태 | 의미 | 사용자 행동 |
|---|---|---|
| ORIGINAL | 사용자의 기존 기록 또는 기본 템플릿 | 읽기·사본 만들기 |
| DRAFT COPY | 항목을 편집 중인 사본 | 수정·취소·미리보기 |
| PREVIEW | 적용 또는 제작 전 모습 | Digital/Analog 전환 확인 |
| MY TEMPLATE | 이름을 붙인 사용자 제작 템플릿 | 다시 사용·복제·삭제 |
| PRINT READY SAMPLE | 실물 제작을 검토할 수 있는 예시 | 사양 확인·계속 수정 |
| ORDER DRAFT | 주문 구성 예시 | 주문 가능 시점 전에는 저장/문의만 |

`PRINT READY`라는 표현은 실제 인쇄 검수와 파일 규격이 확정된 뒤에만 사용한다. 현재 Prototype에서는 `실물 미리보기` 또는 `제작 준비 예시`로 표기한다.

### 15.9 완성 후 두 갈래 사용

```text
템플릿이 준비됐어요.

┌─ 화면에서 사용 ───────────┐   ┌─ 실물로 만들기 ──────────┐
```

두 경로는 동등하게 보이되, 주문 제작을 선택해야 Digital 사용이 가능한 것처럼 연결하지 않는다.

### 15.10 실물 주문 제작 흐름

주문 제작은 사용자가 만든 `내지 Template`을 `실물 다이어리 구성`과 연결하는 별도 과정이다.

#### 권장 5단계

1. `템플릿 확인`
   - Page 수, 반복 Page, 빈 Page와 필수 항목 확인
2. `다이어리 형태 선택`
   - 크기 후보, 내지 유형, 표지와 쿠션 커버 후보
3. `제작 전 미리보기`
   - 앞면, 펼침, Page 순서, 잘림 안전 영역 확인
4. `구성 요약`
   - 사용한 Template, Page 구성, 선택 사양, 미확정 사항
5. `주문 또는 저장`
   - 실제 Commerce 확정 전에는 `제작 준비본 저장` 또는 `출시 알림 받기`

복잡성 제한:

- 한 단계에서 핵심 결정은 하나만 한다.
- 항상 추천 기본값을 제공하고 건너뛰거나 이전 단계로 돌아갈 수 있게 한다.
- 실물 사양을 Template Editor 안에서 동시에 조정하지 않는다.
- 옵션을 전문 인쇄 용어만으로 표시하지 않고 결과 차이를 Image로 보여준다.
- 가격 변화가 확정되면 옵션 선택 즉시 총액과 변경 이유를 함께 표시한다.

### 15.11 주문 제작에서 반드시 확정할 정보

디자인에 주문 제작 내용을 넣기 전, 다음은 실제 생산 근거가 필요하다.

- 제작 가능한 완성 크기와 안전 영역
- 최소·최대 Page 수와 Page 증가 단위
- 지원 내지와 인쇄 방식
- 양면/단면, 여백, 재단 오차 기준
- 제본 방식과 펼침 범위
- 쿠션 커버의 소재·두께·세탁/관리 정보
- 표지 인쇄·박·자수 등 표현 범위
- 최소 주문 수량
- 예상 제작 기간
- 가격 계산 방식
- 파일 오류와 인쇄 색상 차이 고지
- 주문 취소·수정 가능 시점
- 불량·교환·환불 기준
- 배송 범위와 비용
- 사용자가 올린 Image·Font의 저작권 책임과 확인 절차
- 개인정보와 배송지 보관 정책

이 정보가 확정되기 전에는 `지금 주문하기`, 확정 가격, 제작일 보장, 품질 보장 문구를 사용하지 않는다.

### 15.12 Template Gallery의 시각 방향

목록이 일반 쇼핑몰처럼 보이지 않게 다음 원칙을 적용한다.

- 가격 대신 기록 목적·입력 부담·Page 구조를 먼저 표시
- 썸네일은 단일 표지보다 `펼친 내지`를 중심으로 제작
- 같은 템플릿의 Analog Mockup과 Digital Preview를 한 Card 안에서 전환 가능
- Hover 시 장식 Animation보다 Page 구성 2~3장이 보이게 함
- Selected는 색뿐 아니라 Border, Check, `선택됨` Label로 표시
- 대표 Card 크기를 다르게 해 Editorial Rhythm을 만들되 목록 탐색은 깨지지 않게 함
- `새 템플릿` Ribbon 남발 대신 목적 Group의 첫 Card만 강조

권장 Section Composition:

```text
왼쪽: 큰 Featured Template — 여행의 조각
      펼친 쿠션 다이어리 + Digital Preview Toggle

오른쪽 위: 오늘 한 줄 / 5분 기록
오른쪽 아래: 강의 한 장 / 취향 Collection

하단: 내 템플릿 만들기 — 빈 Page가 서서히 구조를 갖추는 Preview
```

Eyebrow:

`04 · TEMPLATE, MADE FOR YOUR WAY`

Heading:

Body:

CTA:

- Primary: `템플릿 둘러보기`
- Secondary: `내 템플릿 만들기`
- Planned Link: `실물 제작 계획 보기`

시각 요소:

- 왼쪽: 펼친 쿠션 다이어리 Template
- 중앙: 구조 Block이 교체되는 Preview
- 오른쪽: Laptop/Tablet의 동일 Template

### 15.16 모바일 Template Maker

모바일에서는 좌·중앙·우 3열 Editor를 축소하지 않는다.

```text
상단: 단계·템플릿 이름·나가기
중앙: Page Preview
하단 고정: [항목] [구조] [표현]
Bottom Sheet: 선택한 편집 Control
하단 Primary: [미리보기]
```

- Preview 영역은 최소 화면 높이의 45% 확보
- Page 선택은 작은 썸네일 가로 Scroll + 이전/다음 Button 제공
- Drag가 어려운 사용자를 위해 `위로`, `아래로` 이동 Button 제공
- Sheet가 열릴 때 배경 Focus 차단, 닫은 뒤 호출 요소로 복귀
- 변경 취소와 전체 나가기를 구분
- 기기 Keyboard가 열린 상태에서도 완료·취소가 가려지지 않게 함

### 15.17 템플릿 기능 검수 기준

#### 목록

- 사용자가 10초 안에 일상·여행·학습·취향 중 원하는 Group을 찾는가
- 가격이나 인기보다 목적과 입력 부담이 먼저 읽히는가
- Analog/Digital/Both가 색 외 Label로 구분되는가
- 카드가 많아도 `직접 만들기`를 발견할 수 있는가

#### 제작

- 디자인 경험이 없어도 4단계를 설명 없이 완료하는가
- 항목·구조·표현·실물 옵션이 구분되는가
- 처음부터 빈 Canvas를 만나지 않는가
- 현재 편집이 원본인지 사본인지 이해하는가
- 미리보기에서 Analog와 Digital 결과 차이를 확인하는가
- 모바일에서 Drag 없이도 모든 핵심 편집이 가능한가

#### 주문 제작

- 주문 제작이 현재 가능한 기능인지 계획 단계인지 즉시 이해하는가
- Digital 사용과 주문 제작이 서로 강제되지 않는가
- 제작 옵션이 Template 편집을 방해하지 않는가
- 가격·기간·소재처럼 미확정된 내용을 단정하지 않는가
- 제작 전 Page 순서와 잘림 위험을 확인할 수 있는가
- 사용 Image와 Font 권리에 관한 안내가 존재하는가

## 16. 추가 웹디자인 레퍼런스 검토와 최종 적용 작업

| [PIT A PET](https://pitapet.imweb.me/) | 상품명 목록, Logo, 개별 제품 Cut, 동일 제품의 흰 배경/색면 배경 Image | 전체 Section 순서와 Scroll Motion | 중간 |
| [Shituation Comedy](https://shituationcomedy.codextyle.com/) | 대표 Logo, 초대형 Editorial Type, 음식·포춘쿠키·키링 등 투명 Cutout Asset | 전체 배치 순서와 Hover/Scroll 동작 | 중간 |

| [아임웹 Theme](https://imweb.me/theme/) | 공식 설명, 80개 이상 Template 안내, 간단 선택 구조, Hover Preview와 Mobile Preview 안내 | Theme Gallery 전체 Visual과 모든 Filter 동작 | 높음 |

검토 원칙:

- 직접 확인하지 못한 Animation은 추측해서 명세하지 않는다.
- 공개 Asset으로 확인된 Scale·Crop·Object 분리·Device 배치만 시각 근거로 사용한다.
- 레퍼런스의 색상·문구·브랜드 개성을 복제하지 않는다.
- DAMORI 초기 기획과 현재 Cream·Olive Palette에 맞는 원리만 가져온다.

### 16.2 PIT A PET에서 가져올 원리

확인된 공개 Asset에서는 제품 하나를 넓은 여백 속에 분리하고, 동일 오브젝트를 흰 배경과 단색 배경에서 다르게 보여주는 방식이 나타난다. 복잡한 배경보다 제품의 Silhouette와 색이 먼저 읽힌다.

#### DAMORI 적용

- 쿠션 다이어리 하나를 배경에서 명확히 분리한 Product Cut을 제작한다.
- 같은 다이어리를 `Cream 여백 Cut`과 `Olive/Sand 색면 Cut` 두 방식으로 사용한다.
- 목록 Card에서는 다이어리 전체 실루엣을 보여주고, 상세 Section에서는 제본·모서리·속지 Close-up을 보여준다.
- 제품을 작은 Thumbnail로만 반복하지 않고 Featured Object 하나를 크게 사용한다.
- Template Gallery에서 각 Card의 배경색을 무작위로 늘리지 않고 목적 Group별 2~3개의 제한된 Tone만 사용한다.

#### 가져오지 않을 요소

- Time Sale, Best, 가격 할인 Ribbon
- 일반 쇼핑몰식 상품명·가격 중심 Card
- 모든 상품을 동일 비율 Grid로 길게 나열하는 방식
- 밝고 강한 상품색을 DAMORI Palette에 그대로 추가하는 것

#### 적용 위치

1. Hero의 쿠션 다이어리 주 오브젝트
2. Analog Stage의 Featured Diary
3. Template Gallery의 대표 Template Mockup
4. 주문 제작 Preview의 Cover/Binding 선택

### 16.3 Shituation Comedy에서 가져올 원리

확인된 공개 Asset에서는 화면 폭을 크게 점유하는 Serif Typography, 얇고 정교한 Wordmark, 음식과 생활 물건의 Transparent Cutout, 예상 밖의 크기 조합이 강한 시각 기억점을 만든다.

#### DAMORI 적용

- Section Intro 중 1~2곳에서만 제목을 화면 폭의 55~75%까지 크게 사용한다.
- `PAPER / SCREEN`, `KEEP / RETURN`, `MY TEMPLATE` 같은 짧은 영문 단어를 배경형 Editorial Type으로 제한 사용한다.
- 다이어리, Bookmark, 펜, 종이 조각을 배경 없이 분리한 Cutout으로 만들어 Section Grid를 일부 침범하게 한다.
- 동일한 3 Card 반복 대신 큰 Type와 작은 Detail Object를 병치한다.
- 예상 밖의 Object 연결은 `종이 Bookmark가 Digital Window의 Tab으로 이어지는 장면`처럼 브랜드 의미가 있을 때만 사용한다.

#### DAMORI식 절제

Shituation Comedy의 과장과 유머를 그대로 적용하면 DAMORI의 차분한 기록 태도가 무너질 수 있다. 따라서 다음 제한을 둔다.

- 초대형 Type는 한 화면에 한 문장만 사용한다.
- Cutout Object는 Section당 1~2개로 제한한다.
- 겹침이 본문과 CTA를 가리지 않게 한다.
- 강한 Black/White 대비 대신 현재 Cream·Olive·Ink 대비를 유지한다.
- 기발함보다 기록의 물성과 사용 맥락을 우선한다.

#### 적용 위치

1. Analog/Digital 비교 Section의 배경 Type
2. Template Maker 진입 Section의 빈 Page→구조 Page 전환
3. 다시 이어가기 Section의 대형 Bookmark Cutout

### 16.4 LUSH App Redesign에서 가져올 원리

확인된 Cover는 넓은 자연 풍경을 배경으로 두 대의 Smartphone을 크고 비스듬하게 배치하고, 실제 App Home 화면과 Brand Message를 한 장면에 결합한다. Device가 단순 장식이 아니라 Digital 경험의 증거로 작동한다.

#### DAMORI 적용

- Hero의 노트북·Tablet·Mobile 화면에 실제 DAMORI Sample UI를 넣는다.
- 빈 Device Mockup이나 검은 Rectangle로 Digital을 대신하지 않는다.
- Digital Stage의 중심 Device는 한 대, 보조 Device는 한 대까지만 사용한다.
- Device 각도를 서로 다르게 해 깊이를 만들되 텍스트를 읽을 수 있는 범위를 유지한다.
- Digital UI 안에는 여행·학습·취향·노트 기록 중 3개를 실제 제목과 Preview로 보여준다.
- 배경은 자연 풍경을 그대로 복제하지 않고 책상·창가·천 소재처럼 DAMORI의 기록 생활에 맞는 환경을 사용한다.

#### 주의

- 해당 Behance 프로젝트는 웹사이트가 아니라 App Redesign이므로 Website IA의 근거로 사용하지 않는다.
- 녹색 자연 풍경과 LUSH Logo Style을 시각적으로 복제하지 않는다.
- Device Mockup이 다이어리보다 커져 Digital이 우위처럼 보이지 않게 한다.
- App UI가 실제 저장·검색·동기화 기능을 제공한다고 오해되지 않도록 SAMPLE Label을 유지한다.

#### 적용 위치

1. Main Hero의 Digital Layer
2. Digital Stage의 Laptop/Tablet Workspace
3. Template Dual Preview의 Mobile/Tablet 결과

### 16.5 아임웹 Theme에서 가져올 원리

아임웹 공식 페이지와 도움말에서는 다수의 Template을 제공하면서도 사용자가 Template을 선택하고, 개설 전 Preview와 Mobile 결과를 확인할 수 있게 한다. 핵심 가치는 전문 기능의 수가 아니라 `고민 없이 선택하고 시작할 수 있음`이다.

#### DAMORI 적용

- Template Gallery 진입 즉시 대표 Template 6개를 보여준다.
- Preview를 적용과 분리한다.
- Preview 상단에 `Analog / Digital / Mobile` 결과 전환을 제공한다.
- Template을 선택해도 나중에 구조와 표현을 바꿀 수 있음을 안내한다.
- 처음부터 모든 Filter를 펼치지 않고 목적 Chip 6~8개만 노출한다.
- Template Maker는 4단계를 유지하고 선택 후 즉시 Sample 결과를 보여준다.

#### 가져오지 않을 요소

- Website·쇼핑·예약 등 범용 Category
- 80개 이상을 그대로 노출하는 대규모 Gallery
- Template 선택과 동시에 기존 작업을 초기화하는 흐름
- 회원가입·요금제 선택을 Template Preview보다 먼저 요구하는 흐름

### 16.6 네 레퍼런스의 통합 판정

각 레퍼런스가 DAMORI에서 맡을 역할을 하나로 제한한다.

| 레퍼런스 | 맡길 역할 | DAMORI 결과 |
|---|---|---|
| PIT A PET | Object 분리와 Product Focus | 큰 쿠션 다이어리 Cut과 제한된 색면 |
| Shituation Comedy | Typography Scale과 Cutout Surprise | Section별 강한 기억점과 Grid Break |
| LUSH App Redesign | Environment + Device + Real UI | Digital 활용이 분명한 Hero와 Preview |
| 아임웹 Theme | 쉬운 Template 선택과 사전 Preview | 복잡하지 않은 Gallery와 Maker 진입 |

이 네 스타일을 한 화면에서 동시에 사용하지 않는다.

- Hero: LUSH식 Environment/Device 원리 + PIT A PET식 Object Focus
- Analog/Digital: PIT A PET식 분리 Cut + 실제 DAMORI UI
- Section Intro: Shituation Comedy식 큰 Type를 제한 사용
- Template Gallery: 아임웹식 쉬운 선택 + DAMORI의 펼친 내지 Preview

| 전 화면 검수 | 예시 문장 두 개만 고치는 것이 아니라 Heading·Card Title·Button·Badge·본문을 360·320·280px에서 전수 확인한다. | Desktop 한 폭만 확인하고 완료 처리 |
| Hero 중심 소재 | 일반 메모지가 아니라 쿠션 커버의 두께·둥근 모서리·봉제 또는 눌림, 불렛저널 내지 구조가 보이는 다이어리를 주인공으로 둔다. | 평평한 흰 종이만으로 다이어리를 대체 |
| 로그인·복귀 | 오른쪽 Utility에는 `로그인`을 두고, 기존 작업 사용자는 최근 기록·템플릿으로 이어지는 진입을 제공한다. HTML에서는 실제 인증처럼 오해되지 않도록 `PROTOTYPE`을 표시한다. | 로그인과 `한 줄 시작하기`를 같은 강도의 Primary CTA로 경쟁시키기 |
| 시각적 단조로움 완화 | Palette는 유지하고 Section별 Scale·Crop·Object Layer·편집 리듬을 다르게 한다. | 색상 수를 늘리거나 동일 Card Grid만 반복 |

상단바의 최종 구조는 다음 한 줄로 고정한다.

```text
[배경 없는 DAMORI Logo]  [중앙 Menu 전용 반투명 Rounded Rectangle]  [배경 없는 로그인 / Utility]
```

중앙 Menu는 완전한 알약형 `999px` Radius를 기본값으로 사용하지 않는다. 첨부 이미지와 같이 낮고 긴 형태를 유지하되 DAMORI의 차분한 인상을 위해 `12~18px` Radius 후보를 우선 검수한다. Scroll 전에는 Hero 위 Overlay, Scroll 후에는 읽기 가능한 Solid 또는 Blur 상태로 전환할 수 있다.

#### 정보 구조

- 한 장은 하나의 평가 항목을 중심으로 한다.
- 웹 화면 전체를 한 장에 그대로 옮기지 않고 `Token → Anatomy → Variant → Usage → Avoid` 순서로 설명한다.
- 8~13장은 원본 평가 항목명을 유지하면서 DAMORI 기능에 맞게 의미를 재해석한다.
- v3의 신규 기능은 기존 컴포넌트의 Variant 또는 Pattern으로 연결한다. 별개의 장식 화면으로 대체하지 않는다.

#### 시각 완성도

- v2의 정교한 선, 숫자 표기, 상태 비교, 실제 이미지와 Paper Texture를 유지한다.
- 배경을 단순한 CSS 도형만으로 채우지 않는다. Diary, Paper, Device, Bookmark, Pen 등 브랜드 소재가 필요한 장에는 실제 Material Image 또는 정교한 Mockup을 사용한다.
- Reference의 고유 Palette를 가져오지 않고 DAMORI Token으로 재해석한다.
- 대형 Type는 Cover와 Editorial Composition에만 강하게 사용한다.
- 모든 장을 같은 Card Grid로 만들지 않고 Anatomy, Scale, Comparison, Flow, Composition을 장별로 다르게 사용한다.

#### 텍스트 정확성

- 한글 제목·본문·치수·상태명은 Browser 또는 Vector 기반으로 렌더링한다.
- 생성형 이미지 안에 한글 설명을 직접 생성하지 않는다.
- `word-break: keep-all`, 의미 묶음 Span, 280px 최소 폭에서 고립 글자 여부를 검수한다.
- 영문 상태명과 한글 영향 설명을 함께 제공한다.

### 17.4 v3 이미지 제작 순서

1. v2 13장을 Reference Layer로 고정한다.
2. 각 장에서 유지할 Grid·Token·정보 밀도를 표시한다.
3. 17.2 표의 보완 내용만 장별로 추가한다.
4. 1~7장 Foundation과 Component를 먼저 확정한다.
5. 8~12장의 상태·Pattern이 1~7장의 Token을 사용하는지 확인한다.
6. 13장에서 Header·Hero·Compare·Template·Resume가 같은 System으로 보이는지 통합 검수한다.
7. PNG 13장을 1586×992px로 출력한다.
8. 전체 Contact Sheet와 개별 원본 크기를 모두 확인한다.
9. 승인된 13장을 기준으로만 최종 v3 HTML을 제작한다.

### 17.5 v3 금지 사항

- v2를 무시하고 13장을 새로운 Flat CSS Board로 다시 만들지 않는다.
- 개선계획의 문장을 한 장에 많이 넣어 시각적 완성도를 낮추지 않는다.
- Header·Hero·Template·Login 화면이 원본 평가 항목을 대신하게 하지 않는다.
- 전체 Header를 하나의 Capsule로 만들지 않는다.
- Diary 대신 일반 Memo Paper만 Brand Object로 사용하지 않는다.
- Analog와 Digital을 Text Column만으로 비교하지 않는다.
- Template Maker를 전문 편집 도구처럼 복잡하게 만들지 않는다.
- 미구현 Login·Sync·Payment·Order를 Available 상태로 표시하지 않는다.
- Reference마다 다른 Style을 한 화면에 혼합하지 않는다.

### 18.3 상단바 3상태 합격 기준

#### Hero Overlay

- Header 전체에는 공통 Card Background·외곽 Border·Rounded Container를 사용하지 않는다.
- Logo는 왼쪽, 중앙 Menu Surface는 가운데, Login/Utility는 오른쪽에 분리한다.
- 중앙 Menu만 Radius 12~18px, 높이 40~48px, Blur 8~16px 후보를 적용한다.
- Hero 상단에 80~120px Quiet Area를 확보해 Diary·손·Device Detail과 겹치지 않게 한다.
- 이미지 밝기와 관계없이 Text 대비 4.5:1 이상을 확보하거나 전용 Scrim을 사용한다.

#### Scroll

- 첫 화면 이후 Solid 또는 Blur Surface로 전환하되 위치와 높이가 튀지 않게 한다.
- 현재 Section은 Underline·작은 Dot·낮은 대비 Fill 중 한 방식으로 표시한다.
- `prefers-reduced-motion`에서는 위치 이동 없이 상태를 전환한다.

#### Mobile Menu

- 중앙 Menu를 제거하고 Logo·Login·44×44px Menu Button을 유지한다.
- 280px에서 충돌하면 Login을 Menu Sheet의 첫 항목으로 이동한다.
- ESC 닫기, Focus Trap, 닫은 뒤 Menu Button Focus 복귀를 제공한다.

### 18.4 문장·문단 가독성 합격 기준

| 문장 | Desktop | Mobile | 금지 |
|---|---|---|---|
| 기록은 남고, 방식은 달라져도 돼요. | `기록은 남고,` / `방식은 달라져도 돼요.` | 같은 2행 우선, 320px 이하에서 `방식은` / `달라져도 돼요.` 허용 | `요.` 단독 행 |
| 하나만 남겨도 기록은 시작됩니다. | 1~2행 + Index/Caption | `하나만 남겨도` / `기록은 시작됩니다.` | 우연한 한 단어 고립 |
| 종이와 화면을 같은 기준으로 비교해요. | `종이와 화면을` / `같은 기준으로 비교해요.` | 같은 의미 묶음 | `비교해요.`·조사 단독 행 |
| 멈춘 자리에서 다시 이어가도 괜찮아요. | 2~3행 | `멈춘 자리에서` / `다시 이어가도 괜찮아요.` | `괜찮아요.`의 우연한 고립 |

- 본문 16px 이상, Line-height 1.6 이상, 권장 폭 55~65ch를 사용한다.
- Intro 설명 45~58ch, Card 설명 24~38ch 후보로 제한한다.
- `word-break: keep-all; overflow-wrap: break-word;`를 기본으로 한다.
- 의미 구절에만 제한적으로 `nowrap`을 사용하고 280px Overflow를 확인한다.
- 마지막 행이 한 글자·구두점만 남거나 본문 폭의 약 15% 이하이면 폭·문구·Tracking을 재조정한다.
- Button Label은 줄바꿈하지 않으며 44×44px Hit Area를 유지한다.

### 18.5 Hero·Diary·Digital Visual 합격 기준

1. H1과 Cushion Diary를 공동 주인공으로 둔다.
2. Digital Device에는 실제 DAMORI Sample UI를 넣는다.
3. Bookmark·Pen·Paper Fragment는 보조 Object로 제한한다.
4. Diary에는 커버 두께·둥근 모서리·봉제선/눌림 중 최소 2개, 제본/펼침, Dot Grid·Index·Rapid Log·Page Marker 중 최소 2개가 보여야 한다.
5. 일반 메모지·얇은 종이 묶음·Tablet Case처럼 보이면 실패다.
6. Digital은 빈 검은 사각형으로 대체하지 않고 실제 기록 Sample UI 최소 2종과 정확한 저장 상태를 보여준다.
7. Device가 Diary보다 커서 Digital만 중심으로 보이지 않게 한다.

### 18.6 Analog/Digital 비교 합격 기준

- 동일한 기록 목적을 두 매체에서 비교한다.
- Analog에는 펼친 Diary, Writing Tool, Binding/Cover Detail 중 최소 2개를 표시한다.
- Digital에는 Laptop/Tablet/App Window와 실제 UI를 표시한다.
- 시작 속도·수정·보관·휴대·감각·재구성 중 최소 4개 기준을 사용한다.
- 어느 한쪽도 정답 또는 상위 방식으로 표현하지 않는다.
- Text Column 두 개뿐이고 물체·화면 차이가 없으면 실패다.

### 18.7 Template·Maker·Order 합격 기준

- Gallery는 대표 Template 6개 이내와 일상·노트 필기·여행·학습·취향·일정/할 일 목적을 보여준다.
- Card는 표지만이 아니라 펼친 내지 또는 Page 구조 Preview를 보여준다.
- Preview와 적용을 분리한다.
- Simple Maker는 `목적 → 항목 → 구조 → Preview`의 4단계를 넘지 않는다.
- 원본·사본·미리보기·내 템플릿 상태를 명시한다.
- 완성 후 Digital 사용과 Physical Order를 두 갈래로 분리한다.
- 주문·결제·배송이 미구현이면 `ORDER PLANNED`만 표시하고 구매 Primary CTA를 사용하지 않는다.

### 18.8 Login·Resume 합격 기준

| 상태 | 문구와 행동 | 판정 |
|---|---|---|
| 비로그인 | `로그인` / `한 줄 시작하기` | Login은 Utility, 시작은 Hero Primary |
| 인증 미구현 HTML | `로그인 화면 예시 · PROTOTYPE` | 실제 인증 성공처럼 표현 금지 |
| Local Draft | `이 기기에 남은 기록 이어가기` | 저장 위치와 영향 안내 |
| 로그인 사용자 설계안 | 최근 기록·최근 Template·마지막 수정 | 구현 전 Sample/Planned 표시 |
| Sync 미구현 | `동기화 준비 중` | Cloud Saved 표시 금지 |

### 18.9 스타일가이드 13장 반영 방식

- v3 정보를 v2 이미지 위 작은 주석 Panel만 추가하는 방식으로 완료하지 않는다.
- 1~12장은 기존 Grid와 완성도를 유지하며 실제 Token·Component Variant를 본문 구성에 통합한다.
- 5장은 Overlay Header Safe Area와 반응형 간격 Diagram을 실제 Scale 예시로 보여준다.
- 6장은 전체 Header Box와 중앙 Menu 전용 Rounded Surface의 `Do / Avoid` 비교를 포함한다.
- 13장은 Header·Hero·Analog/Digital·Template·Login/Resume를 실제 Page Pattern Miniature로 보여준다.

### 18.10 최종 검수 기록

`검수 ID / 대상 / 화면 폭 / 확인 내용 / 결과(PASS·REVISE·HOLD) / 수정 위치 / 증거 파일 / 비고` 형식으로 기록한다.

최종 완료에는 `MD 확정`, `Styleguide PASS`, `HTML PASS`가 모두 필요하다. 하나라도 `REVISE`이거나 근거가 없으면 v3 완료로 표시하지 않는다.
