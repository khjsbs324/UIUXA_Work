# 다모리 사용자·가상 클라이언트 요구사항 통합본

문서 상태: `CANONICAL_WITH_BACKLOG`

## 1. 수량 해석

자료에는 4개 VCG, 5개 상세 VC, 7명 핵심 VC, 50명, 51명이라는 서로 다른 집계가 존재한다. 이는 조사 단계와 확장 방식이 다른 자료를 합치면서 생긴 차이다.

- 검증된 요구 추적 기준: V1의 4개 VCG와 23개 요구사항
- 화면 시나리오에 사용할 대표 사용자: 은재·지안·하람·소담·태오·나린·이준을 중심으로 필요한 경우 다온·여울 보조
- `VC-01~50/51 전수 반영` 주장은 원문 보존 대상으로만 두며 검증 완료 사실로 사용하지 않음

## 2. 승인된 공통 요구

1. 목적과 상황에 맞게 기록 구조를 조정할 수 있어야 한다.
2. 기록 목적별 정보와 표현 방식을 허용해야 한다.
3. 핵심 기능과 취향 표현의 우선순위를 구분해야 한다.
4. 특정 매체·형식·스타일을 강요하지 않아야 한다.
5. 사용 전에 제품과 기록 방식의 적합성을 판단할 근거를 제공해야 한다.
6. 기록 길이와 완성도를 강요하지 않고 시작 부담을 낮춰야 한다.

## 3. 핵심 요구군

| 요구군 | 주요 요구 | 상태 |
|---|---|---|
| Analog 적합성 | 구조·분량·장문 공간·필기 조건·물성·구성 비교 | 승인, 실제 성능은 미검증 |
| Digital 시간 흐름 | 하루·주간 흐름과 중요도 확인 | 승인 |
| 알림·외부 연동 | 시점·빈도·채널·권한 검증 | 조건부/HOLD |
| 작은 시작 | 사진·한 줄 등 낮은 부담의 시작 | 후보에서 MVP 검증 대상으로 승격 |
| 표현 자산 | 기능을 방해하지 않는 미리보기·재사용 | 후보/프로토타입 |
| 중단 후 복귀 | 비난 없이 하기·보류·나누기 선택 | 브랜드 핵심, 구현은 프로토타입 |
| 보존·연속성 | Local·Pending·Conflict·Recovery 상태 이해 | 정보/프로토타입, 실제 동기화 HOLD |
| 접근성 | 키보드·스크린리더·색 외 상태·44px | 필수 설계 기준 |

## 4. 충돌 보존 원칙

- 장문과 짧은 기록을 하나의 평균 흐름으로 합치지 않는다.
- Analog와 Digital은 자동 연동하지 않고 독립 선택을 기본으로 한다.
- 높은 자유도에는 적합성을 판단할 초기 안내를 제공한다.
- 표현 자산은 기능과 원본을 가리지 않는다.
- 알림, 외부 일정, 다기기 연속성, 커뮤니티와 상거래는 별도 검증 전 활성 기능으로 만들지 않는다.

## 5. 시나리오 우선순위

1. 방식 비교와 추천 근거 확인
2. Analog 조건과 Digital 목적의 독립 탐색
3. 가장 작은 단위로 시작
4. 템플릿 구조와 표현 자산 비교
5. 중단 후 다시 이어가기
6. 상태·제한·보존 범위 이해
