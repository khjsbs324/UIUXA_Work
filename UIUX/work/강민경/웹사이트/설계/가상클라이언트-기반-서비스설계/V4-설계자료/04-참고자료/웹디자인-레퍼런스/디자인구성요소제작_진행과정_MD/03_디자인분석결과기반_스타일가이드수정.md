## 1. 전체 비교 결론

### 1.1 공통 기반

기존 스타일 가이드와 사용자의 선호 디자인은 다음 기반을 공유한다.

- Modern
- Clean
- Structured
- 명확한 정보 위계
- 사용성 중심
- 과도하지 않은 Effect
- 역할에 따른 색상과 상태 구분

기존 스타일 가이드는 사용자 취향과 반대되는 체계가 아니다. Foundation과 Component 구조는 안정적이지만, 시각적 개성과 웹페이지 표현 범위가 부족한 상태에 가깝다.

### 1.2 전체 수정 목표

> 기존 디자인 시스템의 구조와 접근성은 유지하고, Typography·Image·Graphic·Editorial Layout·Section Variation 중 검증된 요소를 추가해 정돈된 구조 위에 통제된 Visual Character를 만든다.

### 1.3 유지 우선 항목

1. Primitive → Semantic → Component 연결 구조
2. Foundation 중심의 디자인 시스템 방식
3. 역할 기반 Typography 계층
4. 4/8px 중심 Spacing Token
5. Component Anatomy와 Variant/State 구조
6. Success·Warning·Danger의 의미 체계
7. Focus, 최소 높이, Touch Area 등 접근성 기준
8. 재사용 가능한 Component 구조
9. 기능 화면의 명확한 정보 위계
10. 상태를 예측할 수 있는 상호작용 원칙

### 1.4 수정 가능성이 높은 항목

#### 우선순위 높음

- Brand Color와 Accent 사용 비율
- Typography 표현 방식
- Card 표현 방식과 페이지 전체 Card 의존도
- Layout과 Section Rhythm
- Image 사용 방식

#### 우선순위 중간

- Radius와 Shape 역할
- Surface·Border·Shadow
- Button Visual
- Graphic 표현 범위
- Motion·Interaction 원칙

#### Foundation 결정 후 파생 적용

- Badge
- Progress
- Question Number
- Quiz Option
- Timer

## 2. 확정 수준과 미확정 항목

### 2.1 신뢰도가 높은 판단

| 판단 | 처리 |
|---|---|
| 기존 시스템 구조의 유지 가치가 높음 | 제작 전제 |
| Visual Character 보완이 필요함 | 수정 목표 |
| Typography가 핵심 수정 후보임 | 1순위 검토 |
| Card는 삭제보다 역할 조정이 적절함 | 1순위 검토 |
| Section Layout 변화가 필요함 | 웹페이지 표현 원칙으로 확장 |
| Image 활용 가능성이 높음 | 역할과 사용 규칙 정의 |
| 상태색의 Semantic 의미를 보존해야 함 | 필수 조건 |
| 선호 디자인을 Minimal 하나로 정의할 수 없음 | 단일 스타일 강제 금지 |
| Modern + Clean은 기본이며 그 위에 Character가 필요함 | 전체 방향 |

### 2.2 현재 확정하면 안 되는 항목

- 최종 Brand Color와 정확한 HEX
- Warm/Cool 최종 방향
- 최종 Font Family와 Serif 사용 여부
- Rounded/Sharp 최종 비율
- Card Radius와 Shadow 값
- Motion 강도
- Graphic·Illustration Style
- Photography 우선순위
- Hero 형태
- 정확한 Section Layout
- 특정 레퍼런스 하나를 메인 방향으로 선택하는 것

이 항목은 초안에서 후보를 비교한 뒤 결정한다. 본 문서에는 확정값처럼 기록하지 않는다.

### 2.3 원본 확인이 필요한 항목

- 실제 Primitive HEX
- Semantic → Primitive Binding
- 실제 Figma Variable 명칭
- Button·Badge·Progress·Question Number·Quiz Option의 정확한 Property명
- Auto Layout 구조
- Light/Dark Mode 실제 적용 범위
- Responsive Template 실제 존재 여부
- Foundation Token과 Component Instance의 실제 연결 관계

JPG만으로 확인할 수 없는 정보는 추론값으로 표시하며 구현 완료로 간주하지 않는다.

## 3. 수정 후 시스템 구조

```text
Primitive Token
→ Semantic Token
→ Foundation
→ Component
→ State / Variant
→ Visual / Editorial Rule
→ Interaction Rule
→ Web UI
```

Visual·Editorial·Interaction 규칙은 기존 Component 체계를 대체하지 않는다. 기능을 안정적으로 유지하면서 웹 표현 범위를 확장하는 층으로 사용한다.

### 3.1 수정 범위 A–E

| 축 | 내용 | 13장 스타일 가이드 | 웹디자인 단계 |
|---|---|---|---|
| A. Foundation Visual | Color·Typography·Radius·Effect | 직접 수정 | 적용 후 검증 |
| B. Component Visual | Card·Button·Quiz Option·Badge 등 | 직접 수정 | 실제 흐름에서 검증 |
| C. Page Expression | Section Rhythm·Density·Layout Variation | 일부 페이지에서 시범 | 핵심 적용 영역 |
| D. Visual Media | Image·Illustration·Graphic | 역할과 원칙 제시 | 실제 자산으로 검증 |
| E. Interaction | Hover·Focus·Transition·Scroll Motion | 정적 상태와 원칙 제시 | 동작으로 검증 |

기존 13장에 Image·Motion 페이지를 무조건 추가하지 않는다. A·B는 13장에 직접 반영하고 C·D·E의 상세 구현은 웹디자인 초안에서 검증한다.

## 4. Foundation 수정 기준

### 4.1 Color

#### 유지

```text
Primitive Color
→ Semantic Color
→ Component State
```

- Success·Warning·Danger는 브랜드 Accent와 분리한다.
- Focus Color는 브랜드색과 별도로 모든 배경에서 식별 가능해야 한다.
- Correct·Incorrect·Review는 색 외에 Icon·Label·Shape를 함께 사용한다.

#### 수정 검토

- Navy·Blue가 전체 인상을 지배하는 비율
- Canvas·Surface·Subtle Surface 관계
- Neutral Base와 Accent의 면적 비율
- Brand·Selected·Focus·Info·Success의 역할 충돌

#### 초안 비교 기준

| 항목 | 비교 질문 |
|---|---|
| Base | Neutral, Warm Neutral, Cool Neutral 중 어떤 기반이 선호와 사용성에 적합한가? |
| Accent | 단일 Accent가 CTA와 핵심 정보에 충분히 집중되는가? |
| Surface | Card 없이도 Section과 정보 그룹이 구분되는가? |
| Status | 브랜드색과 Success·Warning·Danger가 혼동되지 않는가? |
| Contrast | 일반 텍스트 4.5:1, 큰 텍스트·비텍스트 경계 3:1을 충족하는가? |

특정 색상이나 HEX는 이 문서에서 확정하지 않는다.

### 4.2 Typography

#### 유지

- Display/Large
- Heading/1~3
- Title/Large·Medium
- Body/Large·Medium·Small
- Label/Large·Medium
- Caption
- Timer

기존 13개 역할은 보존한다.

#### 수정 검토

- Display 크기와 표현력 강화
- Heading 간 크기·Weight 대비 강화
- UI Type과 Display Type 역할 분리 가능성
- Serif/Sans 대비 또는 표현력 있는 Sans 단일 체계 비교
- Typography를 단순 텍스트가 아닌 Section 구성 요소로 사용하는 방법

#### 검증 규칙

- 기능 Label·상태·입력은 가독성을 우선한다.
- 큰 Typography는 짧은 제목과 핵심 Section에 제한한다.
- 한글 줄바꿈, 행간, Button 높이, Card 밀도를 함께 검증한다.
- Font Family와 크기값은 조판 비교 전 확정하지 않는다.

### 4.3 Spacing

기존 `0, 4, 8, 12, 16, 20, 24, 32, 40, 48, 64px` Core Scale을 유지한다.

```text
Component Spacing: 내부 Padding과 요소 간격
Section Spacing: 콘텐츠 그룹과 화면 리듬
Page Spacing: Container Margin·Hero·페이지 전환
```

Component Spacing은 기존 규칙을 유지하고, Section·Page Spacing은 더 큰 단위로 확장한다. 정확한 값은 Desktop·Tablet·Mobile 비교 후 정한다.

### 4.4 Sizing

- 32·40·48px Control 구조는 유지 우선이다.
- 모든 조작 대상은 최소 44×44px Hit Area를 확보한다.
- Question Number의 보이는 크기가 40px이면 Hit Area를 별도로 44px 이상 확보한다.
- Quiz Option 최소 높이 64px를 유지한다.
- 기능 Control을 취향 때문에 임의 확대하지 않고 Hero·Image·Heading·Section Scale을 확장한다.

### 4.5 Radius와 Shape

기존 `0, 4, 8, 12, 16, 24, full` Token은 유지하고 역할별 사용 범위를 재검토한다.

| 영역 | 검토 방향 |
|---|---|
| Button·Input·Quiz Option | 조작성과 상태 인지 우선 |
| Badge·Question Number | 짧은 상태와 숫자 인지 우선 |
| Card·Panel | 콘텐츠 그룹화에 필요한 만큼만 사용 |
| Image·Editorial Section | Sharp·Small Radius·다른 Frame 허용 |
| Modal·Overlay | 상위 Layer가 구분되는 형태 |

Rounded 자체를 제거하지 않으며 모든 요소에 같은 Radius를 반복하지 않는다.

### 4.6 Surface와 Effects

```text
여백과 정렬
→ Background Tint
→ Border
→ Image·Typography 대비
→ 필요한 경우에만 Shadow
```

- Card/Floating/Overlay의 3단계 구조는 유지 가능하다.
- 모든 Card에 Shadow를 자동 적용하지 않는다.
- Border·Surface·Image·Overlap·Scale로 Depth를 함께 만든다.
- Shadow 값은 최종 Color와 Surface가 정해진 후 검증한다.

## 5. Component 수정 기준

Component는 구조보다 Visual Layer를 우선 수정한다. 실제 Property명이 확인되지 않은 상태에서는 기존 분석상의 명칭과 구현 명칭을 구분한다.

### 5.1 Button — 24 Variants 유지

- Size 2 × Style 3 × State 4 구조 유지
- Primary·Secondary·Danger 행동 위계 유지
- Focus 2px 이상, 최소 높이와 Touch Area 유지
- Brand Color, Radius, Typography, Border, Hover, Icon 사용 방식을 비교
- Disabled가 단순 저대비 텍스트가 되지 않게 검증

### 5.2 Badge — 10 Variants 유지

- Size 2 × Tone 5 구조 유지
- Neutral·Brand·Success·Warning·Danger 의미 분리
- Color·Typography·Radius Foundation 결과를 반영
- 전체 스타일을 결정하는 1차 수정 대상은 아님

### 5.3 Progress — 10 Variants 유지

- Value 5 × Tone 2 구조 유지
- 진행값과 완료 의미를 구분
- Brand Tone 변경은 Semantic 결과에 따라 적용
- 색 외에 퍼센트·단계·완료 Label을 제공하는 예시 검토

### 5.4 Question Number — 12 Variants 유지

- Size 2 × State 6 구조 유지
- 응답·현재·채점·검토 상태의 인지력 보존
- Color·Radius·Typography 결과를 반영
- 최소 Hit Area를 44×44px로 통일
- 실제 State Property명은 원본 확인 전 확정하지 않음

### 5.5 Quiz Option — 8 States 유지

- Default·Interaction·Focus·Selected·Correct·Incorrect·Disabled·Review 구조 유지
- 최소 높이 64px 유지
- Selected·Correct·Incorrect·Review를 색만으로 구분하지 않음
- Prefix와 본문의 간격, 한글 줄바꿈, Focus 복합 상태 검증
- 구조적 변경보다 Color·Shape·Typography·Hover·Focus를 개선

### 5.6 Timer — 3 States 유지

- Default·Warning·Danger 의미 유지
- Timer 전용 숫자 가독성 유지
- 색 외에 문구나 Icon으로 위험 상태 보조
- 점멸·흔들림 사용 금지

### 5.7 Card — 4 Variants 유지, 사용 비중 조정

- Base·Stat·Explanation·Result 구조 유지
- 기능적 정보 그룹에는 Card를 유지
- 웹페이지 전체를 동일 Card Grid로 채우지 않음
- Border·Surface·Typography·Image로 Variant 차이를 검토
- Full-width Section·Image/Text Split·Typography Section과 혼합
- Card Radius와 Shadow는 초안 비교 후 결정

## 6. Layout·Image·Graphic·Motion 확장 기준

### 6.1 Layout

- Foundation 페이지는 비교 가능한 Grid와 시작선을 유지한다.
- 웹디자인에서는 기본 Grid 안에서 Section마다 Span·Scale·정렬을 변화시킨다.
- Full-width, Split, Text-led, Image-led, Asymmetric 구성을 선택적으로 사용한다.
- 실험적 Layout을 이유로 정보 순서와 반응형 구조를 해체하지 않는다.

### 6.2 Image

Image를 단순 Thumbnail이 아니라 역할별 Visual Media로 검토한다.

- Hero Image
- Full-width Image
- Editorial Image
- Product/Content Image
- Section Background
- Graphic Asset

13장에 Image Foundation 페이지를 새로 추가하는 것은 현재 확정하지 않는다. 표지·Getting Started·Card 페이지에서 사용 원칙을 제한적으로 보여주고 실제 Crop과 반응형은 웹디자인 초안에서 검증한다.

### 6.3 Graphic과 Illustration

- 특정 Graphic Style을 바로 확정하지 않는다.
- 브랜드 또는 콘텐츠의 개성을 만드는 보조 수단으로 사용한다.
- 기능 Component보다 먼저 보이거나 상태 인지를 방해하면 강도를 낮춘다.
- 레퍼런스의 로고·캐릭터·일러스트·구성을 직접 복제하지 않는다.

### 6.4 Motion과 Interaction

Motion의 사용 가능성은 높지만 적정 강도는 미확정이다.

적합한 목적:

- 정보 등장
- 상태 Feedback
- Section 전환
- 시선 유도
- Navigation·Image·Text Transition

금지:

- 모든 Section에 반복되는 Animation
- 목적 없는 Parallax와 자동 재생
- Animation만으로 상태 전달
- Reduced Motion에서 정보가 사라지는 구성

정적 스타일 가이드에는 상태와 원칙만 기록하며 실제 Duration과 Scroll Motion은 웹디자인에서 검증한다.

### 6.5 핵심 레퍼런스와 수정 영역 연결

5. 스타일 가이드 최종안 기반 웹디자인 최종 제작
6. 디자인 기획 설명과 제작 과정을 포트폴리오 프로세스로 정리

초안과 최종안은 13장 모두 달라질 필요가 없다. 최소 3장은 비교 가능한 차이가 있어야 하며 우선 후보는 Colors, Typography, Card다. 표지, Radius & Effects, Button, Quiz Option은 대안 후보로 둔다.

## 12. 완료 조건

이 문서는 다음 조건을 충족하면 완료로 본다.

- 기존 스타일 가이드와 LOVE 선호 분석의 비교 결과가 수정 기준으로 연결됨
- 유지·수정·추가 검토·미확정 항목이 구분됨
- Foundation과 7개 Component의 수정 경계가 정의됨
- 13장 영향도와 제작 우선순위가 정의됨
- Layout·Image·Graphic·Motion의 적용 범위가 구분됨
- 핵심 LOVE 레퍼런스와 수정 영역의 연결 근거가 기록됨
- 13장별 Before·Change·Expected Effect·성공 기준이 정의됨
- 초안 출력 규격과 후보 평가 방식이 정의됨
- 접근성, 원본 확인 제한, 보호 규칙이 포함됨
- 브랜드 정의서의 내용이 반영되지 않음
- 다음 결과물이 제출물 1번 `스타일 가이드 초안`임이 기록됨

본 문서 검수 완료 후에만 보호 대상과 분리된 신규 파일에서 스타일 가이드 전체 수정을 시작한다.
