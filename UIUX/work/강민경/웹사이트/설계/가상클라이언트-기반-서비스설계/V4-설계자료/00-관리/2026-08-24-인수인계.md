## 1. 현재 상태 요약

V4의 3 Page·16 Section Skeleton과 새 대표안 MD는 유지할 가치가 있다. Source → Master Mapping과 상세 명세 제작까지 완료했으며, 해결 불가능한 Source Conflict는 없다.

새 대표안은 내용과 추적성 면에서 기존 V2보다 발전했다. 최초 SVG의 세로 길이와 정보 밀도를 개선한 보정 MMD/SVG도 제작했으며 실제 Edge 렌더링으로 검토했다. 보정안은 기존 대표안보다 명확히 읽기 쉬워졌지만, Page 열 순서와 보조 영역 배치에 소폭 보정 여지가 있어 아직 V2에는 반영하지 않는다.

## 10. 시각 검토 핵심 결과

### 정보 밀도

- 48개 정보 그룹은 MD에서 유효하다.
- SVG는 Source, Priority, 상태, 콘텐츠·기능 문장이 한 Node에 함께 노출되어 과밀하다.
- SVG 유지: Page, Section, 목적, 핵심 정보 그룹, 대표 P1, 주요 관계
- SVG 축약: Source ID, 긴 콘텐츠·기능 문장, 반복 Priority
- MD 전용: 세부 P2/P3, 전체 Source Trace, 상세 미확정 근거

### Source Trace

- `SOURCE_TRACE_TOO_VISIBLE` 경향
- SVG는 대표 Source 1개 또는 핵심 DN/RG 한 묶음만 남기고 전체 Trace는 MD에 유지한다.

### 정보 우선순위

P1 표기는 있으나 Node가 비슷한 크기와 강도로 보여 우선순위 차이가 충분히 시각화되지 않았다. SVG는 P1 중심, P2/P3는 MD 중심으로 조정한다.

### 관계선

- 판정: `RELATIONSHIP_UNDER_VISUALIZED`
- 관계 과부하는 아니다.
- 8개 관계를 별도 블록에서 읽을 수 있지만 실제 Page 사이 연결선이 부족하다.
- 핵심 4개는 직접 선, 나머지 4개는 범례 방식이 적절하다.

### 제품 구조

약 200개 후보 → 임시 제품 그룹 → 최소 15개 화면 검토용 구성 → 특징·사양 정보 관계는 의미상 PASS다. 다만 SVG 하단에 있어 관련 Section과 시각적으로 멀다.

### Scope 경계

제외 범위라는 의미는 분명하지만 상단에서 시각적으로 강하다. 오른쪽 또는 하단 보조 영역으로 이동하는 것이 적절하다.

- 미확정 어원이나 슬로건을 만들지 않는다.
