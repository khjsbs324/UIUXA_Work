DAMORI / V4 서비스설계 프로젝트 진행 기준 기록
================================================

문서 목적
---------
이 문서는 DAMORI 프로젝트를 CLI에서 계속 진행할 때,
지금까지 어떤 단계를 거쳤는지, 각 단계에서 무엇을 중요하게 봤는지,
현재 무엇이 확정/미확정인지, 다음에 무엇을 해야 하는지 빠르게 확인하기 위한
프로젝트 체크포인트 기록이다.

주의:
- 이 문서는 프로젝트 이해를 돕는 운영/진행 기록이다.
- 실제 근거 충돌 시에는 최신 실제 파일과 원본 Source를 우선한다.
- 파일명에 FINAL / APPROVED / 공식 기준본이라고 적혀 있어도
  사용자 명시 승인 기록이 없으면 자동 승인으로 간주하지 않는다.
- 기존 파일은 사용자 승인 없이 삭제/이동/이름변경하지 않는다.


================================================
1. 프로젝트 최종 목표
================================================

최종 목표는 DAMORI 브랜드를 기반으로 한 3페이지 웹사이트 설계와 웹디자인이다.

최종 3페이지:
1) HOME / MAIN
   - 일반 쇼핑몰 메인 X
   - 브랜드 소개 + 기록 경험 + 제품 포트폴리오가 결합된 롱스크롤 랜딩페이지
   - 최소 15개 이상의 Product 콘텐츠를 실제 화면에 수용

2) PRODUCTS / CATEGORY-SUB
   - 단순 판매목록이 아니라 제품군 탐색, 특징/사양 이해, 사용자 기준 탐색을 위한 포트폴리오형 서브페이지

3) BRAND
   - 회사 연혁 나열형 페이지 X
   - DAMORI의 존재 이유, 기록 철학, 핵심 가치, 아날로그/디지털 원칙, 제품 원칙을
     에디토리얼 흐름으로 보여주는 브랜드 소개페이지

4. 가상 클라이언트 핵심 구조
================================================

대표 7인:

- 아날로그 장문 기록 / 물성 / 소재 / 제본

C02 지안
- 디지털 타임라인 / 일정 충돌 / 제어 니즈

C03 하람
- 저부담 기록 / 짧은 회고 / 부담 없는 접근

C04 소담
- 원문/레이아웃 보존 / 템플릿·꾸미기 관련 니즈

C05 태오
- 오프라인 / 로컬 기록 / 보관 관련 니즈

C06 이준
- 기록을 쉬었다가 죄책감 없이 다시 돌아오는 니즈

C07 다온
- 자율 탐색 / 제품 비교 / 선택 기준 니즈

중요:
일부 가상 클라이언트의 원래 니즈는 실제 앱 기능과 관련되어 있다.
현재 결과물은 3페이지 포트폴리오형 웹사이트이므로,
원래 앱 기능을 웹사이트가 실제로 제공하는 것처럼 과장하지 않는다.

구분 원칙:
- ORIGINAL_SERVICE_NEED: 원래 서비스/앱 수준 니즈
- SITE_LEVEL_NEED: 현재 3페이지 웹사이트가 실제로 충족할 수 있는 정보/경험 수준 니즈

Coverage 구분:
DIRECT
INFORMATIONAL
EXPERIENCE_PREVIEW
OUT_OF_CURRENT_SCOPE
HOLD

12. 웹디자인 레퍼런스 역할
================================================

V4-설계자료 내부의:
웹디자인-레퍼런스/

는 DESIGN_REFERENCE_ONLY이다.

현재 와이어프레임까지 반영된 것:
- Long Scroll Rhythm
- Editorial Composition
- Whitespace
- Hero Text / Visual 관계
- Portfolio Showcase Density
- Product Information Grouping
- Section별 강약
- Brand Editorial Storytelling
- Image / Text Alternation

현재 의도적으로 반영하지 않은 것:
- 선호 사이트의 Color
- Typography
- Radius
- Effects
- 실제 Button 스타일
- 실제 Card 스타일
- 실제 그래픽/이미지 톤
- Decoration

이것들은 누락이 아니라
후속 스타일가이드 / Visual Design 단계로 이관된 내용이다.

18. 현재 발견된 감사 포인트
================================================

최종-기준본 13개 내부 점검에서 확인된 사항:

1. 사용자 승인 상태
- 일부 MD/JSON/SVG 내부에
  APPROVED / 사용자 승인 공식 기준본 / OFFICIAL 표현이 남아 있음
- 사용자 명시 승인과 기준본 상태를 분리해서 정리 필요

2. PATH C
- Service Flow / Storyboard는 공식 경로 정상
- Screen Spec 일부 문장에 축약 경로 잔여 가능

3. PRODUCTS 1.4
- Client / Screen Spec / Service Flow 일부 표현은
  실제 동적 조건 필터처럼 읽힐 수 있음
- Wireframe V3는 NON-EXECUTABLE 구조로 정리됨
- 상위 문서와 V3 의미 정합성 감사 필요

4. 앱형 Design Opportunity
- 저부담 회고 팝업
- 최근 작성 포커스 UI
- 1-click 복귀

22. 파일 운영 원칙
================================================

사용자 승인 없이:
- 삭제 금지
- 이동 금지
- 이름변경 금지
- 기존 파일 덮어쓰기 금지

버전:
V1 / V2 / V3 방식 사용

날짜/시간을 파일 버전명으로 사용하지 않는 방향 선호

기존 버전은 원본 보존

최신본이라고 해서 과거 파일을 자동 삭제하지 않는다.

파일명:
- 일반 결과물은 한글 파일명 선호
- 도구상 영문이 필요한 AGENTS.md / SKILL.md 등은 영문 유지

상태:
파일 이름과 문서 내 APPROVED/FINAL 표기보다
사용자의 실제 명시 승인 기록을 우선한다.


================================================
23. CLI 작업 원칙
================================================

CLI는 작업 전 실제 파일을 읽는다.

추측 금지.

없는 정보 생성 금지.

Source에 없는 Product Fact 생성 금지.

현재 3페이지 Scope 밖 기능 자동 생성 금지.

기존 기준본을 수정해야 할 때는
감사 결과를 먼저 보고하고
사용자 승인 후 수정한다.

작업 보고에는:
- 생성 파일
- 수정 파일
- 삭제 파일
- 기존 원본 보존 여부
- 현재 상태
를 명확히 작성한다.
