# DAMORI V4 사이트 흐름도 고도화 명세

> 상태: `SITE_FLOW_SPEC_FOR_REVIEW`  
> 범위: 3 Page / 16 Section / Navigation Flow  
> Master 방향: `SEQUENTIAL_NARRATIVE + CORE_ANCHOR + CONTEXT_RETURN`  
> 후속 산출물: 대표 Site Flow MD / MMD / SVG

## 1. 사이트 흐름도 명세 목적

이 문서는 확정된 사이트 구조 안에서 사용자가 어디로 진입하고, 어떤 Page와 Section을 거쳐 이동하며, 관련 정보를 교차 확인한 뒤 어디로 돌아오거나 탐색을 끝내는지를 정의한다.

사이트 구조맵의 정보 관계를 그대로 화살표로 복제하지 않는다. 각 이동을 `ENTRY`, `SEQUENTIAL`, `ANCHOR`, `CROSS_PAGE`, `GLOBAL_NAV`, `RETURN`, `EXIT`, `RE_ENTRY`, `INFORMATION_ONLY`로 분류하고, 대표 흐름에는 실제 Navigation으로 필요한 관계만 남긴다.

완료 목표는 다음과 같다.

- 3 Page·16 Section의 기본 서사 유지
- 사용 목적이 분명한 핵심 Section 직접 진입
- 제품·브랜드 교차 탐색 후 이전 정보 맥락 복귀
- GNB와 Footer를 통한 전역 이탈·재진입
- 사이트 흐름과 서비스 상태·판단·오류 흐름 분리
- 후속 MMD/SVG에서 거미줄 관계를 만들지 않는 우선순위 확정

## 5. Candidate 분석 결과 요약

### 5.1 Candidate 1 — 서사 순차 탐색형

- 핵심 원리: Page별 Editorial Narrative 우선
- Entry: HOME 0.1 중심
- 장점: 가장 단순하고 Page 서사가 명확함
- 단점: 목적 정보로 빠르게 진입하거나 원래 맥락으로 돌아가기 어려움
- KEEP: HOME·PRODUCTS·BRAND의 기본 Section 순서
- REFINE: GNB 직접 Entry와 일부 핵심 Anchor 추가
- EXCLUDE: 모든 이동을 순서대로 강제하는 Wizard 방식

### 5.2 Candidate 2 — 목적별 허브·Anchor 탐색형

- 핵심 원리: HOME과 GNB를 목적별 정보 허브로 사용
- Entry: 3개 Page 상단 및 주요 Section Anchor
- 장점: 제품·브랜드 목적 정보에 빠르게 도달
- 단점: 정보 관계를 모두 Link로 만들 경우 거미줄화
- KEEP: GNB, 목적별 직접 진입, 핵심 Anchor
- REFINE: Anchor를 실제 사용자 목적이 명확한 관계로 제한
- EXCLUDE: 16개 Section 전부를 상호 연결하는 구조

### 5.3 Candidate 3 — 맥락 복귀 하이브리드형

- 핵심 원리: 순차 Narrative를 기본으로 하고 핵심 정보만 Anchor로 분기한 뒤 Source 맥락 복귀
- Entry: HOME 기본 + GNB Page Entry
- 장점: 서사·빠른 탐색·복귀를 균형 있게 지원
- 단점: Primary·Optional·Return의 시각 위계가 없으면 복잡해짐
- KEEP: Narrative, 핵심 Anchor, Browser Back 기대, Context Return
- MERGE: Candidate 1의 순차 흐름과 Candidate 2의 목적별 진입
- EXCLUDE: App History Restore와 자동 상태 복원

## 6. Master 승계 방향

Master는 `서사 기반 순차 흐름 + 핵심 Anchor + 맥락 복귀` 구조를 사용한다.

### 6.1 서사 기반 순차 흐름

DAMORI는 판매 과업을 빨리 완료하는 App이 아니라 브랜드와 제품 세계를 이해하는 Portfolio Website다. 따라서 각 Page의 정보 순서는 단순 배열이 아니라 이해 순서다. HOME은 정체성에서 제품으로, PRODUCTS는 범위에서 정보 대조로, BRAND는 정의에서 제품 원칙으로 진행한다.

### 6.2 핵심 Anchor

긴 Page를 처음부터 다시 읽게 만들지 않는다. 기록 경험에서 철학으로, Portfolio에서 사양으로, 제품 정보에서 제품 원칙으로 이동하는 등 사용자 목적과 도착 정보가 명확한 관계만 Anchor로 채택한다.

### 6.3 맥락 복귀

제품 정보와 브랜드 원칙은 서로 검증하는 관계다. 교차 정보를 확인한 뒤 원래 Section으로 돌아갈 수 있어야 비교가 끊기지 않는다. 이는 App 상태 복원이 아니라 Browser Back, Source Section Link, GNB와 Anchor를 이용한 Navigation Context Return이다.

### 6.4 병합 제한

- 모든 Candidate의 모든 Arrow를 합치지 않는다.
- Primary Flow는 Section당 최대 1개를 원칙으로 한다.
- Optional Cross는 사용자 목적이 분명한 경우만 둔다.
- 모든 Page에서는 GNB를 Global Escape로 사용할 수 있다.
- `2.5→0.4`는 정보 관계로 유지하고 대표 Diagram의 필수 직접선에서는 제외한다.

## 8. Global Navigation

GNB 메뉴는 `메인`, `카테고리·서브`, `브랜드 소개` 3개다.

| 역할 | 의미 | 도착 원칙 |
|---|---|---|
| GLOBAL_ESCAPE | 현재 Section Narrative를 따르지 않고 이탈 | 선택 Page 상단 |
| GLOBAL_REENTRY | 탐색했던 Page에 다시 진입 | Page 상단, 상태 자동 복원 없음 |
| GLOBAL_PAGE_SWITCH | 다른 정보 영역으로 전환 | HOME 0.1 / PRODUCTS 1.1 / BRAND 2.1 |

GNB는 모든 Page에서 구조적으로 접근 가능한 Fallback이다. Sticky 여부와 구체 UI는 미확정이다.

## 12. Anchor Navigation

Anchor는 16개 Section 전체를 메뉴로 노출한다는 의미가 아니다. 긴 Page 이동과 Cross-page 정보 심화에 필요한 Target만 구조적으로 확보한다.

| Anchor ID | Page | Section | 필요성 | 주요 진입 Source | Fallback | 상태 |
|---|---|---|---|---|---|---|
| AN-01 | BRAND | 2.1 | 브랜드 요약에서 상세 정의 확인 | HOME 0.2 | BRAND 2.1 Page Entry | REQUIRED |
| AN-02 | BRAND | 2.3 | 기록 경험의 철학 근거 확인 | HOME 0.3 | BRAND 2.1 후 순차 이동 | REQUIRED |
| AN-03 | PRODUCTS | 1.2 | 기록 방식에서 제품군 탐색 시작 | HOME 0.4 | PRODUCTS 1.1 후 순차 이동 | REQUIRED |
| AN-04 | PRODUCTS | 1.3 | Portfolio·원칙·기준을 실제 정보에 대조 | HOME 0.5, BRAND 2.6, PRODUCTS 1.4 | PRODUCTS 1.1/1.2 | REQUIRED |
| AN-05 | BRAND | 2.6 | 제품 정보 제공 원칙 확인 | PRODUCTS 1.3 | BRAND 2.1 후 순차 이동 | REQUIRED |
| AN-06 | HOME | 0.4 | 매체 원칙과 기록 방식 관계 참고 | BRAND 2.5 | HOME 0.1 후 순차 이동 | OPTIONAL |
| AN-07 | 각 Long Page | Page Top/주요 Heading | 현재 위치 재인식과 긴 Page 재탐색 | Section Navigation/Footer | GNB Page Entry | REQUIRED |

Anchor UI 형태는 확정하지 않는다.

- Sticky TOC: 미확정
- Floating Navigation: 미확정
- Tab/Side Navigation: 미확정
- 구조 판정: `ANCHOR_NAVIGATION_REQUIRED` 또는 `OPTIONAL`

## 14. Back / Return

### 14.1 Return 유형

| Return ID | 유형 | 구조적 의미 | 적용 예 |
|---|---|---|---|
| RT-01 | RETURN_TO_SOURCE_SECTION | 교차 정보를 확인한 뒤 출발 정보 맥락으로 복귀 | 1.3→2.6→1.3 |
| RT-02 | PREVIOUS_SECTION | Page Narrative의 이전 Section 재탐색 | 1.4→1.3 |
| RT-03 | RETURN_TO_PAGE_TOP | 긴 Page 상단·전체 Narrative로 복귀 | 0.6/Footer→Page Top |
| RT-04 | GNB_RETURN | 다른 Page 상단으로 전역 재진입 | BRAND→HOME, PRODUCTS→HOME |
| RT-05 | BROWSER_BACK_EXPECTED | 일반 Browser History를 통한 이전 탐색 위치 복귀 | 0.5→1.3 후 Browser Back |

### 14.2 핵심 Context Return

- `HOME 0.5 → PRODUCTS 1.3 → HOME 관련 맥락`: Browser Back 또는 Source Section Return
- `PRODUCTS 1.3 → BRAND 2.6 → PRODUCTS 1.3`: 명시적 상호 Anchor Pair
- `PRODUCTS 1.4 → PRODUCTS 1.3`: 같은 Page의 기준→정보 재대조

Back은 일반적인 이전 위치 이동이고, Return은 관련 정보를 확인한 후 의도적으로 Source 맥락에 돌아오는 이동이다. 별도 App History System이나 자동 상태 복원을 의미하지 않는다.

## 15. Exit

| Exit ID | 위치 | 의미 | Service Success 여부 |
|---|---|---|---|
| EX-01 | HOME 0.6 | Long Scroll 종료 후 추가 탐색 없이 종료 | 아님 |
| EX-02 | 각 Page Footer | Page 탐색 종료 또는 다른 Page 선택 | 아님 |
| EX-03 | 정보 확인 지점 | 필요한 정보 확인 후 Browser Exit | 아님 |
| EX-04 | GNB Page Switch | 현재 Page Flow를 종료하고 다른 Page Flow 시작 | 아님 |

제품 탐색의 Exit는 구매 완료가 아니라 제품군·특징·사양·탐색 기준·제품 원칙을 필요한 수준까지 확인한 상태다.

## 17. Footer Flow

Footer는 새 기능 영역이 아니라 탐색 종료와 재선택을 지원하는 보조 Navigation이다.

허용:

- HOME 재진입
- PRODUCTS 재진입
- BRAND 재진입
- 현재 Page Top 복귀
- 현재 범위 내 기본 안내

금지:

- 계정·구매·결제·Community Link 추가
- 현재 Scope에 없는 App 기능 진입

## 18. 이동 유형 및 Priority

### 18.1 Flow ID 체계

| Prefix | 의미 |
|---|---|
| EN | Entry |
| PN | Primary Narrative |
| CR | Cross-page/Anchor Navigation |
| GN | Global Navigation |
| RT | Return |
| EX | Exit |
| RE | Re-entry |
| IO | Information Only |

### 18.2 이동 유형

- `SEQUENTIAL`: Page 내부 기본 서사
- `CROSS_PAGE`: 다른 Page 정보로 이동
- `ANCHOR`: 지정 Section 직접 진입
- `GLOBAL_NAV`: GNB/Footer Page 이동
- `RETURN`: Source·이전 Section·Page Top 복귀
- `EXIT`: Navigation 탐색 종료
- `RE_ENTRY`: Page/Section 재진입
- `INFORMATION_ONLY`: 의미 관계는 있으나 직접 Link 필수 아님

### 18.3 Priority

- `PRIMARY`: 대표 Narrative의 기본 다음 이동
- `OPTIONAL`: 사용자 목적이 분명할 때 선택
- `GLOBAL`: 현재 위치와 무관하게 사용할 Fallback

## 21. 대표 Navigation Path

### 21.1 PATH A — 브랜드 발견 중심

- Entry: `외부 → HOME 0.1`
- Sequence: `0.1 → 0.2 → 0.3`
- Cross: 필요 시 `0.2 → BRAND 2.1` 또는 `0.3 → BRAND 2.3`
- Continue: BRAND 내부 Narrative의 다음 Section 또는 GNB
- Return: Browser Back/Source Return으로 HOME 맥락 복귀 가능
- Exit: HOME 0.6, BRAND Footer, 정보 확인 후 Browser Exit

### 21.2 PATH B — 제품 정보 중심

- Entry: `GNB → PRODUCTS 1.1` 또는 `HOME 0.4/0.5`
- Sequence: `1.1 → 1.2 → 1.3 → 1.4`
- Loop: 필요 시 `1.4 → 1.3`
- Cross: `1.3 → BRAND 2.6`
- Return: `2.6 → PRODUCTS 1.3`
- Exit: PRODUCTS Footer 또는 정보 확인 후 Browser Exit

### 21.3 PATH C — 기록 경험에서 제품·철학 교차 탐색

- Entry: `외부 → HOME 0.1 → 0.2 → 0.3`
- 제품 분기: `0.3 → 0.4 → PRODUCTS 1.2 → 1.3`
- 철학 분기: `0.3 → BRAND 2.3`
- Cross: 필요에 따라 제품 정보와 제품 원칙 `1.3 ↔ 2.6`
- Return: Source Section 또는 GNB로 HOME/PRODUCTS/BRAND 재진입
- Exit: 각 Page의 종료 지점

세 경로는 Navigation Path이며 Trigger·감정·판단·성공/실패 조건을 포함하지 않는다.
