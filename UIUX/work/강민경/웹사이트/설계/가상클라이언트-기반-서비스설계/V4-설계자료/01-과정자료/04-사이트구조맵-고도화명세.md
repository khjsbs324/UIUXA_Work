# DAMORI V4 사이트 구조맵 고도화 명세

> 문서 성격: 대표 사이트 구조맵 MD/MMD/SVG 제작 전 상세 내용 명세  
> 고도화 원칙: `KEEP_EXISTING_SKELETON + REFINE_AND_INHERIT_DETAIL`  
> 현재 구조: 메인·카테고리·서브·브랜드 소개 3 Page / 16 Section  
> 사용자 노출 언어: 한국어 중심, 영문 Page ID와 DN/RG는 기술 보조 표기  
> 범위 경계: 브랜드·제품 Portfolio Website. 쇼핑몰·기록 실행 App이 아님

## 1. 사이트 구조맵 개요

이 문서는 51명의 Source Client, Client별 A/B/C 사이트 구조 후보 153개, V1~V3 통합 구조, V4 Client Baseline·사이트 분석·사이트맵을 현재 3 Page·16 Section에 농축한 상세 사이트 구조맵 명세다.

사이트맵이 Page·Section·Depth를 정의한다면, 본 구조맵은 각 Section의 정보·콘텐츠·허용 기능·사용자 요구·정보 우선순위·연결 관계를 정의한다. 기존 V4의 Skeleton은 유지하고, 과거 App Scope와 20 Page 구조는 복원하지 않는다.

## 2. 설계 목적

1. 처음 방문한 사용자가 DAMORI의 정체성과 Portfolio Website 성격을 이해한다.
2. 기록 경험과 기록 방식이 제품 세계에 연결되는 이유를 이해한다.
3. 약 200개 Product Working Pool을 공식 Category로 오인하지 않고 검토용 정보 그룹으로 탐색한다.
4. 제품 간 차이를 확인된 특징·사양·사용 맥락과 정보 상태로 비교한다.
5. 제품 정보가 DAMORI의 기록 철학과 제품 원칙에 어떻게 연결되는지 확인한다.
6. 저장·구매·자동 추천 없이 Page 이동과 정보 확인만으로 사이트 수준 목표를 달성한다.

## 3. 설계 Source

| Source | 사용 범위 | 본 명세 반영 |
|---|---|---|
| 51 Source Client | 원본 상황·Need·REQ·성공/실패 조건 | 대표 Source Client와 Rare-but-important 구조 근거 |
| 153개 A/B/C 후보 | 과업 직결, 맥락·근거, 대안·안전 구조 | 정보 그룹·우선순위·교차 관계로 농축 |
| V4 대표 Client 7인 | Website 수용 요구 | Section별 대표 Client |
| DN-01~08, DN-12, DN-13 | Pure Need | Need→Section 추적 |
| RG-01~08 | Requirement Group | 정보 구조 반영 근거 |
| V1 구조 자료 | 상세 Page 역할·비교·가이드 | 유효 정보만 현 Section에 병합 |
| V2 통합 구조 | Client 전수 Page Mapping | Source Coverage 근거 |
| V3 통합·브랜드 고도화 구조 | 브랜드·제품·기록 방식 관계 | 3 Page 관계로 정제 |
| V4 사이트 분석 | 메뉴·콘텐츠·기능 | 구조맵의 직접 입력 |
| V4 사이트맵 | 3 Page·16 Section | 변경하지 않는 Skeleton |
| 브랜드 정의 Source | 브랜드 성격·철학·범위 | BRAND_CORE |
| Product Source | 약 200개 Working Pool·검토용 제품 | PRODUCT_SOURCE |

세부 51명 전수 Trace는 기존 과정자료를 기준으로 유지한다. 본 문서는 각 Section에 대표 Client, 주요 Source Client, DN/RG만 표시한다.

## 4. 현재 Scope

### 4.1 현재 구조 확정

- 메인 페이지(HOME): 0.1~0.6
- 카테고리·서브 페이지(PRODUCTS): 1.1~1.4
- 브랜드 소개 페이지(BRAND): 2.1~2.6
- Page 수: 3
- Section 수: 16
- 실제 허용 행동: Page 이동, Section 이동, 제품·브랜드 정보 확인, 비교 기준 참고

### 4.2 검토용 구조

- 약 200개 Product Pool을 이해하기 위한 임시 제품 그룹
- 메인에서 최소 15개 이상 수용하는 Working Display Set
- 제품 특징·사양의 추가 확인 슬롯
- Section Anchor의 시각적 표현 방식

### 4.3 Source 추가 확인 필요

- 공식 Category 수와 명칭
- 최종 노출 Product 15개
- 제품별 실제 재질·제본·치수·성능
- 브랜드 공식 어원·최종 슬로건
- 최종 Copy와 Asset

## 5. 전역 구조

```text
DAMORI Portfolio Website
├─ 메인 페이지 (HOME)
│  └─ 브랜드 첫 이해 → 핵심 약속 → 기록 경험 → 제품 연결 → Portfolio → 다음 이동
├─ 카테고리·서브 페이지 (PRODUCTS)
│  └─ 제품 맥락 → 임시 제품 그룹 → 특징·사양 대조 → 사용자 기준 안내
└─ 브랜드 소개 페이지 (BRAND)
   └─ 브랜드 정의 → 존재 이유 → 기록 철학 → 핵심 가치 → 매체 원칙 → 제품 원칙
```

전역 공통 요소는 브랜드 식별, 3개 메뉴 GNB, 현재 Page 표시, 긴 페이지 위치 인지, Section Anchor, Page 간 교차 이동, Footer다. 검색·로그인·회원·장바구니는 포함하지 않는다.

## 7. Page별 상세 구조

### 7.1 메인 페이지 (HOME)

- **Page ID**: `PAGE-00 / HOME`
- **Page 이름**: 메인 페이지
- **Page 목적**: DAMORI의 브랜드 정체성, 기록 경험, 제품 세계를 순차적으로 이해시키는 Portfolio Long Scroll Landing.
- **핵심 사용자**: 브랜드를 처음 발견한 사용자, 부담 없는 기록 방식을 찾는 사용자, 제품 세계를 먼저 훑고 싶은 사용자.
- **핵심 사용자 요구**: 무엇을 위한 브랜드인지 이해하고, 자신과 연결되는 기록 경험과 제품 탐색 입구를 찾는다.
- **대표 Client**: V4-C03 하람, V4-C04 소담, V4-C06 이준.
- **주요 DN/RG**: DN-03·04·06·12·13 / RG-03·04·06.
- **핵심 콘텐츠**: 첫인상, 브랜드 핵심 가치, 기록 경험, Analog/Digital과 제품 연결, 최소 15개 수용 Showcase, 다음 이동.
- **허용 기능**: 순차 스크롤, Section Anchor, 제품·브랜드 Page 이동, 현재 위치 확인.
- **주요 진입점**: 외부 링크, GNB HOME, 다른 Page의 HOME 링크.
- **주요 종료/이동점**: PRODUCTS 1.2/1.3, BRAND 2.1/2.3, Footer.
- **다른 Page와 관계**: 전체 맥락을 제공하고 PRODUCTS와 BRAND의 진입 동기를 만든다.
- **정보 우선순위**: 정체성·핵심 경험·제품 연결 P1, 보조 사례 P2, 장식 Asset P3.
- **현재 미확정 사항**: 최종 Copy, 대표 Visual, Working Display Product 15개.

### 7.2 카테고리·서브 페이지 (PRODUCTS)

- **Page ID**: `PAGE-01 / PRODUCTS`
- **Page 이름**: 카테고리·서브 페이지
- **Page 목적**: 공식 Category를 확정하지 않은 상태에서 제품 세계의 범위와 제품 간 차이를 정보 중심으로 탐색하게 한다.
- **핵심 사용자**: 기록 방식에 맞는 제품군·서식·물성·치수 정보를 찾는 사용자.
- **핵심 사용자 요구**: 판매 압박이나 복잡한 진단 없이 제품 범위, 특징, 사양, 비교 기준을 파악한다.
- **대표 Client**: V4-C01 은재, V4-C02 지안, V4-C04 소담, V4-C07 다온.
- **주요 DN/RG**: DN-01·02·04·07·08·13 / RG-01·02·04·07·08.
- **핵심 콘텐츠**: 제품군 Visual, 임시 정보 그룹, 제품 유형·특징·사양·사용 맥락, 비실행형 탐색 기준.
- **허용 기능**: 제품군 정보 확인, 사양 대조 정보 확인, Section 이동, 브랜드 제품 원칙 이동.
- **주요 진입점**: HOME 0.4/0.5, GNB PRODUCTS.
- **주요 종료/이동점**: BRAND 2.6, HOME, 다른 제품 정보 그룹.
- **다른 Page와 관계**: HOME에서 제시한 제품 관심을 근거 있는 정보 확인으로 전환하고 BRAND의 제품 원칙으로 역추적한다.
- **정보 우선순위**: 정보 상태·제품 차이·탐색 범위 P1, 사례·추가 설명 P2, 장식 P3.
- **현재 미확정 사항**: 공식 Category, 최종 15개, 제품별 실제 Fact.

### 7.3 브랜드 소개 페이지 (BRAND)

- **Page ID**: `PAGE-02 / BRAND`
- **Page 이름**: 브랜드 소개 페이지
- **Page 목적**: DAMORI가 어떤 브랜드이며 왜 존재하고 어떤 기록·제품 원칙을 따르는지 독립 서사로 설명한다.
- **핵심 사용자**: 브랜드의 태도와 제품 정보의 배경을 확인하려는 사용자.
- **핵심 사용자 요구**: 감성적 주장만이 아니라 사용자 문제, 브랜드 방향, 제품 적용 관계를 이해한다.
- **대표 Client**: V4-C01 은재, V4-C06 이준, V4-C07 다온.
- **주요 DN/RG**: DN-01·06·07·08·12 / RG-01·06·07·08 및 BRAND_CORE.
- **핵심 콘텐츠**: 브랜드 정의, 존재 이유, 기록 철학, 편안함·보존·자율성, Analog/Digital 원칙, 제품 원칙.
- **허용 기능**: 서사 순차 읽기, Section Anchor, PRODUCTS 1.3 이동, HOME 이동.
- **주요 진입점**: HOME 0.2/0.3, PRODUCTS 1.3, GNB BRAND.
- **주요 종료/이동점**: PRODUCTS 1.3, HOME.
- **다른 Page와 관계**: HOME의 요약을 심화하고 PRODUCTS 정보가 존재하는 이유와 판단 원칙을 제공한다.
- **정보 우선순위**: 정체성·존재 이유·철학·제품 원칙 P1, 적용 사례 P2, 장식적 서사 P3.
- **현재 미확정 사항**: 공식 어원, 최종 슬로건, 최종 Copy, 이미지 Asset.

## 8. Section별 정보 구조

### 8.1 `0.1` 첫인상 / 메인 비주얼

- **Section ID / 이름**: `0.1` / 첫인상·메인 비주얼
- **Section 목적**: 첫 화면에서 DAMORI의 정체성과 Website 성격을 오해 없이 전달한다.
- **사용자 상황**: DAMORI를 처음 접해 브랜드인지 쇼핑몰인지 앱인지 모른다.
- **사용자가 알고 싶은 것**: 어떤 브랜드이며 이 Page에서 무엇을 볼 수 있는가.
- **핵심 정보**: DAMORI 작업 브랜드명, 기록 라이프스타일 브랜드, 브랜드+제품 Portfolio Landing, 비판매·비앱 방향.
- **보조 정보**: 현재 작업명 상태, 다음 Section에서 핵심 약속을 설명한다는 안내.
- **주요 콘텐츠**: 브랜드명, 한 문장 정의, 대표 Visual, 짧은 Scope 문구.
- **허용 기능**: 다음 Section 이동, GNB 이동. 구매 CTA는 금지한다.
- **사용자 행동**: 브랜드 성격을 확인하고 아래로 읽거나 GNB로 목적 Page를 선택한다.
- **진입 위치**: 외부 진입, HOME 최상단.
- **다음 연결**: `0.2` 브랜드 핵심 소개.
- **교차 연결**: 필요 시 `2.1` 브랜드 소개.
- **Source Client**: VC-11·38·43·49.
- **Representative Client**: V4-C06 및 BRAND_CORE 검증 Source.
- **DN/RG**: BRAND_CORE, PROJECT_CONSTRAINT.
- **정보 우선순위**: P1 정체성·범위, P2 상태 고지, P3 Visual, OUT 구매 정보.
- **확정 정보**: DAMORI 현재 작업명, 기록 라이프스타일 브랜드, Portfolio Website.
- **미확정 정보**: 공식 어원, 최종 슬로건, 최종 Hero Asset.
- **현재 Scope 밖 정보**: 성과 수치, 인증, 가격·재고, 강한 구매 CTA.
- **후속 Flow 전달사항**: 외부 진입→정체성 확인→0.2 또는 BRAND 2.1 분기.

### 8.2 `0.2` 브랜드 핵심 소개

- **Section ID / 이름**: `0.2` / 브랜드 핵심 소개
- **Section 목적**: 편안함·보존·자율성을 사용자 문제 및 Website 적용 위치와 연결한다.
- **사용자 상황**: 브랜드명은 이해했지만 실제로 무엇을 중요하게 여기는지 모른다.
- **사용자가 알고 싶은 것**: DAMORI의 약속이 자신에게 어떤 이익을 주는가.
- **핵심 정보**: 편안함은 기록 압박 감소, 보존은 원본·정보의 정직한 유지, 자율성은 강요 없는 선택을 의미한다.
- **보조 정보**: 편안함→0.3/2.3, 보존→1.3/2.4, 자율성→1.4/2.4 연결.
- **주요 콘텐츠**: 세 가치 요약 카드와 적용 위치 안내.
- **허용 기능**: `2.1` 브랜드 상세 이동, 관련 Section Anchor.
- **사용자 행동**: 가치 의미를 비교하고 기록 경험 또는 브랜드 상세를 선택한다.
- **진입 위치**: `0.1` 다음.
- **다음 연결**: `0.3` 기록 경험.
- **교차 연결**: `2.1`, `2.4`.
- **Source Client**: VC-11·27·45.
- **Representative Client**: V4-C03·C04·C06·C07.
- **DN/RG**: DN-03·04·06·07·12 / RG-03·04·06·07.
- **정보 우선순위**: P1 가치 의미·사용자 이익, P2 적용 위치, P3 보조 Symbol.
- **확정 정보**: 편안함·보존·자율성의 상위 방향.
- **미확정 정보**: 최종 가치 명칭과 Copy.
- **현재 Scope 밖 정보**: 가치 실현을 실제 저장·자동화 기능으로 약속하는 표현.
- **후속 Flow 전달사항**: 가치 요약→0.3 경험 또는 2.1/2.4 심화.

### 8.3 `0.3` 기록 경험

- **Section ID / 이름**: `0.3` / 기록 경험
- **Section 목적**: 사용자가 DAMORI의 기록 관점을 자신의 상황과 연결한다.
- **사용자 상황**: 시작 부담, 원본 손실 우려, 중단 후 죄책감 중 하나를 경험한다.
- **사용자가 알고 싶은 것**: DAMORI가 어떤 기록 경험을 지지하는가.

## 12. 정보 우선순위

- **P1**: Section 목적 달성에 필수인 정체성, 사용자 요구, 제품 정보, 정보 상태, Page 관계.
- **P2**: P1의 이해를 돕는 적용 위치, Source, 사용 맥락, 보조 사례.
- **P3**: 후속 Visual Design에서 선택 가능한 장식 Asset, 추가 사례, 보조 문구.
- **OUT**: 현재 Website가 실제 지원하지 않는 App·Commerce 기능과 검증되지 않은 Fact.

원칙적으로 각 Section은 P1을 Text로 제공해야 하며, 이미지나 모션만으로 P1 정보를 전달하지 않는다.

## 15. 제품 정보 구조

```text
약 200개 Product Working Pool
└─ 임시 제품 그룹 / 정보 그룹
   ├─ 대표 노출 후보와 아직 탐색하지 않은 범위
   ├─ 중복 소속 가능성
   └─ 메인 Working Display Set (최소 15개 이상 수용)
      └─ 제품 특징·사양 정보
         ├─ 제품 식별·유형
         ├─ 관련 기록 방식·사용 맥락
         ├─ 재질·제본·서식·치수 등 Source 확인 정보
         ├─ 추가 확인 필요 정보
         └─ 미확정·보류 정보
```

제품 정보 상태:

- **확인됨**: 실제 Source로 확인되고 적용 범위가 명시된 정보.
- **추가 확인 필요**: 정보 필드는 필요하지만 해당 제품 Fact가 아직 검증되지 않은 상태.
- **미확정**: Category, 제품 선정, 명칭 또는 적용 여부가 결정되지 않은 상태.
- **보류**: 근거가 부족해 대표 정보로 사용할 수 없는 상태.

가격·재고·배송·구매 CTA는 포함하지 않는다.

## 17. 공통 구조

1. 브랜드 식별과 3개 GNB를 모든 Page에서 일관되게 제공한다.
2. 현재 Page와 현재 Section을 Heading·Anchor로 인지할 수 있게 한다.
3. 긴 Page는 Section 건너뛰기와 상단 복귀 경로를 제공한다.
4. Heading Hierarchy와 읽기 순서는 시각 배치와 독립적으로 유지한다.
5. 모든 이동은 Keyboard로 접근 가능해야 한다.
6. Visual은 정보를 보조하며 제품명·핵심 설명·특징·브랜드 메시지는 Text로도 존재한다.
7. 이미지 실패 시 해당 Section의 Text 정보를 유지하고 전체 Page를 빈 오류 화면으로 대체하지 않는다.
8. 교차 Page 이동 후 원래 Page·Section으로 돌아갈 수 있는 구조적 위치 정보를 전달한다.
9. Footer는 브랜드·제품 Page 이동과 범위·상태 고지를 보조한다.

- Normal·Branch·Empty·Error·Exit·Re-entry Sequence
