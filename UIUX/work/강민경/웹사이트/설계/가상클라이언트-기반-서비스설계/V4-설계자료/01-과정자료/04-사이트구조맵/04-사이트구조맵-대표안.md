# DAMORI V4 사이트 구조맵 대표안

> 상태: 사용자 검토용 대표 Candidate  
> 기준 Source: `../04-사이트구조맵-고도화명세.md`  
> 구조 원칙: `KEEP_EXISTING_SKELETON + REFINE_AND_INHERIT_DETAIL`  
> 범위: 3 Page / 16 Section / Portfolio Website

## 1. 구조맵 목적

이 구조맵은 Page 목록이 아니라 `사용자 요구 → 정보 그룹 → 콘텐츠 → 허용 기능 → Section → Page`의 관계를 보여준다. V4의 3 Page·16 Section을 유지하면서 51 Source Client와 153개 A/B/C 후보에서 검증된 상세를 현재 범위에 농축한다.

사용자는 이 문서와 SVG를 통해 다음을 확인할 수 있어야 한다.

- 각 Page와 Section이 왜 필요한가
- 각 Section에서 어떤 정보를 확인할 수 있는가
- 정보가 어떤 Client·DN·RG에서 나왔는가
- 어떤 기능만 허용되는가
- 정보 우선순위와 확정 상태는 무엇인가
- Page가 왜 서로 연결되는가

## 5. 메뉴

- **메인**: 브랜드와 제품 세계의 전체 맥락을 제공한다.
- **카테고리·서브**: 제품군 범위·특징·사양·탐색 기준을 확인한다.
- **브랜드 소개**: 존재 이유·기록 철학·제품 원칙을 심화한다.

새 메뉴는 추가하지 않는다. 과거의 기록 방식·아날로그·디지털·템플릿·가이드는 현재 16개 Section의 정보 그룹으로 병합한다.

## 7. 기능

### 허용

- 3개 Page 이동
- Section Anchor와 현재 위치 확인
- 제품군·제품 특징·사양 정보 확인
- 비실행형 비교 기준 참고
- 제품 정보↔브랜드 원칙 교차 이동
- Keyboard 접근 가능한 이동과 Text 대체 정보

### 허용하지 않음

- 로그인·회원·장바구니·결제
- Editor·Save·Sync·Export
- 자동 추천·진단 결과·개인화 저장
- 실행형 Filter·Product Detail 독립 Page

## 10. 정보 우선순위

- **P1**: SVG에도 반드시 표시하는 Section 목적, 핵심 정보 그룹, 주요 Source, 핵심 연결.
- **P2**: MD에서 상세 유지하고 SVG에서는 축약 가능한 보조 정보·사용 맥락.
- **P3**: 후속 디자인에서 선택하는 추가 사례·Asset·보조 문구.
- **OUT**: 현재 구조 내부에 넣지 않고 Scope 경계에서만 표시하는 App·Commerce 요구.

| 1.4 | 1.3 | 비교 기준 적용 | 자기 기준을 실제 정보에 대조 |
| 2.5 | 0.4 | 매체 원칙 적용 | 브랜드 매체 관점을 제품 Bridge에서 확인 |
| 2.6 | 1.3 | 제품 원칙 검증 | 선언을 실제 제품 정보 상태로 확인 |

## 13. 제품 구조

```text
약 200개 제품 후보 Pool
↓
임시 제품 정보 그룹 — 공식 Category 아님
↓
메인 최소 15개 수용 화면 검토용 구성 — 최종 선정 아님
↓
제품 특징·사양 비교 — Source 확인 정보만 Fact로 사용
```

제품 정보는 `출처 확인 / 추가 확인 필요 / 미확정` 상태를 Text와 기호로 함께 표시한다. 가격·재고·배송·구매 정보는 포함하지 않는다.

## 14. 브랜드 구조

```text
브랜드 정의

→ 확인 정보·미확정 구분·선택 비강요 제품 원칙
```

## 18. SVG 읽는 방법

1. 상단의 Source·사용자 요구에서 구조의 근거를 확인한다.
2. 가운데 세 Page 그룹에서 16개 Section의 순서를 읽는다.
3. 각 Section Box의 `목적 / P1 정보 / 콘텐츠·기능 / Source`를 확인한다.
4. 굵은 실선은 Page 내부 순서, 점선은 Page 간 사용자 목적 연결이다.
5. 하단 제품 구조는 200 Pool과 화면 검토용 구성의 관계를 보여준다.
6. 오른쪽 Scope 경계는 누락이 아니라 의도적으로 제외한 요구다.

### 대표안 판정

`NEW_MASTER_CANDIDATE_IS_CLEARLY_BETTER`
