## 01. V4 Client Baseline 개요

### 1.1 프로젝트 목적
본 프로젝트는 **"브랜드를 소개하면서 제품군까지 설득력 있게 보여주는 포트폴리오형 랜딩 경험"**을 구축하기 위해, 가상 클라이언트(Virtual Client)의 실제 사용자 요구(Pure User Need)를 바탕으로 검증된 UX/UI 설계를 도출하는 것을 목적으로 한다.

### 1.2 V4 Client 생성 목적 및 Source Master 보존
- **Source Master (51명)**: 기존 `clients-51-v6.json`에 수용된 51명의 가상 클라이언트 데이터는 조사·분석 근거 추적 및 원치 요구 검증을 위한 **SOURCE MASTER**로 100% 보존된다. (폐기되거나 삭제되지 않음).
- **V4 대표 Client (7명)**: V4 후속 설계 단계에서 51명을 각각 반복 실행하여 사이트맵·화면·스토리보드를 개별 생성하는 비효율을 제거하고, 51명의 Pure Need와 Requirement Pattern을 100% 누락 없이 완벽하게 커버하면서 실질적 설계 판단 차별성을 가지는 **현재 자료 기준 최소 유효 대표 Client 후보 7인 세트(`V4-C01` ~ `V4-C07`)**를 확정하여 활용한다.

## 02. Source 운영 구조

```text
51 Source Client (clients-51-v6.json)
       ↓
Pure User Need (10개 Pure DNs)
       ↓
Requirement Pattern (8개 RGs)
       ↓
V4 Representative Client (7인 세트)

별도 5개 독립 Layer:
- Product Requirement (제품 스펙 검토 조건)
- Brand Rule (브랜드 디자인 선언 및 물성 원칙)
- System Rule (다기기 및 시스템 공통 규칙)
- Accessibility Rule (WCAG 2.1 AA 웹 접근성 표준)
- Design Opportunity (후속 설계 시 비교·검토 가능한 후보 Solution)
```

## 03. V4 대표 Client 7인 상세 명세

### 1) V4-C01 은재 (통합 대표 Client)
- **ID**: `V4-C01`
- **대표 이름**: 은재
- **대표 사용자 유형**: 아날로그 장문 사색형 사용자
- **상황**: 길게 생각과 감정을 적을 때 노트 중앙이 솟아올라 손목이 아프거나 만년필 잉크가 뒷면에 비쳐 기록 집중도가 떨어지는 경험을 가지고 있음.
- **핵심 목표**: 중앙이 편평하게 펼쳐지고 번짐 없는 아날로그 노구와 속지 스펙을 직접 확인하고 선택
- **주요 행동**: 노구 및 속지 명세 확인 ➔ 필기감/번짐성 검증 ➔ 선택
- **Pain Point**: 스프링 단차로 인한 필기 방해, 만년필 잉크 번짐
- **Pure User Need**: **"장시간 많은 글을 적어도 손이 편안하게 180도 평평하게 펼쳐지고, 만년필 잉크 번짐이 없는 종이를 원함."**
- **판단 기준**: 평면 펼침 단차 0mm 보증, 잉크 번짐률 0%
- **성공 조건**: 필기 장애 요소 0% 확인 후 소장
- **실패 조건**: 중앙 솟아오름 발생, 번짐 심함
- **Analog / Digital 관계**: 100% 아날로그 중심
- **Source VC**: `VC-01`, `VC-06`, `VC-17`, `VC-29`
- **Pure DN**: `DN-01`
- **Requirement Pattern**: `RG-01`, `RG-07`
- **Product Requirement**: 평평하게 펼쳐지는 제본 구조 및 비침·번짐을 줄일 수 있는 적절한 종이 사양 검토
- **Design Opportunity**: 노트 내부 중앙 평면 감성 뷰어, 번짐 검증 라벨 섹션 (후보 Solution)
- **관련 Global Rule**: `DN-09 (제품 스펙)`, `DN-10 (불박 각인 브랜드 원칙)`

- **Product Requirement**: 24시간 세로 타임라인 일간 플래너 서식 검토
- **Design Opportunity**: 외부 연동 차단 패널, 시간축 충돌 조작 타임라인 위젯 (후보 Solution)

## 07. 후속 설계 운영 규칙 & 프로젝트 최종 Constraint

### 7.1 후속 설계 운영 파이프라인 규칙
V4 설계 진행 시 어떠한 통합본도 바로 단일 생성하지 않으며, 아래의 검증 단계를 준수한다:
1. **사이트맵**: 다수 후보(A/B/C안) 도출 ➔ 대조 검증 ➔ 사용자 승인 ➔ V4 통합 사이트맵 병합
2. **서비스 흐름도**: 다수 Flow 후보 도출 ➔ 대조 검증 ➔ 사용자 승인 ➔ V4 통합 서비스 흐름도 병합
3. **화면설계서**: 다수 화면 구성 후보 도출 ➔ 대조 검증 ➔ 사용자 승인 ➔ V4 통합 화면설계서 병합
4. **스토리보드**: 메인/서브/브랜드 다수 후보 도출 ➔ 대조 검증 ➔ 사용자 승인 ➔ 최종 3개 스토리보드 병합

### 7.2 파일 폭증 방지 규칙
하나의 마크다운 비교 파일 안에 A안, B안, C안을 작성하여 불필요한 형식을 반복 생성하지 않는다. 사용자 승인 후 필요한 형식만 추가 제작한다.
