# DAMORI V4 사이트 흐름도 대표안

> 상태: `SITE_FLOW_MASTER_CANDIDATE_FOR_REVIEW`  
> 기준: `05-사이트흐름도-고도화명세.md`  
> 범위: 3 Page / 16 Section / Navigation Flow  
> 방향: `SEQUENTIAL_NARRATIVE + CORE_ANCHOR + CONTEXT_RETURN`

## 1. 대표 Site Flow 목적

이 대표안은 DAMORI Website에서 사용자가 어디로 진입하고, Page별 정보를 어떤 순서로 읽으며, 언제 관련 Section으로 건너가고, 교차 확인 후 어떻게 원래 맥락으로 돌아오거나 탐색을 끝내는지를 보여준다.

사이트 구조맵이 “무엇이 있는가”를 설명한다면, 이 사이트 흐름도는 “어떻게 움직이는가”를 설명한다. Trigger·판단·오류·복구 같은 서비스 처리 흐름은 포함하지 않는다.

## 2. Master 방향

대표 흐름은 세 규칙을 결합한다.

1. **서사 기반 순차 흐름**: HOME·PRODUCTS·BRAND는 각각 이해 순서에 맞는 Primary Narrative를 가진다.
2. **핵심 Anchor**: 사용 목적과 Target 정보가 분명한 경우 관련 Section으로 직접 이동한다.
3. **맥락 복귀**: 제품·브랜드 정보를 교차 확인한 뒤 Source Section 또는 이전 탐색 위치로 돌아갈 수 있다.

하이브리드는 모든 관계를 합치는 방식이 아니다. Primary는 Section당 1개를 중심으로 두고, Cross는 6개, Information Only는 1개로 제한한다.

## 3. 전체 Navigation 구조

```text
외부 → HOME 0.1
          ↓
GNB → HOME / PRODUCTS / BRAND 상단
          ↓
Page별 Primary Narrative
          ↓
목적이 분명하면 핵심 Anchor·Cross Navigation
          ↓
관련 정보 확인
          ↓
Source Section Return / GNB·Footer 재탐색 / Exit
```

확정 수치:

- Page: 3
- Section: 16
- Primary: 13
- Anchor: 7
- Cross-page Navigation: 6
- Information Only: 1
- Return Type: 5
- Exit Type: 4
- Re-entry Type: 4
- 대표 Path: 3

## 4. Entry

| Entry ID | From | To | 목적 | 방식 |
|---|---|---|---|---|
| EN-01 | 외부 | HOME 0.1 | 브랜드와 Website 성격 첫 이해 | Primary Entry |
| EN-02 | GNB 메인 | HOME 0.1 | 메인 Narrative 재진입 | Global Entry |
| EN-03 | GNB 카테고리·서브 | PRODUCTS 1.1 | 제품 정보 Page 범위 이해 | Global Entry |
| EN-04 | GNB 브랜드 소개 | BRAND 2.1 | 브랜드 Editorial Narrative 진입 | Global Entry |
| EN-05 | 유효한 내부 Cross Link | 지정 Target Section | 관련 정보 직접 확인 | Anchor Entry |

범용 외부 Deep Link는 확정하지 않는다. EN-05는 아래 Cross·Anchor 관계가 실제 Target을 담당한다.

## 5. GNB

GNB는 `메인`, `카테고리·서브`, `브랜드 소개` 3개다.

- `GLOBAL_ESCAPE`: 현재 Narrative를 중단하고 다른 Page로 이동
- `GLOBAL_REENTRY`: 선택 Page 상단으로 재진입
- `GLOBAL_PAGE_SWITCH`: 정보 영역 전환

GNB는 각 Page의 첫 Section만 연결한다. 모든 Section에 개별 연결하지 않는다. Sticky 여부는 미확정이다.

## 6. HOME Flow

`0.1 첫인상 → 0.2 브랜드 핵심 소개 → 0.3 기록 경험 → 0.4 기록 방식과 제품 연결 → 0.5 제품 포트폴리오 → 0.6 마무리 및 이동`

| Flow | 목적 | Priority |
|---|---|---|
| 0.1→0.2 | 브랜드 성격에서 핵심 가치로 확장 | PRIMARY |
| 0.2→0.3 | 브랜드 약속을 실제 기록 경험과 연결 | PRIMARY |
| 0.3→0.4 | 기록 경험을 기록 방식과 제품 접근으로 연결 | PRIMARY |
| 0.4→0.5 | 기록 방식과 관련 제품 세계 확인 | PRIMARY |
| 0.5→0.6 | Portfolio 확인 후 다음 탐색 선택 | PRIMARY |
| 0.6→PRODUCTS/BRAND/Exit | 제품·브랜드 심화 또는 종료 | OPTIONAL |

HOME은 Long Scroll Narrative지만 Wizard가 아니다. GNB와 핵심 Anchor로 순서를 건너뛸 수 있다.

## 7. PRODUCTS Flow

`1.1 대표 비주얼·범위 → 1.2 제품군 탐색 → 1.3 제품 특징·사양 → 1.4 사용자 기준 탐색 안내`

| Flow | 목적 | 유형 | Priority |
|---|---|---|---|
| 1.1→1.2 | Page 범위에서 임시 제품 그룹으로 이동 | SEQUENTIAL | PRIMARY |
| 1.2→1.3 | 제품군에서 특징·사양 근거 대조로 이동 | SEQUENTIAL | PRIMARY |
| 1.3→1.4 | 실제 정보 확인 후 자기 탐색 기준 참고 | SEQUENTIAL | PRIMARY |
| 1.4→1.3 | 기준을 실제 특징·사양에 다시 적용 | RETURN/ANCHOR | OPTIONAL |

제품 탐색의 목적은 제품군·특징·사양·탐색 기준·제품 원칙 이해까지다. 구매 Flow는 없다.

## 8. BRAND Flow

`2.1 브랜드 소개 → 2.2 존재 이유 → 2.3 기록 철학 → 2.4 핵심 가치 → 2.5 아날로그·디지털 원칙 → 2.6 제품 원칙`

| Flow | 목적 | Priority |
|---|---|---|
| 2.1→2.2 | 브랜드 정의에서 존재 이유로 확장 | PRIMARY |
| 2.2→2.3 | 사용자 기록 문제에서 철학으로 연결 | PRIMARY |
| 2.3→2.4 | 철학을 핵심 가치로 구체화 | PRIMARY |
| 2.4→2.5 | 가치를 매체 원칙에 적용 | PRIMARY |
| 2.5→2.6 | 매체 원칙을 제품 원칙으로 연결 | PRIMARY |
| 2.6→PRODUCTS 1.3 | 원칙을 실제 특징·사양에 대조 | OPTIONAL RETURN |

GNB Entry는 2.1이 기본이며 HOME 0.3과 PRODUCTS 1.3에서는 각각 2.3과 2.6으로 직접 진입할 수 있다.

## 9. Anchor

| Anchor | Target | 주요 진입 | 상태 |
|---|---|---|---|
| AN-01 | BRAND 2.1 | HOME 0.2 | REQUIRED |
| AN-02 | BRAND 2.3 | HOME 0.3 | REQUIRED |
| AN-03 | PRODUCTS 1.2 | HOME 0.4 | REQUIRED |
| AN-04 | PRODUCTS 1.3 | HOME 0.5·BRAND 2.6·PRODUCTS 1.4 | REQUIRED |
| AN-05 | BRAND 2.6 | PRODUCTS 1.3 | REQUIRED |
| AN-06 | HOME 0.4 | BRAND 2.5 의미 관계 | OPTIONAL |
| AN-07 | Page Top·주요 Heading | 긴 Page 내부·Footer | REQUIRED |

Anchor UI 형태는 화면설계서와 Wireframe에서 결정한다.

## 10. Cross Navigation

| Flow ID | From | To | 목적 | 방식 |
|---|---|---|---|---|
| CR-01 | HOME 0.2 | BRAND 2.1 | 브랜드 상세 확인 | DIRECT/ANCHOR |
| CR-02 | HOME 0.3 | BRAND 2.3 | 철학 근거 확인 | ANCHOR |
| CR-03 | HOME 0.4 | PRODUCTS 1.2 | 제품군 탐색 | ANCHOR |
| CR-04 | HOME 0.5 | PRODUCTS 1.3 | 제품 정보 심화 | ANCHOR |
| CR-05 | PRODUCTS 1.3 | BRAND 2.6 | 제품 원칙 확인 | ANCHOR |
| CR-06 | BRAND 2.6 | PRODUCTS 1.3 | 원칙을 실제 정보에 대조 | ANCHOR/RETURN |

대표 관계는 `0.3→2.3`, `0.4→1.2`, `0.5→1.3`, `1.3↔2.6`이다. `BRAND 2.5→HOME 0.4`는 “매체 원칙↔기록 방식 의미 연결”이라는 `INFORMATION_RELATION_ONLY`로 남기고 필수 Arrow에서는 제외한다.

## 11. Return

| Return ID | 유형 | 대표 적용 |
|---|---|---|
| RT-01 | Source Section 복귀 | 1.3→2.6→1.3, 0.5→1.3→0.5 맥락 |
| RT-02 | 이전 Section | 1.4→1.3 |
| RT-03 | Page Top | 긴 Page 하단→상단 |
| RT-04 | GNB Return | 다른 Page 상단 재진입 |
| RT-05 | Browser Back Expected | 이전 탐색 위치 복귀 |

Browser Back은 별도 Website 기능이 아니다. 대표 SVG에서는 Context Return과 Return 범례만 강조한다.

## 12. Exit

| Exit | 위치 | 의미 |
|---|---|---|
| EX-01 | HOME 0.6 | Long Scroll 탐색 종료 |
| EX-02 | 각 Page Footer | Page 종료 또는 다른 Page 선택 |
| EX-03 | 정보 확인 지점 | 필요한 정보 확인 후 Browser Exit |
| EX-04 | GNB Page Switch | 현재 Page Flow 종료, 다른 Page Flow 시작 |

Exit는 서비스 성공·실패나 구매 완료가 아니다.

## 13. Re-entry

| Re-entry | 방식 | 상태 자동 복원 |
|---|---|---|
| RE-01 | GNB로 Page 상단 재진입 | 없음 |
| RE-02 | Anchor로 Target Section 재진입 | 없음 |
| RE-03 | 교차 확인 후 Source Section Return | 없음 |
| RE-04 | Footer Page Link로 재진입 | 없음 |

## 14. Footer

Footer는 Page 탐색 종료, HOME/PRODUCTS/BRAND 재선택, Page Top 복귀를 지원한다. 계정·구매·결제·Community 등 새 기능은 추가하지 않는다.

## 15. PATH A/B/C

### PATH A — 브랜드 발견

`외부 → HOME 0.1 → 0.2 → 0.3 → 필요 시 BRAND 2.1 또는 2.3 → HOME Return 또는 Exit`

### PATH B — 제품 정보

`GNB/HOME → PRODUCTS 1.1/1.2 → 1.3 → 1.4 → 필요 시 1.3 재대조 → 1.3↔BRAND 2.6 → Exit`

### PATH C — 기록 경험에서 제품·철학 교차

`HOME 0.3 → 0.4 → PRODUCTS 1.2 → 1.3` 또는 `HOME 0.3 → BRAND 2.3`, 필요 시 `1.3↔2.6`

세 Path는 Navigation Path다. 사용자 심리·판단·성공·실패는 후속 Service Flow에서 다룬다.

## 17. Scope Boundary

현재 대표 Flow에서 의도적으로 제외한다.

- 로그인·계정
- 장바구니·구매·결제·배송
- 편집·저장·동기화·내보내기
- Community
- 자동 추천·실행형 Filter
- Product Detail 독립 Page
- 20 Page App Flow
- 상태 자동 복원

## 18. Service Flow Handoff

Site Flow에서 전달:

- Entry와 Target Page/Section
- Primary Sequence
- Cross/Anchor Target
- GNB·Footer 이동
- Return·Exit·Re-entry
- PATH A/B/C

Service Flow에서 추가:

- 사용자 상황·Trigger·Goal
- 판단·Branch Condition
- Success·Failure
- Empty·Error·Recovery
- 서비스 종료 조건

## 19. SVG 읽는 방법

- 굵은 실선: Primary Narrative 13개
- 약한 점선/관계 Band: Optional Cross 6개
- Anchor 표식: 직접 Target Section
- Return Band: Source Section·이전 Section·Page Top 복귀
- GNB: 3개 Page 첫 Section에만 연결
- 하단: PATH A/B/C, Exit/Re-entry, Scope Boundary
- `2.5↔0.4`: 직접 Navigation이 아닌 Information Only 주석

## 20. 기존 V2 사이트 흐름도 대비 개선점

| 항목 | 기존 V2 | 새 대표안 |
|---|---|---|
| Page/Section | 일부 Section을 묶어 표현 | 3 Page·16 Section 전체 직접 표현 |
| Entry | HOME 중심 선언 | 외부·GNB·Cross Entry 5개 구분 |
| Primary Narrative | 일부 주요 경로 중심 | HOME 5·PRODUCTS 3·BRAND 5, 총 13개 |
| Anchor | 중간 Section 이동은 있으나 유형 불명확 | Target Anchor 7개 명세 |
| Cross | 일부 관계만 직접선 | 목적 Label이 있는 Cross 6개 |
| Return | 재탐색 선언 수준 | Context Return과 5개 유형 구분 |
| Exit | 단일 종료 노드 중심 | 0.6·Footer·정보 확인·Page Switch 구분 |
| Re-entry | 구체 유형 없음 | GNB·Anchor·Source Return·Footer 구분 |
| PATH | 주요 경로 C 중심 | PATH A/B/C 3개 Navigation Path |
| Site/Service 경계 | 시스템 처리 미포함 선언 | Handoff 항목까지 명시 |
| 시각 구조 | 간결하지만 일부 Section 축약 | 16 Section 이동과 관계 Band를 함께 표시 |

기존 V2의 장점은 Arrow 수가 적어 빠르게 읽힌다는 점이다. 새 대표안은 그 간결함을 유지하기 위해 Cross를 Page 사이 거미줄이 아닌 관계 Band로 분리한다.
