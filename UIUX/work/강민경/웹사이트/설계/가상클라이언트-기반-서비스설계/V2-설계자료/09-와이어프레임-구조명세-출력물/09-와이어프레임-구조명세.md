# 전체 클라이언트 와이어프레임 구조명세

상태: `ALL_CLIENTS_STRUCTURE_SPEC_CREATED`
범위: `VC-01~VC-51` · 총 51개 개별 구조명세
작성 목적: 클라이언트별 와이어프레임 구조를 한 파일에서 확인하고, 이후 스토리보드 보완·연결성 점검의 기준으로 사용한다.

## 1. 적용 원칙

- 각 클라이언트는 메인페이지·카테고리서브·브랜드소개 3개 구조를 가진다.
- 공통 페이지명만 같고, 콘텐츠·정보 구조·상태·검증·상호작용은 클라이언트 요구에 따라 달라진다.
- 모든 구조명세는 기존 Client·REQ·Product·Page·서비스 흐름도·화면설계서를 입력으로 한다.
- 가격·재고·배송·결제·외부 연동·미검증 성능은 근거 없이 확정하지 않는다.
- 상태는 Default·Loading·Empty·Error·HOLD·Offline·Resume를 필요한 범위에서 구분한다.
- 개별 파일이 상세 원문이며, 이 파일은 전체 목록·점검 기준·연결 허브다.

## 5. 점검 결과 (2026-08-18)

### 판정

VC-01~VC-51 개별 파일 51개는 모두 존재한다. 그러나 생성 여부와 별개로 현재 상태는 스토리보드 제작으로 넘길 최종 통과 상태가 아니다. 상세도·반응형·접근성·요구사항 추적성을 보완한 뒤 다음 단계로 이동한다.

### 자동 점검 결과

| 점검 항목 | 결과 | 판정 |
|---|---:|---|
| 클라이언트별 파일 누락 | 0 / 51 | PASS |
| 메인·카테고리서브·브랜드 소개 구조 키워드 | 51 / 51 | PASS |
| 1,000자 미만 개별 명세 | 46 / 51 | FAIL — 상세도 부족 |
| 접근성 항목 명시 | 6 / 51 | FAIL — 45개 보완 필요 |
| Desktop·Mobile 모두 명시 | 47 / 51 | FAIL — VC-04·13·46·47 보완 필요 |
| REQ 추적 토큰 | 49 / 51 | FAIL — 2개 파일 확인 필요 |

### 보완 사유

- 다수 파일이 요약 수준이라 실제 화면을 그릴 영역 순서·컴포넌트·콘텐츠량·상태 전환·CTA 결과가 충분히 고정되지 않았다.
- 공통 3페이지 골격과 별개로 각 브랜드 전략의 차별 요소가 화면 배치 규칙과 상호작용으로 연결되어야 한다.
- 접근성은 공통표가 아닌 각 파일에 heading/landmark/focus/keyboard/alt/aria-live 기준과 예외를 기록해야 한다.
- Desktop/Mobile 및 1200/768/360px 변화 규칙을 개별 파일에 명시해야 후속 HTML 통합 시 누락을 막을 수 있다.

### 다음 보완 게이트

1. 46개 단문 명세를 화면 구조·컴포넌트·콘텐츠·상태·인터랙션·반응형 규칙까지 확장한다.
2. 접근성 미기재 45개와 반응형 미기재 4개를 개별 파일에서 보완한다.
3. REQ 추적이 끊긴 2개 파일을 원 설계자료와 대조해 복구한다.
4. 동일 점검을 재실행해 51개가 통과할 때에만 클라이언트별 스토리보드 MD/HTML을 진행한다.
## 6. 화면 설계서 양식 대조 점검 (2026-08-18)

대조 기준은 `화면명·화면 목적·주요 콘텐츠·인터페이스 요소·레이아웃·작동 방식·연결 화면·사용자 경로·비고·주석` 9개 항목이다.

### 판정

- VC-01~VC-05: 3개 화면을 영역별 표와 상태/전이/반응형 규칙으로 나누어 작성되어 있어 양식에 대체로 부합한다. 다만 일부는 화면명이나 목적이 표 제목에 흡수되어 있으므로 최종 화면 설계서에서 명시형 필드로 정리해야 한다.
- VC-06~VC-51: `화면·골격·핵심 필드/행동·상태` 4열 요약에 머문다. 9개 양식 중 콘텐츠와 상태 일부만 확인 가능하며, 인터페이스 요소·작동 방식의 세부 동작·연결 URL/PAGE·사용자 경로·비고/주석이 화면별로 분리되어 있지 않다.
- 따라서 현재 와이어프레임은 화면 설계서를 충실히 전개한 결과라기보다, VC-06~VC-51의 경우 핵심 방향을 압축한 구조 메모에 가깝다.

| 화면 목적 | 충족 | 부분 충족 | 핵심 과업은 있으나 화면 단위 목적이 부족 |
| 주요 콘텐츠 | 충족 | 부분 충족 | 짧은 필드명 위주, 실제 카피·이미지·영상·데이터량 부족 |
| 인터페이스 요소 | 충족 | 미충족 | 버튼/입력/필터/탭/모달의 역할과 상태를 화면별로 작성 필요 |
| 레이아웃 | 충족 | 부분 충족 | 전체 골격은 있으나 영역 순서·비율·고정/스크롤 규칙 부족 |
| 작동 방식 | 충족 | 부분 충족 | 일부 전이는 있으나 클릭 후 결과·검증·취소·복귀가 부족 |
| 연결 화면 | 충족 | 부분 충족 | PAGE 번호는 있으나 링크 조건과 왕복 경로가 부족 |
| 사용자 경로 | 충족 | 부분 충족 | 일부 전이만 존재, 목표 달성 단계와 분기 부족 |
| 비고·주석 | 충족 | 부분 충족 | HOLD/금지 일부만 있고 설계 의도·예외·추가 아이디어 부족 |

### 결론

현재 상태에서 “화면 설계서를 기반으로 51개 와이어프레임이 상세 제작되었다”고 판정할 수 없다. 특히 VC-06~VC-51은 각 클라이언트마다 메인·카테고리서브·브랜드 소개를 9개 필드 형식으로 다시 풀어 써야 한다. 이 보완이 끝나기 전에는 스토리보드 HTML을 최종 산출물로 간주하지 않는다.

### 보완 기준

각 화면마다 다음 순서의 고정 블록을 추가한다.

`화면명 → 화면 목적 → 주요 콘텐츠(실제 문구/미디어/데이터량) → 인터페이스 요소(상태 포함) → 레이아웃(Desktop/Tablet/Mobile) → 작동 방식(입력·클릭·검증·실패·취소) → 연결 화면(PAGE/조건/복귀) → 사용자 경로(정상·분기·HOLD) → 비고·주석(근거·미확정·추가 아이디어)`
