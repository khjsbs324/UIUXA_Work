# 제품 콘텐츠 도출 결과 V2 — 검증·보완본

## 1. 작업 범위

- 입력 결과물: `제품콘텐츠-도출결과-V1.md`
- 목적: 기존 제품 후보를 제품별 한 줄 기준으로 재검증하고, Client·REQ·PAGE 연결 누락을 확인한다.
- 대표 제품 15개 선정: **미실행**. 사용자 지시에 따라 후보 검증 이후로 보류한다.
- 제품 후보 수 기준: 200개 고정이 아니라, 제품군별 2~3개 이상을 확보하여 총 100개 이상을 구체적으로 확장한다.

## 2. 검증 결과

- 제품 ID 행 수: 100개
- 고유 제품 ID: 100개
- 중복 제품 ID: 0개
- Client 연결 누락 행: 0개
- REQ 연결 누락 행: 0개
- PAGE 연결 누락 행: 0개
- 상태값 누락 행: 0개
- 제품 연결이 확인된 Client: 47명
- 직접 연결이 확인되지 않은 Client: VC-16, VC-19, VC-40, VC-42

## 3. 보완 판단

1. V1의 100개 후보는 유지한다. 기존 V1을 덮어쓰지 않는다.
2. 각 후보는 제품 ID, 제품군, Client 참조, REQ 참조, PAGE 참조, 상태값을 갖추고 있어 V4 연결의 입력으로 사용할 수 있다.
3. VC-16·VC-19·VC-40·VC-42는 현재 후보표에 직접 연결된 제품이 없으므로 제품을 임의로 끼워 넣지 않는다. V4에서 `직접 연결 제품 없음`으로 기록하고 후속 보완 대상으로 남긴다.
4. `KEEP`, `HOLD` 등 상태값은 후보의 검증 상태이며 대표 15개 선정 결과가 아니다.
5. V4 Client 결과물에는 제품 ID와 연결된 REQ를 함께 기록하여, 제품이 어떤 과업과 요구를 구체화하는지 추적 가능하게 한다.

## 4. V4 연결 규칙

- Client별 V4 파일을 1개씩 생성한다.
- V3 복구본이 있으면 V3를 기준으로 하고, V3가 없는 Client는 V2 요구사항본을 기준으로 한다.
- 기존 V2·V3 파일은 보존한다.
- 제품이 직접 연결되지 않은 Client도 누락시키지 않고, 연결 없음과 후속 검토 필요를 명시한다.
- 메인 랜딩페이지 대표 제품 15개는 이 단계에서 선정하지 않는다.

## 5. 다음 검토 지점

- 사용자 검토 후 직접 연결이 없는 4개 Client에 추가 제품 후보를 보완할지 결정한다.
- 그 다음에야 제품 후보 중 대표 15개를 선정하고 메인 랜딩페이지 배치를 설계한다.
