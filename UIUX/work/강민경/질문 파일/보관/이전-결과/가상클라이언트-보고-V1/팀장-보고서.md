## 1. 작업 목적

승인된 04-1 분석을 실제 인물의 복사나 근거 없는 사업 조직으로 바꾸지 않고, 문제·목표·이용 모드가 다른 의뢰자 관점으로 전환했는지 검토한다. 두 독립 팀의 결과를 비교해 확실한 Client, 후보, 검증 백로그를 분리하고 04-3에서 오해 없이 사용할 수 있는 승인 경계를 정한다.

## 2. 직관팀·창의팀 결과 요약

### 직관팀

- VCG-001과 VCG-002의 분리는 근거와 목적 차이가 명확해 승인 가능하다고 판단했다.
- VCG-003은 U-02와 같은 참여자의 회고 모드일 가능성 때문에 `CANDIDATE`, VCG-004는 설정 근거 중심이므로 `HOLD` 유지가 타당하다고 판단했다.
- 요구 23개의 상태 합계는 맞지만 명시 요소 포함 수가 실제 6건이라는 오류를 확인했다.
- 조건부 승인 해제 기준, VCG-002와 VCR-001의 간접 관계, VCR-004의 설계 원칙 성격을 명료화하도록 요구했다.

### 창의팀

- 승인 렌즈 2개, 후보 모드 1개, 검증 백로그 1개로 운영하는 대안을 제안했다.
- VCG-003은 독립 Client와 VCG-002 하위 이용 모드 두 가설을 경쟁 검증하고, VCG-004는 활성 세트 밖의 조사 백로그로 격리하도록 제안했다.
- 명시 요소 수 오류와 VCG-002 근거 범위의 `INT-022` 포함 오류를 확인했다.
- `VCR-004·009`는 설계 제약/해석임을 표시하고, `VCR-010`은 개별 행동이 아니라 공통 원칙 중심으로 관리하도록 제안했다.

| 쟁점 | 통합 확인 |

| VCG-003 | 실제 요구 근거는 있으나 독립 유형 확정 근거는 부족하여 `CANDIDATE` 유지 |

## 5. 요구 표현과 상태에 대한 통합 판정

### 5.1 명시 요소 수량

`04-2-CLIENT-REQUIREMENTS.md`의 `명시 요소 포함: 7`은 오류다. 실제 `명시+잠재` 요구는 아래 6개다.

- VCG-001-REQ-002
- VCG-001-REQ-003
- VCG-002-REQ-001
- VCG-002-REQ-002
- VCG-003-REQ-001
- VCG-003-REQ-002

수정 후 총계는 `명시 요소 포함 6`, `잠재 요소 포함 23`으로 검증해야 한다.

### 5.2 조건부 승인 정의와 해제 기준

`조건부 승인`은 Client 상태와 구분되는 요구 수준 상태로 정의해야 한다. 무조건 승인으로 합산하지 않으며, 04-3에서는 조건이 붙은 요구로 전달한다.

VCG-002-REQ-002의 조건부 승인 해제 기준은 다음 네 항목 모두다.

1. 사용자가 중요 일정으로 구분하는 기준 확인.
2. 상기가 필요한 시점·빈도·채널 범위 확인.
3. 방해로 느끼는 조건과 허용 수준 확인.
4. `MISSING-005`와 `CONFLICT-006`의 판정 결과를 요구 근거와 연결.

조건이 충족되기 전에는 알림 기능, 횟수, 강도, 채널을 확정하지 않는다.

### 5.3 VCR-004·009·010

- `VCR-004`: 중간·원본+가설 혼합이다. VCG-001-REQ-004를 확정 사용자 사실로 두지 말고 `조건부 설계 원칙`으로 표기한다. 취향 일반화와 기록 방해 여부를 검증해야 한다.
- `VCR-009`: 중간·분석적 해석이다. VCG-002-REQ-003은 `조건부 설계 원칙`, VCG-003-REQ-003은 기존 `후보`를 유지한다. 실제 사용자가 기능/표현 분리를 직접 요구한 것처럼 쓰지 않는다.
- `VCR-010`: 강한 교차 근거의 공통 원칙이므로 `VCG-GLOBAL-004`에서 채택한다. 각 Client 행은 삭제하지 않더라도 `공통 원칙 적용 참조`임을 표시하고, 각 사용자의 Digital/Analog 교차 사용 행동으로 추적하거나 중복 승인 수를 늘리지 않는다.

## 6. 최종 통합 결과와 선정 근거

### Client 통합 판정

| Client | 판정 | 04-3 기본 전달 | 선정 근거 |
|---|---|---:|---|
| VCG-001 | 채택 | 예 | 강한 근거와 독립된 물리 구조·물성·장문 문제 |
| VCG-002 | 채택 | 예 | 강한 근거와 독립된 미래 일정·시간 정보 문제 |
| VCG-003 | 보류 (`CANDIDATE`) | 아니요 | 회고 요구는 실재하나 독립 Client성 미확정 |
| VCG-004 | 보류 (`HOLD`) | 아니요 | 설정 중심 가설; 검증 백로그로 보존 |

VCG-003과 VCG-004는 서로 다른 이유로 보류하며 `MERGED` 또는 `REJECTED`로 바꾸지 않는다. VCG-003은 독립성 검증 대상이고 VCG-004는 실사용 근거 확보 대상이다.

### 통합 판정

`REVISION_REQUIRED_BEFORE_DIRECTOR_APPROVAL`

핵심 Client 구조, Agent/Skill 목적, 요구 ID 체계는 재구축할 필요가 없다. 그러나 수량 오류와 제외 근거 범위, 조건부 상태 정의, 중간·해석 근거의 승인 표현은 04-3에서 사실과 확정 요구를 왜곡할 수 있으므로 부장 승인 전에 수정해야 한다.

4. VCG-002-REQ-002에 `MISSING-005`, `CONFLICT-006` 기반 조건부 승인 해제 기준을 기록한다.

6. VCG-002-REQ-003(VCR-009)을 `조건부 설계 원칙`으로 표시한다. VCG-003-REQ-003은 후보 상태를 유지한다.
7. VCR-010 관련 개별 요구는 `VCG-GLOBAL-004 공통 원칙 적용 참조`로 표시해 실제 교차 매체 행동과 구분한다.
