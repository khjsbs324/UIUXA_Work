# 사이트구조맵·사이트맵 생성 및 검증 기준 V1

## 1. 단계 정의

- 단계: 사이트구조맵·사이트맵 생성·검증
- 입력: 제품이 연결된 Client V4, 요구사항 분석 결과, 제품 콘텐츠 검증·보완본, 브랜드·공유자료
- 분석 기준: 통합 자료를 참고하되 최종 기준은 개별 가상 Client
- 출력 기준: 메뉴, 콘텐츠, 기능, 페이지 목적, 연결 관계
- Figma: 사용하지 않음. CLI에서 확인하고 다른 도구에서 재사용 가능한 로컬 파일로 출력
- 인코딩: UTF-8

## 2. Client별 생성 원칙

- Client를 병합하지 않는다.
- Client 하나당 우선 2~3개의 구조안을 만든다.
- 하나의 안을 바로 확정하지 않는다.
- 각 안은 해당 Client의 상황·목표·과업·불편·요구·판단 기준·제품 연결을 반영한다.
- V4 원문은 보존하고 사이트구조맵 출력물에서만 구조를 도출한다.

## 3. 기본 페이지 범위

1. 메인 랜딩페이지: 브랜드 소개와 제품 탐색을 결합한 스크롤형 구조
2. 카테고리 서브페이지: 제품군·콘텐츠를 모아 보여주는 포트폴리오형 탐색 구조
3. 브랜드 소개페이지: 브랜드 방향·특징·제작 과정·제품과의 관계를 설명하는 구조
4. 제품·콘텐츠 상세 및 비교 연결
5. 공통 영역, 상태별 영역, 예외 페이지

## 4. 구조안에 포함할 항목

- 프로젝트 개요
- Client 식별자와 이름
- 설계 근거와 핵심 사용자 목표
- Client 요구사항·REQ·제품 ID 추적
- 전역 내비게이션
- 1차·2차·3차 계층형 사이트맵
- 메뉴·콘텐츠·기능
- 페이지별 목적·핵심 콘텐츠·주요 기능·연결 페이지 표
- 공통 영역
- 회원·비회원 등 상태별 영역(자료에 없는 상태는 가정 표시)
- 주요 사용자 여정
- 오류·결과 없음·취소·복귀 등 예외 페이지
- 가정과 미확정 사항
- 중복 페이지·끊긴 연결·누락 요구 검증

## 5. 파일 출력 규칙

구조안마다 다음 세 파일을 만든다.

- `사이트맵.md`: 설명, 표, 계층 구조, Mermaid 코드
- `사이트맵.mmd`: MD에 사용한 Mermaid flowchart 코드만 포함
- `사이트맵.svg`: 한글이 깨지지 않는 확대 가능한 벡터 출력

권장 파일명:

`VC-번호-Client명-사이트구조맵-A안-V1-사이트맵.md`

같은 규칙으로 `.mmd`, `.svg`를 만든다. A·B·C안은 같은 Client 안에서 관리하며 불필요하게 Client 파일을 합치지 않는다.

## 6. 계층·내비게이션 검증

- 메뉴 폭은 가능하면 5~9개 이내로 관리한다.
- 깊이는 3차를 기본으로 하며 5차를 넘기지 않는다.
- 같은 의미의 메뉴명은 통일한다.
- 전역 내비게이션·지역 내비게이션·브레드크럼·검색·페이지 링크를 구분한다.
- 모든 페이지는 진입 경로와 다음 행동을 가진다.
- 오류·결과 없음·취소·복귀 상태에서 끊긴 경로가 없어야 한다.

## 7. 구조안 검증 체크

- [ ] Client의 요구사항이 메뉴·콘텐츠·기능에 연결되었는가
- [ ] 연결 제품과 REQ가 어느 페이지에 반영되는지 추적되는가
- [ ] 메인·카테고리·브랜드 소개페이지의 역할이 겹치지 않는가
- [ ] 판매 페이지와 포트폴리오 탐색 페이지가 구분되는가
- [ ] 제품을 강조할 섹션과 제품군 탐색 경로가 있는가
- [ ] 중복 페이지와 끊긴 링크가 없는가
- [ ] 모바일·접근성·저연결성 요구가 구조에서 누락되지 않았는가
- [ ] 입력 자료에 없는 내용은 가정으로 표시했는가
- [ ] Mermaid 문법과 SVG 한글 렌더링을 확인했는가

## 8. 진행 순서

1. VC-01 입력 연결 확인
2. VC-01 구조안 A·B·C 생성
3. MD·MMD·SVG 출력 및 검증
4. 사용자 검토 후 기준 보완
5. 같은 기준으로 나머지 Client 확장
