# 이은수 학생 피드백

## 총평

가상 클라이언트 생성부터 사이트맵, 서비스 흐름도, 화면 설계서, HTML 와이어프레임까지 이어지는 전체 제작 파이프라인을 체계적으로 구성했습니다. 박지안·정시우 두 클라이언트에 대해 시안 5개와 병합본을 분리한 점은 과정 중심 작업으로서 강점입니다. 다만 자동화 규칙을 설명하는 분량에 비해 각 결과물의 사용자 근거와 검증 내용은 상대적으로 얇아, 다음 단계에서는 문서의 양보다 의사결정의 근거와 실제 사용성을 강화할 필요가 있습니다.

## 잘한 점

- 단계별 폴더와 파일명이 규칙적으로 구성되어 작업 흐름을 파악하기 쉽습니다.
- 두 클라이언트에 사이트맵·서비스 흐름도·화면 설계서·스토리보드가 일관되게 제공됩니다.
- 개별 시안과 최적 병합본을 구분해 탐색 과정과 최종 결정을 함께 남겼습니다.
- `.md`, `.mmd`, `.svg`, `.html`을 함께 제공하여 문서와 시각 결과를 교차 확인할 수 있습니다.
- 최종 HTML이 무채색 와이어프레임 원칙과 긴 스크롤 구성을 유지합니다.

## 개선할 점

1. **병합 기준을 증거 중심으로 작성해 주세요.** 각 시안의 장단점과 선택 기준을 사용자의 핵심 과업, 비즈니스 목표, 접근성, 구현 난이도로 비교한 평가표가 필요합니다.
2. **클라이언트 간 차별성을 더 강하게 보여 주세요.** 레이아웃 타입뿐 아니라 콘텐츠 우선순위, 핵심 전환 행동, 탐색 구조가 왜 달라야 하는지 사용자 시나리오와 연결해 설명하면 좋습니다.
3. **절대 경로 링크를 상대 경로로 바꿔 주세요.** 병합 문서의 `file:///` 링크는 기존 로컬 경로에 의존하므로 다른 컴퓨터에서 열리지 않을 가능성이 큽니다. 같은 폴더의 SVG를 상대 경로로 연결해야 합니다.
4. **웹 접근성 마크업을 보완해 주세요.** 두 HTML 모두 ARIA 속성이 확인되지 않고, 정시우 화면에는 입력 요소에 대응하는 `label`이 없습니다. 랜드마크, 헤딩 단계, 폼 레이블, 포커스 표시, 색상 대비를 실제 코드에서 확인해 주세요.
5. **명세와 산출물의 불일치를 정리해 주세요.** 통합 명세에는 시안 1~3 예시와 8개 섹션 기준이 혼재하지만 실제 결과는 시안 1~5이고, 박지안 HTML은 7개 `section`으로 구성됩니다. 규칙을 고정하거나 예외 사유를 기록해 주세요.
6. **실행 완료 체크를 자동 선언하지 말고 검증 결과로 남겨 주세요.** 체크리스트의 `[x]`는 실제 파일 존재, 링크 유효성, HTML 유효성 검사 결과와 연결되어야 신뢰도가 높아집니다.

- 문제 다음에 바로 사단의 해결 원칙을 보여주는 것은 좋지만 여기에 실제 제품 구조 그림이나 레이어링 예시가 추가되면 말뿐인 해결책이 아니라 눈으로 확인할 수 있는 해결책이 돼

[대표 향 2 적송 홍화]

- 레이어링 도식에는 색만 사용하지 말고 향 이름, 분사 횟수, 순서를 글자로 같이 표시해야 색을 구분하기 어려운 사용자도 이해할 수 있어


[대표 향 3 백단 묵향]

[디스커버리 킷]
